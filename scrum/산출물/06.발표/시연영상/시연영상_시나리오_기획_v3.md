# 시연영상 시나리오 기획 v3

> 목적: 기능을 설명하는 영상이 아니라, 사용자가 실제 업무 문제를 화면에서 해결하는 과정을 보여주는 약 3분 분량의 유즈케이스 중심 시연 영상
> 중심 상황: 월말 법인카드 정산 마감 D-2
> 핵심 구조: `사용자 문제 -> 화면에서 기능 선택 -> 버튼 클릭 -> 처리 결과 확인 -> 다음 역할로 인계`
> 목표 길이: 약 3분(180초)

---

## 1. 영상 핵심 방향

### 한 줄 컨셉

**월말 정산에서 각 사용자가 지금 해야 할 일을 찾고, 실제 기능으로 바로 처리하는 과정.**

### V2와 달라지는 점

| V2 | V3 |
|---|---|
| 전체 서비스 플로우 설명 중심 | 사용자별 업무 상황과 해결 과정 중심 |
| 기능이 무엇인지 소개 | 어떤 문제에서 어떤 기능을 쓰는지 시연 |
| 목업과 그래픽 비중이 큼 | 실제 시스템 화면과 클릭 동작 비중이 큼 |
| 룰 생성부터 순차 설명 | 월말 정산 상황 안에서 역할별 유즈케이스 연결 |

### 연출 원칙

1. 한 장면에서 하나의 문제만 제시한다.
2. 문제를 보여준 직후 실제 버튼을 클릭한다.
3. 클릭 뒤 목록, 상태, 건수 또는 화면이 어떻게 바뀌는지 반드시 보여준다.
4. 버튼 이름은 실제 화면 표기를 그대로 사용한다.
5. 실제 데이터에 따라 달라지는 이름, 금액, 건수는 촬영 화면의 값을 사용한다.
6. 카드사 실시간 연동이나 외부 ERP 전송으로 오해할 표현은 사용하지 않는다.

## 2. 전체 스토리라인

월말 정산 마감이 이틀 남았다. 사원은 결제 내역과 증빙을 정리해 팀에 제출해야 한다. 팀장은 여러 팀원의 지출 중 이상 건을 골라 보완을 요청하고 정상 건은 회계로 넘겨야 한다. 회계 담당자는 검토가 필요한 건만 근거와 함께 확인하고, 반복 가능한 보완 업무는 일괄 처리하되 최종 확정은 건별로 수행한다. 회계 리드는 변경된 사내 규정을 새로운 룰로 만들고, 과거 데이터로 검증한 뒤 별도 권한자의 승인을 거쳐 활성화한다.

### 사용자별 핵심 질문

| 사용자 | 업무 상황 | 영상에서 답할 질문 | 사용하는 화면 |
|---|---|---|---|
| 사원 | 결제 내역과 증빙을 정리해 제출해야 함 | 누락된 증빙을 어떻게 찾고 빠르게 제출하는가? | S-01 내 지출 |
| 팀장 | 마감 전 팀 지출을 취합해야 함 | 이상 건만 돌려보내고 정상 건만 한 번에 제출할 수 있는가? | S-02 팀 취합·제출 |
| 회계 담당자 | 검토 건이 쌓여 있음 | 반복 보완은 일괄 처리하고, 위험 건은 근거를 보며 판단할 수 있는가? | S-03 검토 워크스페이스 |
| 회계 리드/승인자 | 규정 변경을 판정 기준에 반영해야 함 | 새 룰을 검증하고 승인 통제 후 적용할 수 있는가? | S-04 Rule 콘솔 |

### 유즈케이스 3. 회계 담당자: 반복 보완은 일괄 처리하고 위험 건은 근거를 보고 결정한다

## 5. 시연 화면 녹화 지침

### 클릭 장면 공통 규칙

1. 버튼 클릭 전 0.7초 동안 커서를 멈춰 버튼 이름을 읽게 한다.
2. 클릭 후 로딩, 상태 배지 변경 또는 목록 이동이 보일 때까지 화면을 유지한다.

5. 시스템 화면의 실제 동작음은 제거하고 편집 단계에서 통일된 클릭 효과음을 넣는다.

## 7. 촬영 전 확인이 필요한 실제 데이터

아래 항목은 시나리오에서 임의로 정하지 않는다. 실제 시연 환경을 확인한 뒤 화면과 자막에 반영한다.

- 로그인할 사원, 팀장, 회계 담당자, 룰 활성 권한자 계정
- S-01에서 불러올 수 있는 표본 데이터의 남은 회차와 건수
- 증빙 `누락` 상태이며 상세 편집이 가능한 지출 건
- S-02의 이상 건 수와 정상 건 수
- S-03에서 AI 권장이 `보완요청`인 건과 고위험 상세 보고서가 준비된 건
- `확정 대기`에서 확정 후 전표(안)을 확인할 수 있는 건
- Rule Agent 생성에 사용할 실제 규정 문서명과 검색어
- 대화형 수정에 입력할 실제 조건 문장
- 시뮬레이션이 완료되는 데 걸리는 실제 시간
- Active 요청자와 `rule_activate` 권한을 가진 승인자 계정

## 8. 최종 내레이션 초안

> 월말 정산 마감 이틀 전.
>
> 사원은 증빙을 제출하고, 팀장은 취합하며, 회계 담당자는 검토와 확정을 마쳐야 합니다.
>
> 사원은 내역 불러오기로 준비된 표본 결제 내역을 가져옵니다.
>
> 증빙 필터를 사용하면 영수증이 없는 건만 바로 찾을 수 있습니다.
>
> 영수증을 등록하면 초안 작성 Agent가 내용을 정리하고, 사용자는 필요한 부분만 확인하고 수정합니다.
>
> 준비가 끝난 건은 선택해 팀에 한 번에 제출합니다.
>
> 팀장은 이상 건만 모아 우선 확인합니다.
>
> 이상건 자동 보완요청을 누르면 문제 건은 판정 사유와 함께 담당 사원에게 돌아갑니다.
>
> 문제 건을 제외한 나머지는 회계로 일괄 제출합니다.
>
> 회계 담당자에게는 자동 처리되지 않은 건만 위험도 순으로 모입니다.
>
> AI 권장이 보완요청인 건은 필터로 모아 사유를 확인한 뒤 일괄 처리할 수 있습니다.
>
> 위험 건은 점수만 보여주지 않습니다. 어떤 특징이 이상 신호가 되었는지, 어떤 규정이 근거인지 함께 확인합니다.
>
> 승인은 반드시 상세 화면에서 근거를 확인한 뒤 건별로 수행합니다.
>
> 검토가 끝난 건도 사람이 한 번 더 확정합니다.
>
> 확정 후에는 내부 전표 초안이 자동 생성됩니다.
>
> 변경된 규정은 Rule Agent가 룰 그래프 초안으로 만들고, 대화로 조건을 조정합니다.
>
> 검증셋과 직전 달 실제 정산 내역에 먼저 적용해 결과를 확인합니다.
>
> 시뮬레이션을 마친 룰도 권한자의 최종 승인을 받아야 운영 기준이 됩니다.
>
> 각자의 문제는 기능으로 해결되고, 모든 결정은 하나의 정산 흐름으로 이어집니다.
