# 시연영상 시나리오 기획 v2

> 목적: 기존 60초 홍보 영상 시나리오를 확장해, 서비스의 전체 흐름을 2~3분 안에 이해시키는 소개 및 홍보 영상으로 재구성한다.
> 기준 플로우: `룰 생성 -> 정산 처리 -> 룰 엔진 판정 -> 사람 최종 검토/확정`
> 권장 길이: 약 2분 20초 ~ 2분 40초

---

## 1. 영상 방향

### 핵심 컨셉

**법인카드 정산은 자동화하되, 최종 통제권은 사람에게 남긴다.**

이 영상은 단순 기능 나열이 아니라, 실제 기업에서 법인카드 정산이 어떻게 흘러가는지 보여준다. 먼저 회계팀이 사내 규정을 AI와 함께 룰로 만들고, 이후 지출자가 증빙을 제출하면 시스템이 정산 흐름을 자동으로 정리한다. 마지막에는 룰 엔진과 Risk Review Agent가 결과를 분류하고, 회계 담당자가 최종 확정한다.

### 영상 톤

| 항목 | 방향 |
|---|---|
| 전체 분위기 | 빠르고 세련된 B2B SaaS 홍보 영상 |
| 시각 톤 | 입체적인 UI 카드, 빠른 컷 전환, 데이터 흐름 애니메이션 |
| 감정 흐름 | 복잡함 -> 정리됨 -> 신뢰 가능함 -> 확장 가능함 |
| 내레이션 | 설명형이지만 짧고 단정하게 |
| 자막 | 긴 문장보다 핵심 키워드 중심 |
| 시스템 화면 | 전체 화면보다 핵심 영역 확대 중심 |
| 음악 | 초반은 긴장감, 서비스 등장 이후는 속도감 있는 테크 톤 |

---

## 2. 한 줄 메시지

**룰은 회계팀이 만들고, 정산은 AI가 정리하며, 최종 결정은 사람이 내립니다.**

### 실제 구현 기준 반영

| 항목 | 영상 표현 기준 |
|---|---|
| 카드사/ERP 연동 | 실제 API 연동이 아니라 `내역 불러오기`로 표본 데이터를 순차 반환하는 시뮬레이션으로 표현 |
| 전표 처리 | 외부 ERP 전송이 아니라 내부 `전표(안)` 초안 자동 생성으로 표현 |
| 룰 활성화 | `Active 요청 -> 승인대기(SIMULATED) -> 권한자 최종 승인 -> ACTIVE` 2단계 게이트로 표현 |
| Agent 명칭 | 로그인 화면 기준 `초안 작성 Agent / Rule Agent / Risk Review Agent`로 통일 |
| 상태명 | 정산 상태는 `승인대기 / 보완요청 / 검토중` 사용 |
| 룰 판정 결과 | 룰 판정 결과는 `통과 / 보완 필요 / 검토 필요 / 규정 위반`으로 별도 표기 |

## 3. 서비스 전체 흐름

### 1단계. 룰 생성

회계팀이 법인카드 관련 사내 규정 문서를 업로드한다. AI는 문서에서 관련 조항을 찾고, 정산 판정에 사용할 수 있는 룰 초안을 만든다. 회계 담당자는 대화형 Agent를 통해 세부 조건을 수정하고, 과거 지출 건으로 시뮬레이션한 뒤 담당자 승인 후 룰을 활성화한다.

**핵심 흐름**

| 순서 | 장면 | 설명 |
|---|---|---|
| 1 | 규정 문서 업로드 | 법인카드 관련 사내 규정 문서를 업로드 |
| 2 | AI 룰 초안 작성 | 문서에서 조항을 찾고 룰 후보 생성 |
| 3 | 대화형 수정 | 회계팀이 Agent와 대화하며 기업 상황에 맞게 수정 |
| 4 | 시뮬레이션 | 과거 지출 건에 적용해 결과 검증 |
| 5 | 요청 후 승인 | Active 요청 후 승인대기 상태로 전환 |
| 6 | 최종 활성화 | `rule_activate` 권한자가 승인해야 실제 판정 기준으로 사용 |

### 2단계. 정산 처리

직원은 `내역 불러오기`로 표본 결제내역을 가져오거나 영수증 기반으로 지출을 등록한다. 증빙 제출 단계에서 초안 작성 Agent가 금액, 사유, 카테고리 초안을 채우고, 직원은 내용을 확인해 수정한다. 팀장은 팀 지출을 취합하고, 문제가 없는 건은 회계로 일괄 제출한다.

**핵심 흐름**

| 순서 | 장면 | 설명 |
|---|---|---|
| 1 | 지출 등록 | `내역 불러오기` 표본 데이터 또는 영수증 기반 지출 등록 |
| 2 | 증빙 제출 | 초안 작성 Agent가 금액, 사유, 비용 분류 초안을 채움 |
| 3 | 직원 확인/수정 | 직원이 초안을 확인하고 필요한 부분 수정 |
| 4 | 팀 취합 | 팀장이 전체 지출과 보완 필요 건 확인 |
| 5 | 회계 제출 | 문제 없는 건은 회계로 일괄 제출 |

### 3단계. 룰 엔진 판정

활성화된 룰을 기준으로 시스템이 정산 결과를 분류한다. 명확한 정상 건은 승인대기 상태로 보내고, 이상 신호가 있는 건은 검토중 상태로 분리한다. 보완이 필요한 건은 직원에게 다시 증빙 제출 단계로 돌아간다. 이때 정산 상태와 룰 판정 결과 라벨을 혼동하지 않도록 화면 자막을 구분한다.

**결과 분기**

| 결과 | 의미 | 후속 흐름 |
|---|---|---|
| 승인대기 | 회계 담당자가 최종 확인하면 확정 | 내부 전표(안) 초안 자동 생성 |
| 보완요청 | 증빙 또는 사유가 부족함 | 직원이 수정 후 재제출 |
| 검토중 | 이상 신호 또는 근거 확인 필요 | Risk Review Agent와 회계 담당자가 함께 확인 |

## 6. 최종 내레이션 초안

> 법인카드 정산은 매달 반복됩니다.
>
> 영수증을 확인하고, 규정을 대조하고, 다시 보완을 요청합니다.
>
> 문제는 지출 건마다 기준이 다르고, 판단 근거를 남겨야 한다는 점입니다.
>
> 그래서 우리는 정산 흐름을 Agent와 룰 엔진으로 나누어 설계했습니다.
>
> 먼저 회계팀은 법인카드 관련 사내 규정 문서를 업로드합니다.
>
> AI는 문서에서 관련 조항을 찾고, 정산 판정에 사용할 룰 초안을 작성합니다.
>
> 회계 담당자는 Agent와 대화하면서 세부 조건을 기업 상황에 맞게 조정합니다.
>
> 만든 룰은 바로 적용하지 않습니다.
>
> 과거 지출 건에 먼저 시뮬레이션해 결과가 기대와 맞는지 검증합니다.
>
> 시뮬레이션을 통과한 룰도 바로 적용되지 않습니다.
>
> Active 요청 후 승인대기 상태가 되고, 권한을 가진 담당자가 최종 승인해야 실제 정산 판정 기준으로 활성화됩니다.
>
> 이제 실제 정산 흐름입니다.
>
> 직원은 표본 결제내역을 불러오거나 영수증을 기반으로 지출을 등록합니다.
>
> 증빙을 제출하면 초안 작성 Agent가 금액과 사용 사유, 비용 분류 초안을 채웁니다.
>
> 직원은 AI가 채운 내용을 확인하고, 필요한 부분만 수정해 제출합니다.
>
> 팀장은 팀 지출 흐름을 한 화면에서 보고, 문제가 없는 건을 회계로 일괄 제출합니다.
>
> 회계로 올라온 건은 활성화된 룰을 기준으로 승인대기, 보완요청, 검토중으로 분류됩니다.
>
> 검토중 건은 이상 신호와 관련 규정 근거를 함께 보여주어 회계 담당자의 판단을 돕습니다.
>
> 최종 확정은 사람이 합니다.
>
> 확정된 건은 내부 전표 초안으로 자동 생성됩니다.
>
> 반복 입력은 줄이고, 검토는 선명하게 만들며, 통제권은 사람에게 남깁니다.
>
> 기준부터 확정까지, 하나의 정산 흐름으로.

## 7. 화면별 연출 가이드

### A. 오프닝 문제 구간

| 장면 | 모션 방향 | 비고 |
|---|---|---|
| 영수증 더미 | 화면 앞쪽으로 빠르게 날아오고 일부는 블러 처리 | 반복 업무의 압박감 |
| 엑셀/정산표 | 셀이 빠르게 채워지고 오류 표시가 튐 | 수작업 느낌 |
| 메신저 보완 요청 | 말풍선이 여러 개 겹치며 등장 | 업무 피로감 |

### B. 룰 생성 구간

| 장면 | 모션 방향 | 비고 |
|---|---|---|
| 규정 문서 업로드 | 문서가 화면 중앙으로 들어오고 조항이 하이라이트됨 | 실제 화면 또는 목업 가능 |
| AI 룰 초안 | 조항 텍스트가 룰 카드로 변환되는 애니메이션 | "문서 -> 룰"을 직관화 |
| 대화형 수정 | 채팅 말풍선과 룰 조건이 동시에 업데이트 | Agent 협업 강조 |
| 시뮬레이션 | 과거 지출 카드들이 룰 엔진을 통과하며 결과 배지 생성 | 검증 후 적용 메시지 |
| 활성화 | `ACTIVE` 배지가 켜지고 룰 엔진으로 연결 | 무조건 자동 적용이 아님을 강조 |

### C. 정산 처리 구간

| 장면 | 모션 방향 | 비고 |
|---|---|---|
| 지출 등록 | 표본 결제내역과 영수증 이미지가 합쳐짐 | 실제 API 연동이 아니라 `내역 불러오기` 표현 |
| 증빙 제출 | 빈 필드에 금액, 사유, 분류가 자동 입력됨 | 실제 기능 체감 |
| 직원 수정 | 일부 필드만 사람이 수정하고 제출 | 사람의 역할 유지 |
| 팀 취합 | 여러 직원 지출 카드가 팀장 화면으로 모임 | 흐름 정리 |

### D. 판정/확정 구간

| 장면 | 모션 방향 | 비고 |
|---|---|---|
| 룰 엔진 판정 | 지출 카드들이 세 갈래로 분기 | 승인대기/보완요청/검토중 |
| 보완요청 | 카드가 직원 화면으로 되돌아가는 루프 | 재제출 흐름 |
| 검토중 | AI 위험 검토 패널이 확대되고 근거 조항 표시 | 차별점 강조 |
| 최종 확정 | 회계 담당자가 확정 버튼 클릭, 전표(안) 초안 생성 | Human Final Decision |

## 8. 영상 생성 AI용 컷별 프롬프트 초안

> 아래 프롬프트는 Runway, Higgsfield, Sora 등에서 컷별 생성할 때 사용할 수 있는 방향성이다.
> 실제 시스템 화면은 이미지 또는 화면 녹화 소스를 함께 넣는 방식이 좋다.

### 컷 1. 정산 업무의 반복

```text
A fast-paced B2B SaaS commercial opening. Floating receipts, spreadsheet grids, and chat request bubbles move toward the camera in layered 3D space. The mood is slightly tense but polished. Use quick cuts, shallow depth of field, glassmorphism UI cards, navy and coral accent colors. Camera pushes forward with subtle shake, then transitions into a clean product interface.
```

### 컷 2. 룰 생성 플로우

```text
A corporate policy document is uploaded into a modern SaaS dashboard. Important clauses glow and transform into structured rule cards. The cards rotate slightly in 3D and connect into a rule engine pipeline. Clean enterprise UI, white background, navy blue labels, coral highlights, premium technology commercial style.
```

### 컷 3. 대화형 Agent 수정

```text
A conversational AI agent interface edits expense policy rules in real time. Chat bubbles appear on the left, rule conditions update on the right, and selected fields animate with smooth highlights. The camera orbits gently around a tilted dashboard screen, creating depth and a dynamic product demo feeling.
```

### 컷 4. 시뮬레이션과 활성화

```text
Past expense cards flow through a simulation pipeline. Each card receives a result badge after passing through the rule engine. The UI shows test results, validation status, and then an ACTIVE badge lighting up. Energetic but trustworthy B2B motion graphics, 3D layered cards, smooth transitions.
```

### 컷 5. 증빙 제출과 자동 초안

```text
A receipt image and corporate card transaction data merge into an expense submission form. Empty fields automatically fill with amount, date, category, and reason draft. The employee reviews and edits only one highlighted field. Clean SaaS product UI, dynamic zoom-in, soft shadows, premium Korean fintech commercial style.
```

### 컷 6. 팀 취합

```text
Multiple employee expense cards move into a team manager dashboard. Budget usage indicators, pending badges, and completion states organize themselves neatly. The scene should feel like chaos becoming structured. Use layered 3D UI cards, quick lateral camera movement, and confident enterprise design.
```

### 컷 7. 룰 엔진 판정

```text
Expense cards enter a rule engine and split into three paths: approval pending, request supplement, and review required. Each path is color coded: green, orange, and blue. The animation is dynamic and dimensional, with cards moving through a transparent 3D pipeline inside a modern SaaS interface.
```

### 컷 8. Risk Review와 최종 확정

```text
A high-risk expense opens in a Risk Review panel. Anomaly signals, evidence, and relevant policy clauses appear beside the expense card. A human accountant reviews the AI result and clicks final confirmation. The mood is trustworthy and controlled, emphasizing human final decision, not full automation.
```

| 2 | S-05 규정 문서 관리 | 규정 문서 업로드, 조항 미리보기, PDF 파싱/청킹/임베딩 흐름을 설명 |

## 10. 팩트체크 반영 항목

| 항목 | 반영 내용 |
|---|---|
| 카드사/ERP 연동 | 실제 연동 표현을 피하고 `내역 불러오기` 버튼으로 표본 데이터를 불러오는 장면으로 표현 |
| 전표 자동 반영 | 외부 ERP 전송이 아니라 내부 `전표(안)` 초안 자동 생성 및 조회로 표현 |
| 룰 활성화 전 승인 | Active 요청과 권한자 최종 승인을 분리해 2단계 게이트로 표현 |
| 과거 지출 시뮬레이션 | 검증셋과 실제 과거 정산 데이터를 함께 활용하는 구현 흐름으로 표현 |
| Agent 명칭 | `초안 작성 Agent / Rule Agent / Risk Review Agent`로 통일 |
| 상태명 | 정산 상태는 `승인대기 / 보완요청 / 검토중`, 룰 판정 결과는 `통과 / 보완 필요 / 검토 필요 / 규정 위반`으로 구분 |

## 11. 편집 메모

- v2는 기능을 많이 보여주되, 모든 화면을 길게 설명하지 않는다.
- 핵심은 “규정을 룰로 만들고, 룰이 실제 정산을 판정한다”는 연결성이다.
- 제품의 신뢰 포인트는 “AI가 최종 승인하지 않는다”는 점이다.
- 영상 생성 AI로 만들 경우, 한 번에 2~3분 전체를 생성하지 말고 6~10초 컷 단위로 만든 뒤 이어붙이는 방식이 좋다.
- 실제 시스템 화면은 그대로 길게 보여주기보다, 필요한 영역을 확대하고 주변에 3D 카드/데이터 흐름 그래픽을 얹는 방식이 적합하다.

## 12. 짧은 카피 후보

- **규정은 룰로, 지출은 흐름으로, 판단은 근거로.**
- **법인카드 정산의 기준부터 확정까지 하나로.**
- **AI가 정리하고, 룰이 판정하고, 사람이 결정합니다.**
- **반복 업무는 줄이고, 검토의 근거는 더 선명하게.**
- **기업마다 다른 정산 기준, 대화형 Agent로 맞춤 설정.**
