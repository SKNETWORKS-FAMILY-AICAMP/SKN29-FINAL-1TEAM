# 시연영상 나레이션 스크립트 v5 — 기능 투어 버전

> **v4와의 차이**: v4는 페르소나(사원→팀장→회계→리드) 서사 중심이었다. v5는 **화면 중심**이다.
> "이 페이지는 무엇을 하는 화면인가 → 무엇을 누르면 → 무엇이 나오는가"를 순서대로 따라간다.
>
> **구성**: 인트로 / 파트 1~7(화면 7개, AI-LAB 제외) / 아웃트로
> **파트 순서**: 지출 증빙 → 팀 취합 → 예산 → 카드 → **규정 문서 → 룰 콘솔 → 검토 워크스페이스**
> 뒤 세 파트를 `규정 업로드 → 그 규정으로 룰을 만들고 활성화 → 그 룰이 판정한 결과를 사람이 검토`
> 한 줄기로 묶어 영상을 닫는다. 각 파트가 다음 파트의 입력을 만들어 주므로 컷 전환에 설명이 필요 없다.
>
> **기준 길이**: 약 3분 15초(195초). 인트로·아웃트로 18초를 빼고 본편 7파트에 약 177초를 배분한다.
> **문체 규칙**: 전부 능동형. `~해서 ~됩니다` 대신 `~해서 ~합니다`. 피동·수동 표현을 쓰지 않는다.
> (주어는 대부분 **화면·시스템·AI·Agent·사용자** 넷 중 하나다. "무엇이 되는가"가 아니라 "누가 무엇을 하는가"로 적는다.)
>
> **읽는 법**: 각 줄의 `예상`은 5자/초 기준 추정치다. 실제 영상 컷 길이에 맞춰 문장을 줄이거나 늘려 쓰면 된다.
> 컷 길이가 모자라면 각 파트의 ★ 표시 줄을 우선 살리고 나머지를 덜어낸다.

### 뒤 세 파트의 연결 고리 (편집 시 반드시 유지)

```

```

## 파트 1 — 지출 증빙 (S-01) · 30초

**흐름**: 첫 화면 소개 → `신규 지출 등록` → 영수증 업로드 → 판독 결과 확인 → `팀에 올림` → 증빙 누락 필터 + 선택 일괄 제출

| # | 화면·동작 | 나레이션 | 예상 |
|---|---|---|---:|
| 1-1 ★ | 첫 화면 | 첫 화면은 지출 증빙입니다. 내가 쓴 법인카드 내역을 한곳에 모으고, 이번 달 사용액과 미제출·검토중·보완요청·반려 건수를 위에서 바로 보여줍니다. | 8초 |
| 1-2 | `신규 지출 등록` 클릭 | 신규 지출 등록을 눌러 등록 창을 엽니다. | 3초 |
| 1-3 ★ | 파일 선택 → 업로드 | 영수증 파일을 고르면 서버가 곧바로 카드전표를 판독합니다. | 4초 |
| 1-4 ★ | 판독 완료 · 기본 내역 채워짐 | 판독을 마치면 가맹점과 거래일자, 금액을 기본 내역에 채우고, 결제 시각과 지출 세부유형, 주류 포함 여부까지 함께 읽습니다. 비용 분류는 AI가 제안하고, 사용자는 확인만 합니다. | 11초 |
| 1-5 | `팀에 올림` 클릭 | 내용을 확인한 뒤 팀에 올림을 눌러 이 건을 팀 취합 단계로 올립니다. | 4초 |
| 1-6 ★ | 목록 → 증빙 `누락` 필터 → 선택 → `선택 N건 팀에 제출` | 목록에서는 증빙 누락 건만 걸러 모아 한 번에 검토하고, 준비를 마친 건들을 골라 팀에 함께 제출합니다. | 7초 |

> 컷이 빠듯하면 1-4를 두 문장으로 나눠 첫 문장만 쓰고, 1-2를 자막으로 대체한다.
> `fact.json`·`AI 코멘트` 영역이 화면에 잡히면 1-4 뒤에 한 줄 덧붙일 수 있다 —
> "판정에 쓰는 사실은 fact.json이 그대로 보여주고, AI 코멘트가 지금 무엇을 보완하면 좋을지 알려줍니다." (5초)

## 파트 2 — 팀 취합·제출 (S-02) · 26초

**흐름**: 첫 화면 소개 → 팀원 개별 건 선택 → `제출`/`보완요청`/`반려` → 사유 모달(AI 초안) → `보완요청 전송` → 일괄 제출

| # | 화면·동작 | 나레이션 | 예상 |
|---|---|---|---:|
| 2-1 ★ | 첫 화면 | 팀 취합·제출 화면은 팀원이 올린 건을 팀장이 한자리에서 확인합니다. 팀 통계와 예산도 같은 화면에서 함께 봅니다. | 7초 |
| 2-2 ★ | 팀원 선택 → 건별 버튼 | 팀원별로 올린 건을 펼쳐 보고, 건마다 제출·보완요청·반려 중 하나를 고릅니다. | 5초 |
| 2-3 | `보완요청` 클릭 → 모달 | 보완요청이나 반려를 고르면 사유 입력 창을 엽니다. | 3초 |
| 2-4 ★ | 모달 · AI 초안 문구 | AI가 사유 초안을 먼저 씁니다. 팀장은 그대로 보내거나, 문장을 직접 고쳐서 보냅니다. | 6초 |
| 2-5 ★ | `보완요청 전송(RETURNED)` → 상단 일괄 버튼 | 검토를 마치면 이상 건은 사유와 함께 돌려보내고, 나머지는 이상건 제외 일괄제출로 회계에 한 번에 올립니다. | 7초 |

> 모달 상단 배너("룰 판정은 승인이었습니다 — 다르게 판단하시는 이유를 남겨주세요")를 여기서는 **설명하지 않는다.**
> 같은 장치를 파트 7에서 영상의 결론으로 쓰기 때문에, 여기서 먼저 말하면 마지막 한 방이 약해진다.

> **5-5가 파트 6의 문을 연다.** 컷을 바로 Rule 콘솔로 넘기고, 나레이션을 끊지 않고 6-1로 잇는다.

> 분류가 어긋나면 "방금 올린 규정"이라는 말과 화면이 따로 놀아 연결이 깨진다.

## 파트 6 — Rule 콘솔 (S-04) · 38초

**흐름**: (파트 5에서 이어짐) 첫 화면 + 3탭 → `노드 추가` → 자연어 지시 → 노드 반영 → `초안 완료 · 검증 대기로 전환` → 시뮬레이션 실행 → 보고서(Agent 의견·권장 처리) → `Active 요청` → Active 관리 탭 → `승인 · ACTIVE 전환`

| # | 화면·동작 | 나레이션 | 예상 |
|---|---|---|---:|
| 6-1 ★ | 첫 화면 · 탭 3개 | 규정에서 나온 룰은 Rule 콘솔에서 다듬습니다. 초안 그래프, 시뮬레이션, Active 관리 세 탭으로 나뉘고, 왼쪽 목록에서 비용 분류별 그래프를 버전별로 엽니다. | 11초 |
| 6-2 | 접대 · v1 수정중 → `노드 추가` | 방금 올린 규정과 같은 분류인 접대 검증 그래프를 열고, 노드 추가를 눌러 가운데에 제목 미설정 노드 하나를 새로 만듭니다. | 8초 |
| 6-3 ★ | 오른쪽 대화형 창에 자연어 입력 | 이 노드는 오른쪽 대화형 지시·수정 창에서 자연어로 채웁니다. 조건과 처리를 말로 적으면 Agent가 노드를 직접 고칩니다. | 8초 |
| 6-4 ★ | 가운데 노드 갱신 | Agent는 제목과 설명, 언제 걸리고 걸리면 무엇을 하는지, 그리고 액션과 심각도까지 한 번에 채웁니다. | 7초 |
| 6-5 | `초안 완료 · 검증 대기로 전환` → 시뮬레이션 탭 | 초안 완료를 눌러 검증 단계로 넘기고, 시뮬레이션 탭으로 이동합니다. | 4초 |
| 6-6 ★ | 시뮬레이션 실행 → 보고서 | 시뮬레이션 탭은 방금 쓴 초안을 그대로 받습니다. 실행하면 검증셋과 지난달 실제 내역에 이 룰을 적용해 보고서를 만듭니다. | 8초 |
| 6-7 ★ | KPI 4종 + Agent 의견·권장 처리 강조 | 보고서는 자동처리율과 검토 감소량, 테스트 수치, 노드 커버리지를 먼저 보여줍니다. Agent는 그래프 구조와 실행 결과를 각각 평가하고, 도달 불가 노드와 위험 변경 건수를 짚어 권장 처리를 한 줄로 내놓습니다. | 13초 |
| 6-8 | `Active 요청` | 내용을 확인한 뒤 Active 요청을 보냅니다. | 3초 |
| 6-9 ★ | Active 관리 탭 → `승인 · ACTIVE 전환` | Active 관리 탭 승인대기 목록에서 방금 올린 그래프를 찾습니다. 룰 활성 권한자가 보고서를 다시 읽고 승인·ACTIVE 전환을 누르면, 그때 시스템이 이 룰을 운영 기준으로 적용합니다. | 12초 |
| 6-10 ★ | (다음 파트로 넘기는 다리) | 검증을 마친 룰도 사람의 승인 없이는 스스로 활성 상태로 올라가지 못합니다. 이렇게 활성화한 룰이 제출한 건을 자동으로 가릅니다. | 9초 |

> **합이 83초로 배분(38초)을 넘는다.** 파트 6은 두 배 분량으로 써 두었으니 촬영 컷 길이에 맞춰 고른다.
> 최소 세트(38초): 6-1(뒷문장만) → 6-3 → 6-4 → 6-6 → 6-7(앞 문장만) → 6-9 → 6-10(앞 문장만)
> 덜어낼 순서: 6-2 → 6-5 → 6-8 → 6-7 뒷문장 → 6-1 앞문장
> 단 **6-1의 첫 구절("규정에서 나온 룰은")과 6-10의 마지막 문장은 다리 역할**이라 마지막까지 남긴다.

## 파트 7 — 검토 워크스페이스 (S-03) · 33초 — 영상의 마무리

**흐름**: (파트 6에서 이어짐) 첫 화면 소개 → 왼쪽 목록 한 건 선택 → RAG 내규 검증 패널 → `자세히 보기` → 결정 3버튼 → `반려` 모달 → 결정 사례로 닫기

| # | 화면·동작 | 나레이션 | 예상 |
|---|---|---|---:|
| 7-1 ★ | 첫 화면 | 룰이 확실하게 가른 건은 그대로 흘러가고, 자동으로 처리하지 못한 건만 검토 워크스페이스에 위험도 순으로 모입니다. | 8초 |

## 촬영·편집 전 확인 항목

1. **파트 5에서 올리는 규정 문서와 파트 6에서 여는 그래프의 비용 분류를 맞춘다.** 접대·업무추진비 규정을 올렸다면 파트 6도 접대 검증 그래프를 연다. 5-5의 "방금 올린 규정"과 6-2의 "같은 분류인" 표현이 여기에 걸려 있다.
2. **파트 5→6 컷은 끊지 않는다.** 5-5 나레이션이 끝나기 전에 화면을 Rule 콘솔로 넘기고, 6-1을 이어 읽는다. 두 파트 사이에는 전환 모션을 넣지 않는다(같은 이야기의 연속이므로).
3. **파트 6→7 컷도 같은 방식이다.** 6-10의 "제출한 건을 자동으로 가릅니다"에서 검토 워크스페이스 목록으로 넘어가면, 7-1의 "자동으로 처리하지 못한 건만"이 그 문장을 그대로 받는다.
4. **파트 6의 자연어 입력 문장과 결과 노드가 서로 맞는지 확인한다.** 기획에서는 "봉사료 10% 넘는 접대비 보완요청으로 보내줘"를 입력하기로 했는데, 참고 캡처의 결과 노드는 「지출목적 미기재(접대비)」다. 나레이션 6-3·6-4는 **입력 문장을 그대로 읽지 않도록** 써 두었으니 어느 쪽으로 찍어도 어긋나지 않지만, 자막으로 입력 문장을 노출할 거면 둘을 통일한다.
5. **파트 7의 확신도 수치** — 캡처는 72%다. 촬영본이 다른 값이면 7-3의 "72퍼센트"를 촬영값으로 바꾼다.
6. **파트 3의 팀 탭 이름** — AI개발·영업·재무회계. 시드 데이터에 따라 팀명이 다르면 3-2를 촬영값으로 바꾼다.
7. **파트 1의 건수** — "선택 N건 팀에 제출" 버튼의 실제 건수를 읽을지, 건수 없이 넘어갈지 정한다(스크립트는 건수를 읽지 않는다).
8. **파트 5의 업로드 소요 시간** — 파싱·적재는 문서당 수십 초가 걸린다. 5-3과 5-4 사이는 편집으로 붙이고, 나레이션이 진행 상황을 실시간으로 설명하지 않게 한다.
