# 📋 일간 보고 (08/18)

## 1. 가맹점 업종 구분 시스템 구현

* Draft·Risk Agent가 공용으로 쓸 **`classify_merchant` MCP Tool**을 캐시 → 카카오 로컬 API → LLM 재분류 3단 캐스케이드로 실동작 구현
* 카카오가 제공하는 원시 업종 분류는 장소·마케팅 기준이라 **일반음식점과 유흥주점이 같은 코드로 묶이는 문제**를 확인, **LLM이 가맹점명+카카오 원시 카테고리를 보고 자체 업종 어휘 10종으로 재분류**하도록 설계해 리스크 판단에 필요한 구분을 확보
* 카카오 조회 실패·LLM 재분류 실패 모두 예외로 새지 않고 **미확정(공란) 반환**으로 흡수하도록 처리(웹검색 폴백 없음 원칙 유지)
* Django 5건·FastAPI 10건 테스트로 캐시 히트/미스 검증, 카카오 실키의 서비스 미활성으로 인한 403도 정상적으로 흡수됨을 확인
* Draft/Risk Agent가 이 Tool을 실제로 호출하는 **연동은 이번 범위에서 제외** — Tool 실동작을 우선 확보

## 2. 규정 문서 화면 고도화 및 시연용 초기 상태 시드

* 문서 업로드 모달·폴더 트리 구조 개선 등 **규정 문서 관리 화면(S-05) 고도화**
* **`seed_clean` 관리 명령 신설** — "제품을 막 설치한 회사" 상태(사용자·팀·카드 + 기본 게이트 1개만, 정산·규정문서·룰 0건)를 구성해 규정 업로드 → 룰 생성 흐름을 처음부터 시연 가능하게 함
* 규정이 없는 신규 설치 상태에서는 **한도·기한 같은 정책 판단을 걸 수 없다는 제약을 실측으로 확인**, 대신 증빙·목적·가맹점업종 등 **기록 완결성만 판정**하도록 기본 게이트를 설계 — 회귀 테스트 12건으로 정상 건이 강등 없이 통과함을 검증

## 5. RAG 파싱 환경 안정화

* **MCP 툴 등록 결함 발견 및 수정** — 함수를 데코레이터에 직접 넘기는 방식(`mcp.tool(fn)`)이 조용히 등록에 실패해 `/mcp` 전체가 마운트되지 않던 문제를 확인, 정식 등록 API(`add_tool`)로 교체
* Docling 파싱에서 **섹션 헤딩 레벨을 순회 깊이와 실제 계층 레벨로 혼동**해 모든 헤딩이 level 1로 뭉개지던 결함 수정
* 도커 환경에서 docling 실행 여부를 점검하는 진단 스크립트 추가, RAG 적재 파이프라인 e2e·smoke 테스트 보강

## 7. 화면 버그 수정

* 정산 내역조회 기본 날짜가 고정값으로 하드코딩되어 있던 것을 **오늘 날짜 기준으로 계산**하도록 수정
* 룰 콘솔 대화형 수정 로그가 **노드 단위로 걸러지고 있어, 실제로는 그래프 단위로 남는 Agent 로그와 어긋나 항상 0건으로 보이던 결함** 수정 — AI 수정은 정상 동작했지만 화면에 대화 내역만 누락되던 문제
* 시뮬레이션 보고서 서술이 LLM 생성인지 규칙 기반 placeholder인지 구분되지 않던 것을 배지로 명시해 담당자가 신뢰 수준을 오인하지 않도록 개선

## 8. 테스트케이스 자동생성 방향성 정리

* 룰 검증셋을 대화형이 아닌 **완제품(커버리지 기반 + 자체검증 루프)** 으로 자동 생성하는 방향을 확정 — 기존 커스텀 케이스는 유지(append), 노드당 매치·경계값 2건 생성 원칙으로 정리
* 설계 방향만 확정, **구현은 미착수**
