# 📋 일간 보고 (08/18)

## 1. 가맹점 업종 구분 시스템 구현

* Draft·Risk Agent가 공용으로 쓸 **`classify_merchant` MCP Tool**을 캐시 → 카카오 로컬 API → LLM 재분류 3단 캐스케이드로 실동작 구현
* 카카오가 제공하는 원시 업종 분류는 장소·마케팅 기준이라 **일반음식점과 유흥주점이 같은 코드로 묶이는 문제**를 확인, **LLM이 가맹점명+카카오 원시 카테고리를 보고 자체 업종 어휘 10종으로 재분류**하도록 설계해 리스크 판단에 필요한 구분을 확보
* 카카오 조회 실패·LLM 재분류 실패 모두 예외로 새지 않고 **미확정(공란) 반환**으로 흡수하도록 처리(웹검색 폴백 없음 원칙 유지)
* Django 5건·FastAPI 10건 테스트로 캐시 히트/미스 검증, 카카오 실키의 서비스 미활성으로 인한 403도 정상적으로 흡수됨을 확인
* Draft/Risk Agent가 이 Tool을 실제로 호출하는 **연동은 이번 범위에서 제외** — Tool 실동작을 우선 확보

## 2. 규정 문서 화면 고도화 및 시연용 초기 상태 시드

* 문서 업로드 모달·폴더 트리 구조 개선 등 **규정 문서 관리 화면(S-05) 고도화**
* **`seed_clean` 관리 명령 신설** — "제품을 막 설치한 회사" 상태(사용자·팀·카드 + 기본 게이트 1개만, 정산·규정문서·룰 0건)를 구성해 규정 업로드 → 룰 생성 흐름을 처음부터 시연 가능하게 함
* 규정이 없는 신규 설치 상태에서는 **한도·기한 같은 정책 판단을 걸 수 없다는 제약을 실측으로 확인**, 대신 증빙·목적·가맹점업종 등 **기록 완결성만 판정**하도록 기본 게이트를 설계 — 회귀 테스트 12건으로 정상 건이 강등 없이 통과함을 검증

# 📋 일간 보고 (08/19)

## 1. 가맹점 업종 자동분류, 초안 작성에 실제로 연결

* 어제 만들어둔 업종 분류 기능(`classify_merchant`)을 오늘 **초안 작성(Draft Agent) 화면에 실제로 연결**했다. 이제 AI가 지출 내역 초안을 쓸 때, 가맹점 업종을 지어내지 않고 우리 시스템이 미리 조회해준 값을 보고 작성한다
* 연결하려고 보니 업종 이름이 코드 곳곳에서 **제각각으로 쓰이고 있었다**(AI 쪽 10종, 룰 문서, 금지업종 표, 시드 데이터가 서로 다른 이름). 그래서 룰 매칭이 조용히 안 걸리거나, 값이 비어있으면 무조건 "검토 필요"로 넘어가버리는 문제가 있었다
* 업종 이름을 **한 곳(15종)으로 통일**하고 모든 코드가 이 이름을 쓰도록 정리했다. 골프장·노래연습장·이미용 등 규정에서 구분이 필요한 업종도 새로 추가했다
* **모를 땐 "기타"로 대충 넣지 않고 "미확정"으로 남기도록** 했다. "기타"로 넣으면 나중에 금지업종 검사에서 "문제없음"으로 오해될 수 있어서다
* 화면(S-01)에서도 업종 값을 저장할 때 같이 넘기도록 연결했다. 안 하면 화면에는 보여도 실제 판정에는 반영이 안 되는 상태였다
* 서버가 죽었을 때 오류가 그대로 튀어나오던 것도 고치고, 타임아웃 시간들도 정리했다
* 테스트로 확인 완료(Django 213건, AI서버 20건). 다만 Risk Review(위험 검토) 쪽 연결은 아직 안 했다

## 2. 판정 사유(플래그) 정리

* 판정할 때 붙는 사유 코드 27개가 지금까지 정식으로 정의된 곳 없이 그냥 문자열로만 떠돌고 있었다. 오늘 이걸 정식으로 목록화했다
* 시스템이 자동으로 붙이는 사유와, 회사 규정에서 새로 만들어지는 사유를 구분했다. 후자는 회사마다 새로운 규정이 계속 생기니 자유롭게 추가는 되게 하되, 이상한 값이면 경고만 뜨게 했다
* **중요한 원칙 하나를 확정**: 이 사유 코드는 "왜 이렇게 판정했는지" 설명용일 뿐, 실제로 승인/반려 여부를 결정하는 데는 관여하지 않는다
* 같은 뜻인데 이름이 다르게 쓰이던 것 통일, 화면에 영어 코드가 그대로 노출되던 것도 한글 이름이 뜨도록 고쳤다

## 3. Rule Agent(룰 생성 AI) 화면 개선

* AI가 정산 건을 어떻게 처리하면 좋을지 추천하는 로직을 개선했다 — 이제 근거(사실관계)를 종합해서 추천 등급도 다시 판단한다. 다만 명백히 문제가 있는 경우는 AI 판단과 무관하게 서버가 안전하게 처리한다
* 테스트 케이스(검증용 가상 사례)를 자동으로 만드는 방식을 손봤다. 너무 많이 만들지 않게 개수를 조절하고, 예전 것이 계속 쌓이지 않고 새로 만들 때 교체되게 했다
* 사용하는 AI 모델을 용도별로 다르게 지정해 비용을 줄였고, 관련 버그도 수정했다
* 화면 버튼을 정리해서 "시뮬레이션 실행" 버튼 하나로 단순화했다
* 결과 보고서에 요약 부분을 맨 위에 추가해서 한눈에 보기 쉽게 했다
* 여러 파일에 따로따로 박혀있던 설정값들을 한 곳(서버)으로 모으고, 화면과 AI 서버가 그 값을 가져다 쓰도록 정리했다

## 4. Risk Review(위험 검토) AI가 규정을 더 잘 읽도록 수정

* AI가 규정을 검토할 때, 원래는 조문 전체를 가져올 수 있었는데 실제로는 **짧게 잘린 400자짜리 조각만 보고 있던 버그**를 발견해서 고쳤다. 이제 조문 전체(최대 1200자)를 보고 판단한다
* 테스트 4건 추가로 확인

## 5. 직책·직위 데이터 정리

* 관련 시드 데이터와 테스트도 함께 정리
