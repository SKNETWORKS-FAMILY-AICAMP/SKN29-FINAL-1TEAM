## 1. 별표(표) 처리 고도화

* **별표 추출·검증 파이프라인 1차 고도화** (`triage.py`) — 축 제안·값 어휘 검증 로직을 대폭 보강하고 회귀 테스트 추가, `PolicyTableProposal`에 검사 결과(`checks`) 컬럼 신설
* **승인 실패가 화면에 안 보이던 문제 원인 규명·수정** — "승인을 눌러도 반응이 없다"의 실제 원인은 서버가 정상적으로 거절(축 오타·시행일 없음·key 표기 위반 등 400)하고 있었는데, 실패 사유가 페이지 최상단 배너에만 뜨고 별표 카드는 스크롤 아래에 있어 누른 사람 눈에는 안 띄는 구조였음 — 사유를 버튼 옆으로 이동
* 표 원문을 파이프 문자 그대로가 아니라 **실제 HTML 표로 렌더링**(GFM 표 파싱, 실패 시 원문 pre로 폴백) — 셀 경계를 눈으로 세지 않고 추출 결과와 바로 대조 가능하게 함. 페이지 표기도 시작·끝이 같으면 "p.7~7" 대신 "p.7"로 정리
* 승인된 제안은 저장된 표를 그대로 보여줌(축 0~2개는 표, 그보다 깊으면 안전하게 JSON) — 승인 후 "내가 뭘 승인했는지" 확인할 길을 원문 대조 하나로 남기지 않기 위함
* **조용한 무력화 결함 발견·차단**: 축을 선언하고 payload가 `{"value": …}` 한 칸이면 구조 검사는 통과하지만(축 값이 문자열 "value"인 행으로 잘못 읽힘) 영원히 해소되지 않는 상태로 남는 경우를 확인, 승인 거부로 전환
* 같은 파일을 건드린 두 브랜치(별표 고도화 1차 / 표 HTML 렌더링)가 충돌해 되돌리기(revert) 후 merge, 재적용하는 과정을 거쳐 정상 병합 — 실 데이터(법인카드_사용규정 별표1)로 렌더링 검증 완료
* core 테스트 520건, 프론트 빌드 통과 확인

## 3. Rule Agent — 초안 이어붙이기로 전환

* **결함**: 생성할 때마다 새 룰 계열(v1)이 생겨 룰 콘솔이 초안으로 뒤덮이던 문제 — 이제 생성 전 해당 scope의 편집 중인 초안을 찾아 있으면 거기에 노드를 잇도록 수정
* 모델이 기존 초안을 못 보고 같은 조항으로 같은 룰을 반복 생성하던 것도 함께 해결 — 프롬프트에 현재 초안 노드 목록·근거 조항을 실어 겹치면 "이미 초안에 있음"으로 skip하도록 지시
* 체인 잇기는 결정론적 `_plan_append`가 계획: 종단 PASS 중복 생성 방지, 직전 꼬리 NO_MATCH를 새 노드로 라우팅(안 그러면 새 노드가 도달 불가로 조용히 무용해짐), 키 충돌 시 새로 발급
* 구조검증 실패 시에도 초안 전체를 지우지 않고 이번에 생성한 노드만 걷어내도록 변경(`discard_draft`를 쓰면 사람이 편집 중이던 그래프가 통째로 사라지는 문제 방지) — 라우팅 원복을 노드 삭제보다 먼저 처리해 판정 중 그래프가 깨져 보이는 순간을 없앰
* `/api/rules/`에 scope 필터 추가(Agent가 기존 초안을 찾는 창구)

  * `rule-engine-qa.md` — 룰엔진 도입 타임라인 7단계, 검증셋 300건 실측(자동처리율 26%→100%, 오탐 0%)
  * `isolation-forest-report.md` — Risk Review 1단계 이상탐지 모델, 비지도 11종 비교(PR-AUC 0.5865), 위험도 컷오프 실측(LOW 위험 0% / HIGH 11%)
  * `agent-harness-report.md` — LLM 사용 5개 지점 하네스 평가(별표 추출 표 5~6건→12건·경고 3~4건→0건, 증빙 판독 20/20)
* **`seed_adopted` 결정 사례(case_history) 30건 추가** 및 낡은 기대 판정 교정 — QA·시연 양쪽에서 참조할 재현 가능한 사례 데이터 확보
* **규정문서 적재 결과 덤프·복원 커맨드 추가** — 재임베딩 없이 QA 검증 상태를 고정·재현할 수 있는 경로 확보

## 5. README 세팅 절차 전면 재작성

* 시드 절을 화면 단위가 아니라 **"회사가 어느 시점에 있는가"** 축으로 재구성 — `seed_clean`(규정 업로드→룰 생성 흐름)·`seed_adopted`(실제 정산 흐름과 판정) 두 갈래 중심
* 전체 세팅 순서를 기동→서비스 계정→시드→RAG→관리자 한 블록으로 정리
* 사실이 아니게 된 낡은 기술 정정(예: case_history 골든 10건뿐 → 30건, 증빙자료 추출 미착수 → 완료, EvalContext 47경로 → 56경로 등)
* core 533건·프론트 빌드 통과 확인
