# 📋 일간 보고 (07/27)

## 1. 데이터 전처리 및 머신러닝

* 머신러닝 학습에 사용할 Feature를 최종 검토하고, 실제 서비스에서도 수집·활용 가능한 Feature만 선별하여 확정하였다.
* 모델 학습을 위한 데이터 전처리 및 Feature 구성을 완료하고, 데이터셋을 정비하였다.
* 기존 랜덤 Train/Test Split 방식에서 시계열 Feature 사용 시 발생할 수 있는 데이터 누수(Data Leakage)를 방지하기 위해 데이터 분할 방식을 재검토하였다.
* 카드별 분할과 시간 기준 분할을 비교한 결과, 실제 운영 환경과 가장 유사한 **시간 기준 분할(Time-based Split)** 을 적용하기로 결정하였다.
* 현재 **XGBoost, LightGBM, Random Forest**를 주요 지도학습 모델로 학습 중이며, **Isolation Forest**를 활용한 비지도 이상거래 탐지도 함께 비교·검증하고 있다.

## 2. 와이어프레임(Figma)

* Figma 기반 화면 설계를 팀원들과 함께 검토하였다.
* 멘토 피드백을 반영하여 대시보드 구성과 정보 가독성을 고도화하였다.
* 실제 업무 Use Flow를 고려하여 세부 모달을 보완하고, 개발자 관점이 아닌 회계 담당자의 사용성을 중심으로 UI/UX를 개선하였다.
* 개발 과정에서 반영할 수정 사항을 정리하여 화면 설계를 보완하고, 구현 기준을 구체화하였다.

## 3. 개발

* Django 백엔드 개발을 진행하며 실제 서비스 구조를 반영한 도메인 모델과 API를 구현하였다.
* 기존 Placeholder 기반 기능 프로토타입을 실제 서비스 형태로 전환하는 작업을 진행하였다.
* Use Case Flow를 기반으로 **Vertical Slice** 방식으로 기능을 개발하며 핵심 사용자 플로우를 순차적으로 구현하였다.
* 프론트엔드와 백엔드를 실제 API로 연동하고, 화면과 서버 간 데이터 흐름 및 기능 동작을 테스트하였다.

# 📋 일간 보고 (07/28)

## 1. Rule Base 고도화

* 법인카드 정산 자동화를 위한 Rule Base 구조를 구체화하였다.
* 거래 유형별 승인·반려·검토 프로세스를 세분화하고, 예외 처리 및 판단 기준을 명확히 정의하였다.
* Rule 기반 검증과 AI 기반 판단이 자연스럽게 연계될 수 있도록 전체 의사결정 흐름을 재설계하였다.

---

## 2. RAG 문서 구축

* Rule Base 고도화에 맞춰 RAG에서 활용할 규정 문서를 추가 생성하였다.
* 기존 규정 외에 **출장**, **회식**, **기업업무추진비** 관련 규정을 작성하여 업무 시나리오별 판단 근거를 보강하였다.
* 다양한 상황에서 일관된 규정 기반 답변과 검증이 가능하도록 지식베이스를 확장하였다.

---

## 3. 머신러닝 모델 검토

* 지도학습과 비지도학습 기반 이상거래 탐지 모델의 성능을 비교·분석하였다.
* **XGBoost**를 활용한 검토 대상 예측 모델과 **Isolation Forest** 기반 이상거래 탐지 모델의 장단점을 분석하였다.
* 실제 서비스 목적과 데이터 특성을 고려하여 두 접근 방식 중 적합한 모델 구조를 검토하고, 최종 적용 방향을 논의하였다.

---

### ✅ 진행 결과

* Rule Base를 실제 업무 프로세스 수준으로 구체화하여 규정 기반 자동 검증 체계를 정립하였다.
* 출장, 회식, 기업업무추진비 등 주요 업무 규정을 RAG 문서로 구축하여 지식베이스를 확장하였다.
* XGBoost와 Isolation Forest를 중심으로 지도·비지도 모델을 비교 분석하며 서비스에 적합한 이상거래 탐지 방식을 검토하고 있다.
