# 비지도 baseline 비교 실험 — One-Class SVM / LOF / SGDOneClassSVM vs Isolation Forest

**작성 기준**: 2026-07-31, 실제 test set(2024년, 469,902건)으로 1회 채점

**목적**: `ml_final_report.md §3-2`에서 정성적으로만 기각했던 비지도 대안(밀도·커널 기반 방법) 중 실무에서 흔히 쓰이는 One-Class SVM·LOF를 실제로 학습·채점해, Isolation Forest 채택 논리를 수치로도 검증한다. 코드: [`unsupervised_baseline_비교.py`](./unsupervised_baseline_비교.py)(`DATA_DIR`만 맞추면 재실행 가능).

---

## 1. 방법

- 전처리는 `법인카드_이상거래_모델링_v2_최종test평가.ipynb`의 셀2·4·6과 완전히 동일한 로직 재사용(피처셋: Tier0 + `일시불할부구분코드`, 원-핫 인코딩 후 X컬럼, train median으로 NaN 대체).
- **Isolation Forest / SGDOneClassSVM**: train 전체(1,482,969건) 그대로 학습 — 두 모델 모두 대용량에 적합한 구조.
- **One-Class SVM(RBF) / LOF(novelty=True)**: `ml_final_report.md §2`의 효율성 벤치마크(합성데이터 기준 스케일링 곡선 외삽)에서 148만 행 전량 학습이 비현실적임을 이미 확인했으므로, 무작위 서브샘플 5만 건(`random_state=42` 고정, 재현 가능)으로 학습.
- test set은 469,902건(2024년, 이상거래 16,394건, 기저율 3.49%) 그대로 사용 — Isolation Forest의 기존 확정 평가와 동일한 대상.
- 평가지표: PR-AUC(`average_precision_score`), recall/precision@top1/3/5/10%. 부호 규약은 4개 모델 모두 "점수가 높을수록 이상"으로 통일(`decision_function`/`score_samples`를 모델별 규약에 맞춰 반전).

## 2. 결과

| 모델 | n_train | fit(초) | predict/469,902건(초) | PR-AUC | recall@top3% | precision@top3% |
|---|---:|---:|---:|---:|---:|---:|
| **Isolation Forest** | 1,482,969(전체) | 1.94 | 5.38 | **0.648** | 0.591 | 0.687 |
| One-Class SVM(RBF) | 50,000(서브샘플) | 86.3 | 1,248.3(≈20.8분) | 0.432 | 0.543 | 0.631 |
| SGDOneClassSVM(선형근사) | 1,482,969(전체) | 3.01 | 0.02 | 0.315 | 0.358 | 0.417 |
| LOF(novelty, k=20) | 50,000(서브샘플) | 11.5 | 46.1 | 0.037~0.066* | 0.051 | 0.060 |

\* LOF는 스코어 부호(양/음)와 원-핫·연속형 혼합 스케일링 여부를 바꿔가며 재확인했으나(§4), 어느 조합도 기저율(0.0349) 대비 의미 있게 높지 않았다.

## 3. ⚠️ Isolation Forest PR-AUC 수치 차이 — 반드시 읽을 것

이번 실행에서 재현한 Isolation Forest의 PR-AUC는 **0.648**로, `isolation_forest_modeling_결과.md`에 기록된 기존 확정치(**0.5865**)와 다르다.

- 데이터는 동일함을 확인했다: train 1,482,969건 / test 469,902건 / 이상거래 16,394건 / 기저율 3.49% 모두 기존 문서와 정확히 일치.
- 피처 엔지니어링 코드·하이퍼파라미터(`n_estimators=200`, `max_samples='auto'`, `contamination='auto'`, `random_state=42`)도 동일 노트북 셀을 그대로 복사해 사용.
- 그럼에도 값이 다른 이유는 **scikit-learn 버전 차이**로 추정된다 — 이번 실행 환경은 scikit-learn 1.8.0. `isolation_forest_modeling_결과.md`(§4 원본 노트북)는 팀원이 별도 환경(커널명 `final_prj`, Python 3.11.15)에서 실행한 것으로 확인됐으나, 그 환경 자체가 남아있지 않아 정확한 scikit-learn 버전은 사후 재구성이 불가능하다. `IsolationForest`는 `random_state`가 같아도 내부 구현이 버전마다 바뀌면 완전히 동일한 트리가 만들어진다는 보장이 없다. 재발 방지를 위해 [`../requirements.txt`](../requirements.txt)를 추가해 앞으로 `ml/`을 재실행할 때는 버전을 고정한다(`apps/ai/requirements.txt`의 서빙 스펙 `scikit-learn==1.5.*`에 맞춤 — scikit-learn 1.5.1 / numpy 1.26.4 / pandas 2.3.3).
- 이 비교 실험의 목적은 "Isolation Forest 대비 다른 비지도 모델이 상대적으로 얼마나 밀리는가"이므로, **4개 모델을 전부 같은 세션·같은 라이브러리 버전으로 실행**해 상대 순위 자체는 유효하다. 다만 절대 수치 0.648을 기존 문서의 0.5865와 나란히 인용하거나 "성능이 개선됐다"는 식으로 서술하지 않도록 주의가 필요하다 — 두 수치는 서로 다른 실행 환경의 결과다.

## 4. LOF 스코어 진단 (왜 이렇게 낮은가)

LOF의 PR-AUC가 기저율 수준으로 낮게 나와, 부호 규약 오류인지 별도로 검증했다.

| 조건 | PR-AUC |
|---|---:|
| 전체 표준화, `score_samples` 그대로(반전 안 함) | 0.045 |
| 전체 표준화, `score_samples` 반전(본 비교에서 채택한 방식) | 0.037 |
| 연속형만 표준화 + 원-핫 더미는 0/1 유지, 반전 | 0.066 |
| 연속형만 표준화 + 원-핫 더미는 0/1 유지, 반전 안 함 | 0.032 |

sklearn 공식 규약(`score_samples`는 클수록 정상 → 이상 점수는 부호 반전)을 따랐을 때 값이 더 높게 나오는 조합(0.066)이 확인되어 반전 방향 자체는 맞다. 다만 어느 스케일링·부호 조합도 기저율(0.0349) 대비 뚜렷한 우위를 보이지 않았다 — 즉 **부호 실수가 아니라, 이 피처 공간(원-핫 인코딩된 저정보 이진 컬럼이 다수)에서 유클리드 거리 기반 지역 밀도비 자체가 판별력을 거의 갖지 못한다**는 것이 진짜 원인으로 보인다. 이는 `ml_final_report.md §3-2`에서 DBSCAN에 대해 이미 제기했던 "밀도 기반 방법은 이런 데이터 구조에 부적합하다"는 우려가, 알고리즘은 다르지만 같은 계열(밀도 기반)인 LOF에서도 수치로 재확인된 것으로 해석한다.

## 5. 해석 및 결론

- **One-Class SVM(RBF)**: 정확도(0.432)도 Isolation Forest보다 낮고, 5만 건 서브샘플만으로도 학습 86초 + 추론 1,248초(≈21분)가 걸린다. Isolation Forest가 148만 건 전체를 학습(1.94초) + 추론(5.38초)하는 것보다 정확도·속도 양쪽에서 열위 — §2에서 예상했던 "전체 규모에서는 현실적으로 비교 불가"라는 결론이 서브샘플 단계에서부터 이미 드러난다.
- **SGDOneClassSVM**: 유일하게 148만 건 전체를 그대로 학습할 수 있었지만(선형 경계라 확장성은 좋음), PR-AUC 0.315로 4개 모델 중 두 번째로 낮다 — 선형 경계만으로는 이 데이터의 비선형적 이상 패턴을 충분히 포착하지 못한다는 뜻이다.
- **LOF**: 정확도가 기저율 수준(0.037~0.066)에 그쳐 사실상 판별력이 없다.
- **종합**: 정확도·연산 효율성 두 기준 모두에서 Isolation Forest가 4개 모델 중 가장 우수했다. 이는 `ml_final_report.md §2`(효율성 논리)와 `§3-2`(정성적 논리)의 결론을 실제 데이터로 재확인한 결과이며, 최종 모델 선정을 바꿀 근거는 나타나지 않았다. 다만 §3에서 명시했듯 이 결론은 고정된 것이 아니라, `decision_labels`가 축적된 뒤 재검증 시 뒤집힐 수 있는 조건부 결론이다.
