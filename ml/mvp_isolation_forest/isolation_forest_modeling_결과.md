## 2. 모델링 — 알고리즘 및 하이퍼파라미터 (완료)

- **알고리즘**: **Isolation Forest** 채택
  - 비지도(라벨 신뢰성 문제, label bias 우려로 지도학습 배제) + 대용량(148만 행) + 정형데이터 조건을 동시에 만족하는 현실적 선택
  - LOF/One-Class SVM은 대용량에 부적합, Autoencoder는 MVP 단계엔 과함
- **하이퍼파라미터 튜닝**: `n_estimators` × `max_samples` 그리드 탐색 → 개선폭이 노이즈 수준(0.26%)이라 **베이스라인 값 유지**
  - 최종: `n_estimators=200`, `max_samples='auto'`, `contamination='auto'`

## 4. 최종 학습 및 test 평가 (완료, 딱 한 번 수행)

**파일**: `법인카드_이상거래_모델링_v4_최종test평가.ipynb`

`train_df`(2021~2023) 전체로 최종 학습 → `test_df`(2024년)에 이 노트북에서 **딱 한 번만** 채점.

### 데이터 규모

| | 건수 | 컬럼 |
|---|---|---|
| train_df | 1,482,969 | 47 |
| test_df | 469,902 | 47 |
| X_train (모델 입력) | 1,482,969 | 24 |
| X_test (모델 입력) | 469,902 | 24 |

전처리: NaN은 train 기준 median으로 대체(누수 방지), 저카디널리티 범주형(`거래요일_한글`, `시간대구간`, `일시불할부구분코드`)은 원-핫 인코딩. train/test 컬럼을 outer join으로 정렬.

### 전체 test 성능

| 지표 | 값 | 베이스레이트(3.49%) 대비 |
|---|---|---|
| PR-AUC | 0.5865 | train fold 평균(0.4946) 대비 개선 |
| recall@top1% / precision@top1% | 24.9% / 86.8% | 약 25배 lift |
| recall@top3% / precision@top3% | 52.6% / 61.1% | 약 17.5배 lift |
| recall@top5% / precision@top5% | 66.4% / 46.3% | — |
| recall@top10% / precision@top10% | 79.0% / 27.6% | — |

### test PR-AUC(0.5865)가 fold 평균(0.4946)보다 높은 이유

성능이 부풀려진 게 아니라 **분할 방식 자체가 다른 조건을 재고 있기 때문**이다.

1. **카드 재사용률 97%가 핵심**: test 기간(2024)에 등장하는 카드의 97%가 train 기간(2021~2023)에도 이미 등장했던 카드다. `사용자평균사용액_확장` 등 확장 통계(expanding statistics) 피처는 그 카드의 과거 이력이 쌓일수록 값이 안정되는 구조라, test 시점엔 3년치 이력이 이미 쌓인 상태에서 평가받는 셈이다.
2. **fold 5개(카드 단위 무작위 분할)는 더 가혹한 조건**: 5-fold 교차검증은 카드를 무작위로 5등분해 검증하므로, 특정 fold에 거래 이력이 짧거나 패턴이 튀는 카드가 몰릴 수 있고 시간 순서도 지키지 않는다. 즉 fold 평균(0.4946)은 "다양한 카드 구성에서도 버티는 보수적 하한선"이고, test(0.5865)는 "실제 운영과 동일 조건(이미 이력이 쌓인 카드)"을 재는 값이라 조건 자체가 더 유리하다.
3. **§4 pseudo-test로 검증**: test 쪽 누수 의심을 해소하기 위해 train 데이터 안에서만 시간 기준으로 pseudo-test를 재현했다(2023-01-01 cutoff). 결과 PR-AUC 0.5536으로 fold 평균보다 test(0.5865)에 훨씬 가까웠다 — test가 특별히 튄 게 아니라 시간 기준 분할이면 원래 이 정도 나온다는 근거.

**한 줄 요약**: fold 평균은 낮게 나오도록 설계된 보수적 벤치마크이고, test는 실제 배포 조건(카드 이력이 이미 쌓인 상태)을 그대로 반영하기 때문에 더 높게 나오는 게 정상이다.

### 세그먼트별 성능 (재사용 카드 vs 신규 카드)

| 지표 | 재사용 카드 | 신규 카드 |
|---|---|---|
| recall@top3% | 0.526 | 0.577 |
| precision@top3% | 0.612 | 0.686 |
| recall@top10% | 0.790 | 0.828 |

### 이상거래 "확률" 값 — raw score를 그대로 쓰면 안 되는 이유

Isolation Forest는 원 논문(Liu et al., 2008) 정의상 `s(x,n)`(0~1) 값을 이상 점수로 제공하지만, 이는 통계적으로 보정된 확률(P(이상거래|x))이 아니다 — 정상/이상 그룹의 `s(x,n)` 분포가 서로 크게 겹친다(정상 평균 0.442, 이상 평균 0.570, 두 그룹 모두 0.72대까지 값이 겹침). 따라서 **raw score를 "이 거래는 이상거래일 확률 N%"로 그대로 UI·RAG에 노출하면 안 된다.**

대신 test set에서 점수 10분위 구간별 **실제 관측 이상거래 비율**을 계산해 보정 테이블로 사용한다 (전체 기저율 3.49% 대비 lift 참고):

| s(x,n) 구간(백분위) | 실제 이상거래 비율 |
|---|---|
| 하위 0~10% | 0.07% |
| 10~20% | 0.22% |
| 20~30% | 0.59% |
| 30~40% | 0.57% |
| 40~50% | 0.52% |
| 50~60% | 0.74% |
| 60~70% | 1.11% |
| 70~80% | 1.26% |
| 80~90% | 2.23% |
| 상위 90~100% | **27.58%** |

**RAG/UI 반영 시 주의사항**
- 상위 10% 구간에 들어가도 실제 확률은 27.6% 수준 — "위험도 90%" 식 표현은 오도의 소지가 있다. "이 점수대는 과거 기준 약 X% 확률로 이상거래였다"는 식으로, 위 실측 구간표를 근거로 문구를 구성해야 한다.
- 이 보정 테이블은 **train 전체 학습 모델을 2024년 test에 적용한 결과**이며, 모델·피처셋이 바뀌면(§2~3) 재계산이 필요하다. RAG에 캐싱할 경우 모델 버전과 함께 태깅해 stale한 확률표가 남지 않도록 주의.
- 절대적 확률보다 "상위 몇 % 구간인가"에 따른 **상대적 lift**로 설명하는 편이 통계적으로 더 정확하다(§5 recall 분석과 같은 맥락).

→ **신규 카드(콜드스타트)에서 오히려 소폭 우세** — "모델이 카드 이력을 암기해 신규 카드에서 성능이 떨어질 것"이라는 우려가 기우였음을 확인 (다만 신규 카드 표본이 작아 — 163건 — 절대 수치보다 상대적 경향으로 해석)

## 5. 우선순위 랭킹 규칙 (재검토 필요 — top3%는 잠정안)

회계팀 실제 검토 용량을 고려해 **상위 3%를 위험 후보로 분류**하기로 잠정 확정했으나, 아래 recall 분석 결과 이 컷오프는 "이상거래를 놓치면 안 된다"는 요구 수준에 못 미쳐 **재검토가 필요**하다.

- **운영 방식(잠정)**: train 점수 분포의 **97번째 백분위수를 고정 임계값**(score ≥ 0.0620)으로 삼아, 매 거래 진입 시 이 값과 비교
- **검증**: 이 고정 임계값을 test에 적용한 결과, 실제 분류 비율 **3.29%**(의도한 3.00%와 차이 0.29%p) — 임계값이 미래 시점(2024년)에도 안정적으로 작동함을 확인
- test 기준 연간 약 15,465건(하루 평균 약 42건)이 '검토대상'으로 분류됨
- **문제점**: 이 컷오프의 recall은 약 52.6%(전체) / 57.7%(신규 카드)에 불과 — 실제 이상거래의 **절반 가까이를 놓친다**. "정상을 이상거래로 보는 것(false positive)은 괜찮지만 이상거래를 놓치는 것(false negative)은 절대 안 된다"는 원칙과 맞지 않는다.

### recall(놓치지 않기) 목표별 필요 검토 비율

precision(정탐률)보다 **recall(실제 이상거래를 놓치지 않는 비율)에 우선순위**를 두고, 목표 recall을 달성하려면 상위 몇 %까지 검토해야 하는지 재계산했다.

**전체 test (469,902건, 이상거래 16,394건)**

| 목표 recall | 필요 검토 건수 | 전체 대비 비율 | 달성 precision |
|---|---|---|---|
| 80% | 50,689건 | 10.79% | 25.9% |
| 85% | 89,220건 | 18.99% | 15.6% |
| 90% | 153,552건 | 32.68% | 9.6% |
| 95% | 255,919건 | 54.46% | 6.1% |
| 99% | 369,887건 | 78.72% | 4.4% |

**신규 카드 세그먼트 (4,574건, 이상거래 163건)**

| 목표 recall | 필요 검토 건수 | 세그먼트 대비 비율 | 달성 precision |
|---|---|---|---|
| 80% | 404건 | 8.83% | 32.4% |
| 85% | 739건 | 16.16% | 18.8% |
| 90% | 1,240건 | 27.11% | 11.9% |
| 95% | 2,623건 | 57.35% | 5.9% |
| 99% | 3,431건 | 75.01% | 4.7% |

**해석 및 시사점**
- recall을 90% 이상으로 올리려면 전체 거래의 **32% 이상**을 검토해야 하고(precision 10% 미만), 99%를 요구하면 **거의 80%**를 검토해야 함 — 이 모델 단일 랭킹만으로는 "거의 다 잡으면서 검토량도 적게"는 구조적으로 불가능하다.
- "절대 놓치면 안 된다"는 요구를 그대로 적용하면 사실상 전수조사에 가까운 검토 비율이 필요해, 회계팀 검토 용량과 정면으로 충돌한다.
- **대안**: Risk Review 2단계 구조(비지도 탐지 → RAG 내규 검증)에서, 1단계 컷오프를 top3%보다 넉넉히(예: top10~15%) 낮춰 recall을 우선 확보한 뒤, 2차 필터(RAG/Rule)로 정밀도를 보강하는 방향이 현실적이다.
- **미해결 사안**: "절대 놓치면 안 된다"가 어느 recall 수준(90%? 95%?)까지를 의미하는지, 그리고 그에 따른 검토 비용 증가를 회계팀·PM과 합의해야 top3% 컷오프를 대체할 최종 값을 정할 수 있다.

### 두 종류의 "라벨"을 구분해야 함

| | `이상거래여부` (AI Hub) | `decision_labels` (실제 운영) |
|---|---|---|
| 정체 | 카드사 자체 부정사용 탐지 기준 | 회계 담당자의 실제 승인/반려 결정 |
| 현재 상태 | 존재함(합성데이터), 지금까지 **평가 전용**으로만 사용 | **아직 존재 안 함** — 서비스 미배포 상태 |
| MVP 용도 | 비지도 모델의 성능 채점(fold/test 평가) | 축적만, 재학습 미사용 |

**정리**: 우리가 지금까지 한 작업(비지도 Isolation Forest + `이상거래여부`를 평가에만 사용)은 지침과 정확히 일치합니다. "정답 라벨이 있으니 지도학습하자"는 제안은 ①지침상 MVP 범위 밖이고, ②그 라벨 자체가 우리가 원하는 정답(정산담당자 판단 기준)이 아니라는 점에서 재검토가 필요합니다.
