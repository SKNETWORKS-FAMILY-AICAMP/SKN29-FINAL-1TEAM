## 🔴 버그 1 (필수 수정) — 가맹점 피처 look-ahead 누수

**위치**: 섹션 5, 셀 id `5bbe62fb` (전체 12번째 셀 / 코드 셀 기준 7번째), `가맹점평균금액_확장` 계산부

**원인**:
`df`를 `['카드KEY', '거래일자', '승인SEQ', '데이터셋구분']` 기준으로 한 번만 정렬해 둔 상태에서 `groupby('가맹점KEY').transform(...)`을 실행함. `transform`은 그룹 내부를 다시 정렬하지 않고 **df에 나타난 행 순서를 그대로 사용**하기 때문에, 가맹점 그룹 내부 순서가 "카드KEY 순 → 그 안에서 날짜순"이 되어버림. 같은 가맹점을 여러 카드가 방문한 경우 `.expanding()`이 실제 시간순이 아니라 "카드 A의 거래들 → 카드 B의 거래들 → ..." 순으로 계산됨.

**결과 / 영향**:
- `shift(1)`이 "시간상 이전 거래"가 아니라 "df 상 이전 행"을 가져오게 되어, 카드KEY가 앞선 카드의 미래 거래(예: 2024년) 금액이 카드KEY가 뒤인 카드의 과거 거래(예: 2021년) 피처에 섞여 들어감.
- `가맹점첫거래여부`도 같은 이유로 부정확함 — "가맹점 그룹 중 실제 최초 거래"가 아니라 "카드KEY 값이 가장 작은 카드의 거래"가 첫거래로 잘못 지정됨.
- `거래금액_Zscore_확장`은 카드 쪽 통계만 사용하므로 이 버그의 영향을 받지 않음.

**왜 숫자로 안 드러났는가**:
`가맹점첫거래여부` 비율(0.51%)은 "가맹점 그룹당 1행"이라는 구조적 성질 때문에 정렬 순서가 맞든 틀리든 거의 같은 값이 나옴. 현재 출력만으로는 버그가 눈에 띄지 않음.

**수정안**:
기존 `add_rolling_count`에서 이미 쓴 패턴(정렬 → 위치 저장 → 원래 순서 복원)을 가맹점 쪽에도 동일하게 적용.

```python
# 가맹점 피처는 가맹점 기준 시간순으로 별도 정렬 후 계산
merchant_sorted = df.sort_values(['가맹점KEY', '거래일자', '승인SEQ', '데이터셋구분'])
merchant_amt = merchant_sorted.groupby('가맹점KEY')['통합승인금액']
result = merchant_amt.transform(lambda s: s.expanding().mean().shift(1))
df['가맹점평균금액_확장'] = result.reindex(df.index)
df['가맹점첫거래여부'] = df['가맹점평균금액_확장'].isna().astype(int)
```

카드 피처 블록과 가맹점 피처 블록을 각각의 정렬 하에 따로 계산하고, `reindex`(또는 `sort_index()`)로 원래 행 순서를 복원하는 구조로 가야 함.

**영향 범위**: 이미 생성된 `train_processed.csv` / `test_processed.csv`는 재생성 필요.

## 🔴 버그 2 (필수 확인) — `카드이용한도금액_구간`이 구간화가 안 됨

**위치**: 섹션 4, 셀 id `b9af5fd3`

```python
df['카드이용한도금액_구간'] = pd.Categorical(
    df['카드이용한도금액'],
    categories=[0, 1_000_000, 5_000_000, 10_000_000],
    ordered=True,
)
```

**원인**: `pd.Categorical(values, categories=[...])`는 구간(bin)이 아니라 **정확히 일치하는 값만** 카테고리로 인정함. `카드이용한도금액`이 연속값(예: 3,240,000원)일 가능성이 높은데, 이 4개 값과 정확히 일치하지 않으면 전부 NaN이 됨.

**의심 근거**: 컬럼명이 "구간"(binning)을 의도하는데 실제 동작은 정확값 매칭이라 이름과 불일치. 노트북 어디서도 이 컬럼의 분포를 출력·검증하지 않음. `카드이용한도금액` 값이 실제로 저 4개뿐이라 의도적으로 저렇게 쓴 것이라면 `value_counts()` 근거를 주석으로 남겨야 함 — 현재 코드만으론 버그와 구분 불가.

**수정안**:
```python
df['카드이용한도금액_구간'] = pd.cut(
    df['카드이용한도금액'],
    bins=[-np.inf, 0, 1_000_000, 5_000_000, 10_000_000, np.inf],
)
```

## 🟠 구조적 이슈 (설계 재검토 필요) — Train/Test 분할 방식 자체

**현재 방식**: AI Hub가 배포한 train(173.6만)/test(21.7만) 파일이 **2021~2024 전체 기간의 무작위 분할**임(같은 모집단, 같은 이상거래 비율, 카드 100% 중복). 노트북은 이를 그대로 쓰되, 시간 기반 피처만 train+test를 합쳐서 `shift(1)`로 계산 후 재분리하는 방식으로 방어함.

**문제**: `shift(1)`은 "행 시점 이전 정보만 사용"(시간적 causality)은 보장하지만, **test 데이터가 train 피처 계산에 관여하지 않아야 한다는 train/test 격리 원칙**은 보장하지 못함. 카드 A의 거래가 3월엔 test 파일에, 6월엔 train 파일에 있다면, 6월(train) 거래의 확장 피처에 3월(test) 거래 금액이 그대로 들어감 — 미래를 보는 건 아니지만 test가 학습 과정을 오염시킴.

| 누수 종류 | 정의 | 현재 방어 여부 |
|---|---|---|
| 시간적 look-ahead 누수 | 거래 시점에 알 수 없는 미래 정보 사용 | 방어됨(버그1 수정 시) |
| Train/Test 오염 | 평가용 test 데이터가 train 피처 계산에 개입 | **방어 안 됨** |

**제안**: 원본 train/test 파일 구분을 버리고 전체를 합친 뒤 **실제 날짜 기준으로 재분할**(예: ~2023 → train, 2024 → test). 이렇게 하면 test가 항상 train보다 시간상 뒤에 있으므로 오염이 구조적으로 불가능해지고, 실제 운영 시나리오("과거 이력으로 미래 거래 판단")와도 일치함.

**진행 전 확인 필요**:
1. 연도별 이상거래 비율이 안정적인지 (2024년만 뗐을 때 3.687%에서 크게 벗어나지 않는지)
2. 컷오프를 "연도 단위"로 할지 "최근 N개월"로 할지
3. 섹션 9의 train 내부 `StratifiedGroupKFold` 검증 fold 구성에 영향 있는지

## 🟡 경미 (동작엔 문제 없음, 참고용)

- **`카드누적사용액`(cumsum) vs `_확장`(shift(1)) 기준 차이**: cumsum은 당일 거래 금액을 포함, `_확장` 계열은 제외. 누수는 아니지만 기준이 다르므로 주석으로 명시 권장.
- **CSV 재로드 시 dtype 유실**: `거래일자`(datetime), `거래연월`(Period), `카드이용한도금액_구간`(카테고리 대상에 미포함)이 CSV에서 문자열로 풀림. 재로드 가이드에 추가 필요.
- **CSV 대신 `to_pickle` 고려** (개선 제안): parquet 엔진 미설치로 CSV를 쓴 것은 이해되나, CSV는 `category` dtype이 풀려 재로딩 시 다시 캐스팅해야 함. `pickle`은 표준 라이브러리 기반이라 `pyarrow` 없이도 dtype을 그대로 보존하고, 494MB CSV보다 빠르고 작을 가능성이 높음. 다음 모델링 노트북에서 반복적으로 다시 읽을 계획이라면 유용.
- **`승인시간대` / `시간대구간` 중복**: 둘 다 Tier 0에 포함. 트리 모델이라 해는 없으나 의도적 중복인지 확인.
- **`데이터셋구분` 타이브레이크**: 정렬 tie-breaker로 쓴 `데이터셋구분`(문자열 `'test' < 'train'`)은 임의적임. 동일 SEQ 충돌 시 test가 앞에 오지만, 노트북 주석에서 이미 "완전한 동시성 해소는 불가능"이라 인정했으므로 재현성·실질적 영향 모두 문제없음.
