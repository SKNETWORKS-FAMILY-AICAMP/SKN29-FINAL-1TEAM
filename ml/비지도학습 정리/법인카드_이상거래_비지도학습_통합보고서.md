# 법인카드 이상거래 탐지 — 비지도 학습 파이프라인 통합 보고서

**범위**: 전처리(v3) → 피처셋 실험 → 최종 test 평가 → 운영 컷오프 분석
**통합 노트북**: `법인카드_이상거래_비지도학습_통합본.ipynb` (Part 1~4)

## 1. 개요 — 이 모델이 시스템에서 하는 일

Risk Review Agent는 2단계 파이프라인이다: **1단계 비지도 이상 탐지가 이상 후보를 선별**하고, 2단계 RAG 내규 검증이 후보에 대해서만 정책·세무 근거를 붙여 우선순위 검토 리스트를 만든다. 이 보고서는 그중 1단계 모델의 개발 전 과정과 결과를 정리한다.

**핵심 결과 요약**

| 항목 | 확정 내용 |
|---|---|
| 알고리즘 | Isolation Forest (`n_estimators=200`, `max_samples='auto'`, `contamination='auto'`) |
| 피처셋 | Tier0(14개) + `일시불할부구분코드`(1개) = **15개** (모델 직접 입력 13개, 원-핫 후 24컬럼) |
| 학습 데이터 | AI Hub 합성 데이터(21-26/21-2), 날짜 기준 재분할 — train 2021~2023 (1,482,969건) / test 2024 (469,902건) |
| 최종 test 성능 | **PR-AUC 0.5865** (test 베이스레이트 3.49%), recall@top3% 52.6% / precision@top3% 61.1% |
| 운영 임계값(잠정) | train 점수 분포 97퍼센타일 고정 임계값 **score ≥ 0.0620** → test 적용 시 3.29% 분류, recall 0.550 / precision 0.583 |
| 미확정 | **컷오프(top3%)는 recall 분석 결과 재검토 필요** (§8) |

## 2. 설계 원칙 — 왜 비지도인가

이 데이터셋의 `이상거래여부` 라벨은 **카드사 자체 부정사용 탐지 기준**이지, 우리가 원하는 정답(정산담당자의 승인/반려 기준)이 아니다. 이 라벨로 지도학습을 하면 카드사 기준의 편향(label bias)을 정답으로 인코딩하게 된다. 따라서:

- `이상거래여부`(AI Hub) — **평가(채점) 전용**으로만 사용. 지도학습 타깃·필터링 금지.
- `decision_labels`(실제 운영, 회계 담당자 결정) — 아직 존재하지 않음(서비스 미배포). MVP에서는 축적만 하고 재학습에 쓰지 않는다.
- `이상거래유형`·`이상거래설명` — 카드사 세부 분류/96% 결측 자유텍스트라 데이터셋에서 완전 삭제.

이 원칙은 프로젝트 문서와 정확히 일치한다: 요구사항명세서 §9.1(Risk Review = 비지도 1차 → RAG 2차 확정), FR-RR-04·FR-RR-08(지도학습 review_probability는 post-MVP), FR-RL-02(decision_labels는 적재만), 기획_확장안_v2 §2.3, 기술명세서 §7(콜드스타트 전제). **"정답 라벨이 있으니 지도학습하자"는 제안은 ① MVP 범위 밖이고 ② 라벨 자체가 우리 기준의 정답이 아니라는 두 가지 이유로 채택하지 않는다.**

## 3. 데이터 및 전처리 (통합본 Part 1)

### 3-1. Train/Test 재분할 — 날짜 기준

AI Hub 원본 train(173.6만 건)/test(21.7만 건)은 **같은 모집단의 무작위 분할**이다(동일 기간 2021~2024, 이상거래 비율 3.687%로 동일, test 카드 2,577개 전부 train에도 존재). 이 경계를 그대로 쓰면 look-ahead는 막아도 **test 데이터가 train 피처(확장 통계) 계산에 개입하는 오염**을 막을 수 없다.

→ 원본 경계를 버리고 `거래일자 < 2024-01-01` 기준으로 재분할: **~2023 train (75.94%) / 2024 test (24.06%)**. test가 항상 시간상 뒤에 있어 오염이 구조적으로 불가능하고, "과거 이력으로 미래 거래를 판단"하는 실제 운영과 일치한다. 연도별 이상거래 비율(3.44~4.12%)이 안정적임을 사전 확인했다.

| 구분 | 건수 | 이상거래 비율 |
|---|---|---|
| train (2021~2023) | 1,482,969 | 3.750% |
| test (2024) | 469,902 | 3.489% |

### 3-2. 주요 전처리 결정

- **`'_'` 플레이스홀더 → NaN 정규화** (`.isnull()`로 잡히지 않는 은닉 결측 — 실제로는 `승인거래코드` 970건).
- **특이값은 삭제 대신 플래그**: `취소성거래_추정`(0원 거래), `전월매출건수/금액_음수여부`, `법인카드_한도미기재추정`. 0원 거래는 이상거래 비율이 오히려 낮고(0.52%), 전월 실적 음수는 위험 신호 후보라 삭제가 정보 손실이다.
- **Leak-free 피처 엔지니어링**: `사용자평균사용액_확장`·`사용자표준편차_확장`·`거래금액_Zscore_확장`은 Expanding Window + `shift(1)`로 해당 거래 이전 정보만 사용. 콜드스타트(첫 거래)는 `fillna`로 숨기지 않고 `카드첫거래여부` 플래그 + NaN으로 보존.
- **가맹점 파생 피처 완전 제외**: `가맹점평균금액_확장`·`가맹점첫거래여부`는 여러 카드가 공유하는 가맹점 특성상 어떤 분할 방식으로도 시간축 정합성 문제(look-ahead)가 재발함을 확인 → 계산 코드 자체를 제거하고, 가맹점 신호는 **RAG(Chroma `case_history`)로 역할 이관**.
- **세그먼트 플래그**: `카드_train노출여부`(test 전용, 평가 진단용) — 재사용 카드 97.0% / 신규 카드 3.0%(거래 4,574건, 카드 73개). 학습 피처가 아니다.
- **검증 fold**: 카드 단위 `StratifiedGroupKFold` 5-fold. 같은 카드가 fold-train/valid에 걸치면 카드 패턴이 새어 검증이 낙관적으로 부풀므로 카드 단위 그룹화, 클래스 불균형(약 26:1) 때문에 라벨 층화.

### 3-3. 피처 Tier 체계 (프로덕션 가용성 기준, 총 40개)

| Tier | 개수 | 내용 | 프로덕션 가용성 |
|---|---|---|---|
| Tier 0 | 14 | transactions 핵심 필드(금액·시각·카드ID)만으로 계산 | 거의 확실히 유지 |
| Tier 1 | 11 | 카드/거래 정산 메타(한도·할부·승인경로 등) | raw_payload 포함 가능성 높음(§11.2 확정 전) |
| Tier 2 | 0 | 조직 데이터 placeholder | `users`/`teams` 조인 필요 — 데이터셋에 없음 |
| Tier 3 | 15 | 가맹점 속성 + 인적정보 | 사실상 재현 불가(MCC post-MVP, 인적정보는 법인카드에서 구조적 `'_'`) |

## 4. 모델링 — 알고리즘·하이퍼파라미터 (통합본 Part 2)

- **Isolation Forest 채택**: 비지도 + 대용량(train 148만 행) + 정형 데이터를 동시에 만족. LOF/One-Class SVM은 대용량 부적합, Autoencoder는 MVP엔 과함.
- **하이퍼파라미터**: `n_estimators` × `max_samples` 그리드 탐색 결과 개선폭(0.26%)이 fold 노이즈(PR-AUC 표준편차 0.051) 이하 → **베이스라인 값 유지** (`n_estimators=200`, `max_samples='auto'`, `contamination='auto'`).

## 5. 피처셋 확정 실험 (통합본 Part 2)

동일 fold·동일 하이퍼파라미터로 공정 비교했다.

| 시도 | PR-AUC (fold 평균) | 비고 |
|---|---|---|
| Tier0 단독 (14개) | 0.4711 (5-fold, 기준선) | — |
| Tier0+1 전체 (25개 → 원-핫 후 32컬럼) | 0.2101 (−55%) | 저정보 이진 컬럼이 무작위 피처 선택을 희석 |
| Tier1 개별 leave-one-in (3-fold, 중복 제거 후 10개) | 9개 마이너스(−3.6~−11.8%) | `일시불할부구분코드`만 +7.2% |
| **Tier0 + 일시불할부구분코드 (5-fold 재검증)** | **0.4946 (+4.98%)** | **최종 채택** |

**핵심 교훈 두 가지**

1. **저정보 원-핫 컬럼은 Isolation Forest에 해롭다.** 분기 피처를 완전히 무작위로 고르는 구조상, 판별력 없는 이진 컬럼이 늘수록 유용한 연속형 피처(누적사용액, Z-score 등)가 뽑힐 확률이 희석된다. NaN 없는 컬럼에 `dummy_na=True`를 켜서 생긴 상수 컬럼도 같은 이유로 유해했다. → Tier1 범주형은 원-핫 대신 `.cat.codes`, `dummy_na`는 실제 NaN이 있을 때만.
2. **중복 정보 제거**: `카드이용한도금액`(원본)과 `카드이용한도금액_구간`은 완전히 같은 정보(값이 {0, 100만, 500만, 1000만} 4개뿐) — 원본 제외.

**✅ 최종 확정 피처셋: Tier0(14개) + `일시불할부구분코드` = 15개.** 단, `거래일자`·`거래연월`은 파생 계산용 식별자라 모델 입력에서 제외되므로 **실제 직접 입력은 13개, 원-핫 후 24컬럼**이다. 팀 문서·발표에는 "확정 피처셋 15개(그중 모델 직접 입력 13개)"로 표기해야 노트북과 일치한다.

부수 효과: Tier1이 사실상 기여하지 않는다는 결과는 raw_payload 스키마 논의(Open Issue)에 "Tier0만으로 MVP 시작 가능"이라는 정량 근거가 된다.

## 6. 최종 학습 및 test 평가 (통합본 Part 3 — 단 1회 채점)

train(2021~2023) 전체로 최종 학습 후 test(2024)에 **딱 한 번만** 채점했다. 결과를 보고 피처/하이퍼파라미터를 바꿔 재실행하는 것은 test를 이용한 누수이므로 금지 — 개선이 필요하면 train 내부 fold로 돌아간다.

전처리(모델 입력): 확장 통계 NaN은 **train 기준 median**으로 대체(test median 재계산 금지), 저카디널리티 범주형 3개(`거래요일_한글`, `시간대구간`, `일시불할부구분코드`)만 원-핫, train/test 컬럼 outer join 정렬.

### 6-1. 전체 test 성능

| 지표 | 값 | 베이스레이트(3.49%) 대비 |
|---|---|---|
| PR-AUC | **0.5865** | fold 평균(0.4946) 대비 높음 — 아래 6-2 참조 |
| recall@top1% / precision@top1% | 24.9% / 86.8% | 약 25배 lift |
| recall@top3% / precision@top3% | 52.6% / 61.1% | 약 17.5배 lift |
| recall@top5% / precision@top5% | 66.4% / 46.3% | — |
| recall@top10% / precision@top10% | 79.0% / 27.6% | — |

### 6-2. test(0.5865) > fold 평균(0.4946)인 이유 — 부풀림이 아니라 조건 차이

1. **카드 재사용률 97%**: test 기간 카드의 97%가 train 기간에 이미 등장. 확장 통계 피처는 이력이 쌓일수록 안정되므로, test는 3년치 이력이 이미 쌓인 상태에서 평가받는다.
2. **fold는 더 가혹한 조건**: 카드 단위 무작위 5-fold는 시간 순서를 지키지 않고 이력 짧은 카드가 특정 fold에 몰릴 수 있다. fold 평균은 "보수적 하한선", test는 "실제 운영과 동일 조건"을 잰다.
3. **pseudo-test 교차 검증**: train 내부에서만 같은 시간 기준 분할(2023-01-01 컷오프)을 재현한 결과 PR-AUC **0.5536** — fold 평균보다 test에 훨씬 가깝다. test가 특별히 튄 게 아니라 시간 기준 분할이면 원래 이 정도 나온다는 근거다.

**한 줄 요약**: fold 평균은 낮게 나오도록 설계된 보수적 벤치마크, test는 실제 배포 조건(카드 이력이 쌓인 상태)의 성능이다.

### 6-3. 세그먼트별 성능 — 재사용 카드 vs 신규 카드

| 지표 | 재사용 카드 (465,328건) | 신규 카드 (4,574건) |
|---|---|---|
| PR-AUC | 0.5865 | 0.6367 |
| recall@top3% / precision@top3% | 0.526 / 0.612 | 0.577 / 0.686 |
| recall@top10% | 0.790 | 0.828 |

**신규 카드(콜드스타트)에서 오히려 소폭 우세** — "카드 이력을 암기해 신규 카드에서 성능이 떨어질 것"이라는 우려는 기우였다. 다만 신규 카드 세그먼트는 표본이 작아(거래 4,574건, 카드 73개, 이상거래 163건) 절대 수치보다 상대적 경향으로 해석해야 한다.

## 7. 점수 해석 — raw score를 "확률"로 노출하면 안 되는 이유 (통합본 Part 4 §10)

Isolation Forest의 `s(x,n)`(0~1, Liu et al. 2008)은 이상 점수일 뿐 보정된 확률 P(이상거래|x)가 아니다. 정상/이상 그룹의 점수 분포가 크게 겹친다(정상 평균 0.442, 이상 평균 0.570, 두 그룹 모두 0.72대까지 겹침). 대신 test에서 점수 10분위 구간별 **실제 관측 이상거래 비율**을 보정 테이블로 쓴다(전체 기저율 3.49%).

| s(x,n) 구간(백분위) | 실측 이상거래 비율 | | s(x,n) 구간(백분위) | 실측 이상거래 비율 |
|---|---|---|---|---|
| 하위 0~10% | 0.07% | | 50~60% | 0.74% |
| 10~20% | 0.22% | | 60~70% | 1.11% |
| 20~30% | 0.59% | | 70~80% | 1.26% |
| 30~40% | 0.57% | | 80~90% | 2.23% |
| 40~50% | 0.52% | | **상위 90~100%** | **27.58%** |

**RAG/UI 반영 시 주의**

- 상위 10% 구간도 실제 확률은 27.6% 수준 — "위험도 90%" 식 표현은 오도. "이 점수대는 과거 기준 약 X% 확률로 이상거래였다"는 실측 기반 문구로 구성한다.
- 이 테이블은 모델·피처셋이 바뀌면 재계산 필요. RAG 캐싱 시 **모델 버전과 함께 태깅**해 stale한 확률표가 남지 않게 한다.
- 절대 확률보다 "상위 몇 % 구간인가"의 **상대적 lift**로 설명하는 편이 통계적으로 더 정확하다.

## 8. 운영 컷오프와 recall 분석 — top3%는 잠정, 재검토 필요 (통합본 Part 3 §7 + Part 4 §9)

### 8-1. 고정 임계값 방식과 검증 결과

운영에서는 매 거래 진입 시 미리 정한 고정 임계값과 비교해야 한다. train 점수 분포의 **97퍼센타일(score ≥ 0.0620)**을 고정 임계값으로 삼아 test에 적용했다. 두 수치를 반드시 구분해서 기재한다:

| 기준 | 분류 비율 | recall | precision |
|---|---|---|---|
| (a) test 내 정확히 top3% (14,097건) — 이상적 참고치 | 3.00% | 0.526 | 0.611 |
| **(b) train 기준 고정 임계값 적용 (15,465건) — 운영 기대 성능** | **3.29%** | **0.550** | **0.583** |

드리프트는 0.29%p로 작아 **임계값 자체는 미래 시점에도 안정적**이다. test 기준 연간 약 15,465건, 하루 평균 약 42건이 검토대상으로 분류된다.

### 8-2. 문제 — recall이 요구 수준에 못 미친다

"정상을 이상거래로 보는 것(FP)은 괜찮지만 이상거래를 놓치는 것(FN)은 절대 안 된다"는 원칙에 비추면, 이 컷오프는 실제 이상거래의 **절반 가까이(45%)를 놓친다**. 목표 recall별 필요 검토 비율을 재계산한 결과:

**전체 test (469,902건, 이상거래 16,394건)**

| 목표 recall | 필요 검토 건수 | 전체 대비 비율 | 달성 precision |
|---|---|---|---|
| 80% | 50,689 | 10.79% | 25.9% |
| 85% | 89,220 | 18.99% | 15.6% |
| 90% | 153,552 | 32.68% | 9.6% |
| 95% | 255,919 | 54.46% | 6.1% |
| 99% | 369,887 | 78.72% | 4.4% |

**신규 카드 세그먼트 (4,574건, 이상거래 163건)**

| 목표 recall | 필요 검토 건수 | 세그먼트 대비 비율 | 달성 precision |
|---|---|---|---|
| 80% | 404 | 8.83% | 32.4% |
| 85% | 739 | 16.16% | 18.8% |
| 90% | 1,240 | 27.11% | 11.9% |
| 95% | 2,623 | 57.35% | 5.9% |
| 99% | 3,431 | 75.01% | 4.7% |

**시사점**

- recall 90%에는 전체의 32% 이상 검토(precision 10% 미만), 99%에는 거의 80% 검토가 필요 — **이 모델 단일 랭킹만으로 "거의 다 잡으면서 검토량도 적게"는 구조적으로 불가능**하다.
- "절대 놓치면 안 된다"를 그대로 적용하면 사실상 전수조사에 가까워 회계팀 검토 용량과 정면 충돌한다.
- **현실적 대안**: Risk Review 2단계 구조를 활용해, 1단계 컷오프를 top3%보다 넉넉히(예: top10~15%) 낮춰 recall을 먼저 확보하고, 2단계(RAG 내규 검증 / Rule)로 precision을 보강한다.
- **합의 필요**: "놓치면 안 된다"가 recall 몇 %(90%? 95%?)를 의미하는지, 그에 따른 검토 비용 증가를 회계팀이 감당 가능한지 PM·회계팀과 합의해야 top3%를 대체할 최종 값을 정할 수 있다.

## 9. 통합 검토에서 정리한 사항 (문서 정합성)

이번 통합 과정에서 기존 문서·노트북 간 아래 불일치를 확인하고 이 보고서 기준으로 정리했다.

1. **파일 버전 표기**: 기존 결과 문서는 "모델링 v3(Tier 비교) / v4(최종 평가)"로 언급했으나 실제 파일명은 `모델링_v1_Tier0vs1_비교` / `모델링_v2_최종test평가`다. 이 보고서와 통합 노트북은 실제 파일명 기준으로 통일했다. 전처리는 v3이 최종본이며 v2(가맹점제외)는 v3에 포함된 구버전이다.
2. **recall 수치의 (a)/(b) 혼용**: 기존 문서 §5는 고정 임계값 기준 건수(15,465건)와 top3% 정확 컷 기준 recall(52.6%)을 함께 언급했다. 정확히는 (a) test 내 정확 top3%: recall 0.526 / precision 0.611, **(b) 고정 임계값 적용(운영 기대치): recall 0.550 / precision 0.583** — 팀 문서에는 (b)를 운영 성능으로, (a)를 참고치로 병기해야 한다.
3. **"신규 카드 163건"의 의미**: 163은 신규 카드 세그먼트 내 **이상거래 건수**다(거래 4,574건, 카드 73개). "표본 163건"으로만 쓰면 오해 소지가 있어 명확히 했다.
4. **피처 개수 표기**: "15개로 학습"이 아니라 "확정 피처셋 15개, 그중 모델 직접 입력 13개(원-핫 후 24컬럼)"가 정확하다.
5. **재현 코드 누락 보완**: §7 보정 테이블과 §8 recall 분석은 기존 문서에 수치만 있고 코드가 없었다. 통합 노트북 Part 4에 재현 코드를 추가했다(아직 미실행 — 재실행 시 본 보고서 수치와 일치하는지 확인 필요).
6. **베이스레이트 표기**: 전체 데이터 3.687%, train 3.750%, test 3.489% — 문맥에 따라 다른 값이므로 혼용하지 않는다. test 성능 논의의 기저율은 3.49%다.

## 10. 확정 / 미해결 / 다음 단계

**확정 (Open Issue #2 "이상탐지 알고리즘·피처셋" — 1차 해소)**

- Isolation Forest + Tier0(14) + `일시불할부구분코드` = 15개 피처셋, 베이스라인 하이퍼파라미터
- 검증 체계: 카드 단위 5-fold(보수적 하한선 0.4946) + 시간 기준 test(0.5865) + pseudo-test(0.5536) 교차 확인
- 지도학습 미사용 원칙 유지(§2) — MVP 문서 지침과 일치

**미해결 사안**

- **[핵심] 운영 컷오프**: top3%(고정 임계값 0.0620)는 임계값 안정성만 확인된 잠정안. recall 55.0%로는 "놓치지 않기" 요구 미달 — recall 목표치(90%? 95%?)와 검토 용량 증가(32~54%)를 PM·회계팀과 합의 후 최종 결정. 1단계 컷을 top10~15%로 낮추고 2단계(RAG)로 정밀도 보강하는 안을 우선 검토.
- **Open Issue #1(Rule Agent θ_pass/θ_reject)과 이번 anomaly score 컷오프는 별개 사안** — 혼동 주의.
- fold 4가 지속적으로 낮게 나온 원인 미조사(성능 영향은 크지 않아 보이나 참고 필요).
- **[운영 전환 시]** `최근7일사용횟수`·`카드누적사용액`·확장 통계는 현재 배치 전처리 산출물이다. FastMCP `ml_infer`가 실시간 거래 진입 시점에 이 피처를 어떻게 재현할지(Django 내부 read API로 과거 거래 조회 후 계산 vs 별도 피처 저장소)는 Risk Review Agent 서빙 설계 시 별도 논의.
- Part 4 재현 코드 실행 및 수치 일치 확인.
