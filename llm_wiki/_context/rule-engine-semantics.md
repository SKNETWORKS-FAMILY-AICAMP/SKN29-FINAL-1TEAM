# 룰엔진은 분류기다 — 판정 의미론

_최종 갱신: 2026-08-25 · 상태: 캐논(불변식)_

> **한 줄**: 룰엔진은 **확실한 건만 분류**하고 나머지는 사람에게 넘긴다. 검토는 실패가
> 아니고, 승인대기는 기본값이 아니다.

관련: [[rule-engine]] · [[default-gate]] · [[settlement-ui-rules]] · [[rule-flags]]

---

## 1. 룰엔진의 역할 — 규칙 기반 **분류기**

룰엔진은 「잘못된 지출을 찾는 탐지기」가 아니다. **규칙으로 결론 낼 수 있는 건을 골라내는
분류기**다. 결론이 안 나면 사람에게 넘긴다.

```
       ┌─ PASS   (승인대기)  ─┐
정산 ──┼─ RETURN (보완요청)  ─┼─ 룰이 **확정**했다  → 자동처리
       ├─ REJECT (반려)      ─┘
       └─ REVIEW (검토)      ─── 룰이 **확정 못 했다** → 사람에게
```

### 자동처리 = 확정한 것 전부

**`PASS`만이 아니다.** 보완요청도 반려도 룰이 「이 건은 이렇다」고 결론 낸 것이다 —
사람이 규칙을 대신 판단해 줄 필요가 없다.

    자동처리율 = 1 − (REVIEW 건수 / 판정 건수)

`RETURN`을 자동처리에서 빼면 **룰을 더해 보완요청을 더 잘 잡을수록 지표가 나빠진다.**
회계가 규칙을 촘촘히 만들수록 자동처리율은 **올라가야** 한다.

### 검토(REVIEW)는 실패가 아니다

검토로 간 건은 룰이 틀린 게 아니라 **아직 규칙이 없거나, 규칙이 참조할 사실이 없는** 건이다.
정상적인 결과이고, 시스템이 정직하게 「모른다」고 말한 것이다.

> 검토 건수는 **회계가 아직 정의하지 않은 영역의 크기**다.

## 2. 승인대기(PASS)는 적극적 결정이다

`PASS`는 「문제를 못 찾았다」가 아니라 **「이런 기준을 만족했으므로 승인해도 된다」**는
결정이다. 이 결정 뒤에는 회계 담당자의 확정 클릭 하나만 남는다 — 사실상 승인이다.

### ⛔ 디폴트 PASS 금지

**「위반 조건에 안 걸렸으니 통과」는 틀린 구조다.** 규칙이 보지 않은 것은 「문제없음」이
아니라 「모름」이고, 모름은 `REVIEW`다.

| | 방식 | 결과 |
|---|---|---|
| ❌ 블랙리스트 | 위반 노드 나열 → 안 걸리면 `PASS` | **못 적은 위반이 전부 승인된다** |
| ✅ 화이트리스트 | 통과 요건 나열 → 다 만족해야 `PASS`, 아니면 `REVIEW` | 못 적은 것은 사람에게 간다 |

DEFAULT GATE가 「기본 `REVIEW`+사유, `PASS`는 화이트리스트」인 이유가 이것이다
([[default-gate]] §4.1). 자동 통과 요건을 **가드에 맡기지 않고 화이트리스트에 적는다** —
맡겼더니 실사용자 `False` 건이 통과했다.

## 3. 도입 곡선 — 검토가 줄고 판정이 는다

```
도입 직후          회계가 규칙을 쌓는 중              성숙
├─ PASS    소수    ├─ PASS    ↑                    ├─ PASS    다수
├─ RETURN  0       ├─ RETURN  ↑                    ├─ RETURN  적정
└─ REVIEW  대부분  └─ REVIEW  ↓                    └─ REVIEW  예외만
```

**초기 DEFAULT GATE가 거의 모든 건에 플래그만 달아 검토로 넘기는 것은 정상이다.**
제품이 그 회사 규정을 모르는 상태에서 승인 결정을 대신할 수 없다. 회계가 자사 규정을
올려 룰을 만들수록 확정 비율이 오르고 검토가 줄어든다 — 그게 도입의 진척도다.

## 4. 오탐·미탐의 정의

**분류기의 지표**이므로 「사람에게 보냈는가」가 아니라 **「확정을 맞게 했는가」**로 잰다.

| | 뜻 | 왜 나쁜가 |
|---|---|---|
| **오탐(FP)** | **틀리게 확정했다** — ① 보완·반려할 건을 `PASS`로 ② 승인할 건을 `RETURN`/`REJECT`로 | ①은 잘못된 지출이 확정된다 ②는 멀쩡한 건을 되돌려 사람을 두 번 일하게 한다 |
| **미탐(FN)** | **확정할 수 있었는데 `REVIEW`로 넘겼다** | 사람이 안 해도 될 일을 한다. 틀린 건 아니라 오탐보다 가볍다 |

**검토로 보낸 것 자체는 오탐이 아니다.** 그건 분류를 안 한 것이지 틀리게 분류한 것이 아니다.

> ⚠️ 흔한 착각: 「멀쩡한 건이 검토로 갔다 = 오탐」. **아니다.** 그건 미탐(분류 못 함)이다.
> 오탐은 **확정이 틀린 것**만 말한다.

## 5. 상태 대응

| 룰 판정 | 정산 상태 | 뜻 |
|---|---|---|
| `PASS` | `PENDING_CONFIRM` (승인대기) | 규칙상 승인해도 된다 — 회계 확정만 남음 |
| `RETURN` | `RETURNED` (보완요청) | 규칙상 이대로는 안 된다 — 고쳐서 재제출 |
| `REJECT` | `RETURNED` | **엔진은 최종반려를 만들지 않는다** — 규칙이 낸 REJECT도 상태는 보완요청 |
| `REVIEW` | `IN_REVIEW` (검토중) | 규칙으로 결론이 안 난다 — 사람이 본다 |

**`REJECT`(최종반려)는 회계 담당자의 `review()`만 할 수 있다.** 재제출 불가 단말을 규칙이
만들면 되돌릴 방법이 없다([[rule-engine]] · "사람 확정 원칙").

## 6. 이 문서에 반해서 잡은 결함 (2026-08-25)

| 위치 | 무엇이 틀렸나 |
|---|---|
| `orchestrator._combine` | 과목 그래프 없이 게이트 `PASS`를 유지 — **그 자체는 옳다**(게이트가 화이트리스트일 때). 다만 그 전제가 주석에 없어 아래 결함이 조용히 성립했다. 전제를 명시했다 |
| `simulation.py` `"auto"` | 자동처리 = `PASS`만. **`RETURN`을 더 잘 잡을수록 자동처리율이 떨어진다** — 룰 콘솔이 회계에게 거꾸로 된 신호를 준다 |
| `rule_eval` (신규) | 자동처리·오탐·미탐 정의가 전부 「사람에게 보냈는가」 기준이었다 |
| `seed_rules` GLOBAL | `_GLOBAL_PASS`가 `True` 종단 — **블랙리스트**다. 🚨 **미해결** |

### ✅ 해결 — 게이트를 화이트리스트로 바꿨다 (2026-08-25)

`domain/policies/rule_timeline.py`가 게이트·과목 그래프의 **정본**이 됐다. 모든 게이트
버전이 자동 통과 요건을 명시한 화이트리스트 종단으로 끝나고, **요건을 못 채우면
`G-REVIEW`로 간다**.

> ⚠️ **`G-REVIEW`가 없으면 화이트리스트가 무력해진다.** 엔진은 다음 노드가 없을 때
> 「조건이 맞았는가」와 무관하게 **그 노드의 액션**을 돌려준다 — `G-PASS`(액션 `PASS`)를
> 단말로 두면 요건을 못 채운 건까지 `PASS`가 된다(실측: 금액 상한을 3만으로 좁혀도
> 자동처리율이 100% 그대로였다). NO_MATCH를 별도 `REVIEW` 노드로 보내야 한다.

**측정**(검증셋 300건, `rule_eval`): 자동처리율 **26.3% → 90.0%**, 오탐율 **0%**.
단계별 수치는 `.personal/RULE_EVOLUTION.md`.

**시드 실측**(`seed_adopted`, 182건): 자동처리율 92.3% → **76.9%**, `RETURN` **0 → 5**.
자동처리율이 떨어진 것이 개선이다 — 이전 92.3%는 「위반 못 찾음 → 승인」 122건이
떠받치고 있었다.

### 🚧 남은 것 — 시연 시드가 새 룰과 아직 정합되지 않았다

`domain/policies/tests/test_seed_adopted.py` 3건이 실패한다. 그 테스트의 설계 의도가
**「룰이 바뀌면 여기서 먼저 깨져야 한다」**이므로 정상적인 신호다.

| 실패 | 뜻 |
|---|---|
| 검토 건에 사유 플래그가 없다 | `G-REVIEW` 경로의 플래그가 `rule_judgement`에 안 실린다 |
| 미해소 사실 잔존(회식 1인당) | 시드가 확인 인원을 못 채운 건이 남았다 |
| 지난달에 `RETURNED` 미결 | 새 룰이 낸 보완요청을 시드가 처리하지 않고 끝낸다 |

**룰 자체는 검증셋 300건으로 증명됐다**(오탐 0). 남은 것은 시연 데이터를 새 룰에 맞추는
일이지 룰을 되돌릴 이유가 아니다.
