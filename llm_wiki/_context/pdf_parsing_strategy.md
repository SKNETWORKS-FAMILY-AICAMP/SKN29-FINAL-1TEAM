## 2. 엔진 결정 — docling 채택

### 2.1 채택 구성 📏

```python
# docling 2.x / PyPdfium2 백엔드 (실패 시 docling-parse 기본 백엔드로 폴백)
os.environ.setdefault("TORCHDYNAMO_DISABLE", "1")   # ← import 이전에 반드시

pipeline_options = PdfPipelineOptions()
pipeline_options.do_table_structure = True
pipeline_options.table_structure_options.do_cell_matching = True
pipeline_options.do_ocr = False                            # 텍스트 레이어 존재(전 문서 확인)
pipeline_options.heading_hierarchy_options.enabled = True  # 계층 복원의 핵심 스위치
```

- **백엔드 2단 폴백**: `PyPdfiumDocumentBackend` → 실패 시 `docling-parse` 기본. 📏 현재 코퍼스 11종은 전부 1순위에서 `SUCCESS`.
- **OCR 비활성**: 📏 11종 전부 텍스트 레이어 보유, 문자 추출률 0.703~0.958. 스캔본은 현재 코퍼스에 **없다** → OCR은 경로만 열어두고 파라미터는 실 데이터 유입 시 확정.
- **컨버터 재사용**: 모델 로딩 비용 때문에 문서마다 만들지 않는다.

### 2.2 이전안(PyMuPDF + pdfplumber 수제 조립)을 폐기하는 이유

## 3. 실측된 결함 6종 (교정 대상)

현재 `docling_eval/output/markdown/`은 **후처리가 걸리지 않은 raw 출력**이다. 아래는 그 실물에서 확인된 것이다.

### 3.1 [C2] 장(章) 귀속 붕괴 — **최우선. 규정 문서 4/4에서 발생** 📏

장 헤딩이 한 섹션씩 밀려 **조문이 잘못된 장에 소속**된다.

| 문서 | 실제 출력 순서 |
|---|---|
| 법인카드_사용규정 | 제3조 → `## 제1장 총칙` → 제4조 … 제8조 앞 `## 제3장`, 제9조 앞 `## 제2장` |
| 업무추진비_사용규정 | 제3조 → `## 제2장` → 제4조 → `## 제1장 총칙` → 제5조 |
| 출장비_사용규정 | 제2장→제4조, 제1장→제5조, `## 제5장`이 **별표2 뒤 맨 끝** |
| 회식_운영규정 | 제2조 → `## 제1장 총칙` → 제3조 |

**원인 규명 📏 (2026-08-12, bbox 대조)** — 밀린 장 헤딩은 전부 **그 페이지의 최상단 요소인데 그 페이지의 마지막 순서로 배치**된 것이다. docling이 페이지 상단 밴드 요소를 뒤로 미루면서 생긴다.

```
법인카드 p2 :  제1조(top=666.8) → 제2조(572.0) → 제3조(277.1) → 제1장 총칙(top=717.1)
                                                                  └ 최상단인데 순서는 끝
```

**따라서 장 헤딩을 개별 교정할 필요가 없다.** 페이지 안에서 기하학적 순서를 어긴 요소를 제자리로 되돌리면 장 귀속은 결과로 따라온다. 📏 전체 위반은 11종 4,388요소 중 **21건**뿐이고 그중 8건이 규정 4종의 장 헤딩이다 — 파급 범위가 작고 판정이 결정론적이다.

방치 시: `section_path`·`parent_id` 메타가 통째로 거짓이 되고, "총칙에 뭐라고 돼 있나" 류 질의가 엉뚱한 조문을 반환한다. 📏 부모-자식 정확도 0.737의 주범.

### 3.2 [C3] 항(項)·호(號) 마커 파손 📏

**규정형** — 목록 마커 박스가 항목 텍스트 **뒤**에 렌더돼, 번호가 문단 꼬리에 붙는다.
```
- 사적 용도의 지출 1.                        ← 이 "1."은 **이 항목 자신**의 번호(1호)
- 유흥업소, 사행성 업종에서의 지출 2.          ← 2호
```
📏 고아 마커 검출(교정기 판정 기준): 법인카드 **26** · 업무추진비 **23** · 회식 **21** · 출장비 **21** · 직급체계 **4** = **95건**.

> ⚠️ **마커는 자기 자신의 번호다. 다음 항의 번호가 아니다.** 꼬리에 붙어 있어 다음 항목 것으로 읽기 쉽고, 한 칸 밀려 해석하면 **모든 호 번호가 어긋난다**. 구현 중 실제로 이 방향을 한 번 틀렸고 조문 본문 대조로 잡았다 — 번호 연속성 검사만으로는 안 걸린다(밀려도 1,2,3…으로 보인다).

**법령형** — `①②③`이 **잘못된 순번의 ordered list**로 변환된다.
```
3. ② 제1항에도 불구하고 대통령령으로 정하는 신탁재산…
9. ④ 제2항에 따라 수탁자가 납세의무자가 되는…
```
📏 원문자 항이 리스트 항목으로 오변환: 법인세법 **98** · 부가가치세법 **78** · 여신전문금융업법 **34** 건.

방치 시: **"제6조 제3항" 인용이 원천적으로 불가능**하다. Rule Agent가 조항 근거를 달아야 하는 구조에서 치명적.

### 3.3 [C1] CJK 양끝맞춤 자간·어절 내 줄바꿈 📏

```
## 타 이 거 주 식 회 사 ( T i ge r I n c . )      ← 문서 제목
…원칙적으로 개인 법인카드를 발 급한다.            ← 어절 내부 분리
…제10조 사전승인 예외절차 신 설, 별표1…
```
📏 **토큰 기준 결함 요소 667건** — 법인세법 387 · 부가세 139 · 여신 87 · 규정 4종 37 · 도해 4종 17.
📏 표 셀에서 공백만 다른 건 **161건** (Cell Acc loose 0.965 vs strict 0.755의 간극이 곧 이 결함).

> ⚠️ **계측은 반드시 토큰 단위로 한다.** `([가-힣] ){3,}[가-힣]` 같은 **문자 단위** 정규식은 정상 한국어("구현 시 두 기준을")도 잡아 실제보다 부풀린다. 초기 계측치 399는 이 방식이라 신뢰할 수 없다. 판정 기준은 ① 한 글자 토큰 3연속 이상 ② 조사가 단독 토큰으로 떨어진 경우 두 가지다 (`parsing/scoring.py`).

방치 시: 임베딩·BM25 양쪽 품질 저하. **문서 제목이 저 상태면 메타데이터로도 못 쓴다.**

> ⚠️ CJK 양끝맞춤은 어절 내/간 간격이 동일해 **원리상 완전 복원이 불가능**하다. 어휘 사전 기반 추정 + 원본 대조 채점이 한계선이다. 100%를 목표로 잡지 말 것.

### 3.4 [C4] 법령형 목차 덤프 📏

조문 제목 수백 개가 **한 줄짜리 코드블록**으로 덤프된다(법인세법 5블록, 부가세법·여신 각 3블록). 청킹하면 그대로 거대 노이즈 청크가 된다.

> **정정 📏 (2026-08-12)**: `&lt;개정 2020. 12. 22.&gt;` escape 846건은 **요소 텍스트에 없다.** docling의 `export_to_markdown()`이 직렬화하면서 넣는 것이고, 요소에는 `<개정 2010`처럼 원문 그대로 들어 있다. 우리는 `Element.text`에서 직접 직렬화하므로 **이 결함은 우리 경로에 존재하지 않는다.** C4의 unescape는 방어용으로만 남긴다(실측 적용 0건).

### 3.5 [C5] 페이지 경계 표 분할 📏 11건

인접 페이지에서 동일 열 구조 표가 쪼개진다(부서소개 2, 조직설계 4, 회식 2, 직급체계 1, 출장비 1, 조직도 1). 📏 행 정확도 0.594의 주된 원인이며, **열 정확도가 1.00인 것이 곧 "구조는 맞는데 행만 갈렸다"는 증거**다.

> ✅ **핵심 한도표는 무사하다.** 법인카드 직책별 한도(5x4), 업무추진비 별표1 청탁금지법 한도·별표2, 출장비 별표1/2 — 값·헤더 전건 정확. 행 손실로 잡힌 `법인카드 t1`·`출장비 t1`은 **제정일/시행일/소관부서 메타 표**로 실피해가 없다. **표 교정은 우선순위가 낮다.**

### 3.6 [C6] 헤딩 텍스트 오염 / furniture 미검증 📏

## 4. 문서 유형 프로파일 — 교정은 문서마다 다르게 건다

**원칙: 라우팅 단위는 문서다.** 이전안은 페이지 단위 라우팅을 설계했으나, 실측된 결함은 전부 **문서 종류에 따라 존재하거나 존재하지 않는** 성질이다(법령엔 자간 결함이 있고 목차 덤프가 있으며 고아 마커는 적다). 페이지 단위 분기는 지금 코퍼스에서 근거가 없다. **필요해질 때 도입한다.**

### 4.1 유형 판정

```python
def detect_profile(doc) -> str:
    if _has_law_toc_block(doc) or _has_circled_clauses(doc):   # 코드블록 목차 or ①②③ 다수
        return "LAW"
    if _table_area_ratio(doc) > 0.5 or _heading_depth(doc) <= 1:
        return "DIAGRAM"
    if _matches(r"제\d+조\s*\(", doc):
        return "REGULATION"
    return "GENERIC"
```

📏 판정 신호는 실측에서 뽑았다 — 법령 3종만 코드블록 목차·HTML escape·원문자 항을 가지며, 도해 4종은 `Flat? = YES (계층 없음)` 또는 표 비중이 압도적이다(부서소개 표 9/요소 32).

### 4.2 프로파일별 교정 단계

| 단계 | 결함 | REGULATION | LAW | DIAGRAM | GENERIC |
|---|---|:--:|:--:|:--:|:--:|
| **C1** 자간·어절 재결합 | §3.3 | ✅ | ✅ | ✅ | ✅ |

## 5. 교정 단계 명세

**원칙: 모든 교정 단계는 「적용 조건 + 예외 조건 + 실패 시 무해(no-op)」 3종을 갖춘다.** 조건 없는 후처리는 반드시 본문을 잘라먹는다. 이 원칙만은 이전안에서 그대로 계승한다.

### C1. 자간·어절 재결합 — [전 프로파일 적용]

| | |
|---|---|
| **입력 신호** | 한글 1음절 + 단일 공백이 3회 이상 연속 / 어절 중간 공백 |
| **처리** | ① NFKC 정규화 + NBSP·제로폭 제거 ② 1음절 연속 패턴 → 공백 전량 제거(제목·헤딩) ③ 본문은 **어휘 사전 조회로 재결합 후보만** 병합 |
| **예외** | 표 셀 안 / `code_block`(ASCII 조직도 — 들여쓰기가 곧 조직 계층) / 영문·숫자 사이 공백 |

### C2. 기하학적 리딩오더 복구 + 장-조 귀속 — [전 프로파일]

§3.1에서 규명한 대로, 밀린 장 헤딩은 **페이지 최상단 요소가 그 페이지 마지막 순서로 배치**된 것이다. 그러니 장을 특별 취급하지 않고 **읽기 순서 자체를 기하학적 위치에 맞춰 되돌린다.** 장 귀속은 결과로 따라온다.

```python
def _violations(page_elements):          # 현재 순서 기준, 앞선 요소보다 물리적으로 위에 있는 것
    out, max_top = [], -inf
    for el in page_elements:
        if max_top > -inf and el.top > max_top + TOP_EPS:
            out.append(el)
        max_top = max(max_top, el.top)
    return out
# 위반이 있는 페이지만 top 내림차순으로 안정 정렬 → 이후 장/조 태깅
```

| | |
|---|---|
| **적용 조건** | 본문 요소의 90% 이상이 bbox 보유 **AND** 해당 페이지에 순서 위반 존재 |
| **예외 1** | 페이지의 25%를 넘게 어긋나면 **단일 컬럼 가정이 깨진 것**으로 보고 그 페이지는 건드리지 않는다 |
| **예외 2** | 요소 8개 미만 페이지는 위반 1건만으로 비율이 튀므로 비율 판정을 적용하지 않는다 (표지 페이지 보호) |
| **예외 3** | `별표`·`부칙`은 장 소속이 아닌 최상위 형제. 부칙은 조 번호가 다시 1부터라 단조성 추적도 끊는다 |
| **실패 시** | 재배열하지 않는다(no-op). 장 계층이 서지 않으면 **조를 최상위로 승격**하고 리포트에 남긴다 — 틀린 장에 매다는 것보다 장이 없는 편이 낫다 |
| **실측 결과 📏** | 위반 21/4,388건 이동. 장 순서·조 순서 **11종 전건 정합**, 장 미귀속 조 1건(여신법) |

> **왜 "조 번호 역산"이 아니라 "기하 복구"인가**: 초안은 조 번호 단조성으로 장 범위를 역산하려 했으나, 실측해 보니 그 방법으로는 복원되지 않는 경우가 있었다(법인카드에서 제2장의 시작 조를 특정할 수 없음). 반면 bbox 기반 복구는 **원인을 직접 되돌리는 것**이라 애매함이 없고, 장뿐 아니라 모든 오배치 요소를 함께 고친다.

### C3. 항/호 마커 복원 — [REGULATION·LAW]

**REGULATION · DIAGRAM** — 고아 마커를 **자기 요소의 앞으로** 되돌린다:
```python
ORPHAN = re.compile(r"\s(\d{1,2})\.\s*$")          # 문단 끝 "… 지출 1."
```
| | |
|---|---|
| **처리** | 문단 끝 `N.` 을 떼어 **그 요소 자신의 앞**에 붙이고 `clause_no=N` 부착. 다음 요소로 넘기지 않는다(§3.2 경고) |
| **예외 3종** | ① 조문 인용 꼬리 `…제10조.` ② **앞이 또 숫자+마침표**면 날짜 나열 — `2026. 7. 20.` 뿐 아니라 법령의 `<개정 2018. 12. 24., 2020. 12.` 도 여기서 걸린다 ③ 한글이 없는 순수 숫자 요소 |
| **실패 시** | 조 블록 안 번호가 불연속이면 **원문 유지 + `marker_uncertain` 마킹**. 청크는 만들되 인용 신뢰도를 낮춘다 |
| **실측 결과 📏** | 95건 전건 복원, 잔존 0 |

**LAW** — 원문자 항 보존:
| | |
|---|---|
| **처리** | `①~⑮`로 시작하는 요소는 `list_item` → `paragraph`로 되돌려 **자동 번호가 붙는 경로를 끊고**, `clause_no`·`no_auto_number`를 부착. NFKC가 `①→1`로 바꾸지 않도록 C1보다 **먼저** 실행 |
| **예외** | 본문 중간의 원문자(조문 인용 `제3조제1항①`)는 변환하지 않음 — 시작 위치만 본다 |
| **항 번호 검증** | **1부터 시작할 것을 요구하지 않는다.** 법령은 ①이 조 제목과 같은 줄에 들어가는 일이 많아(`제3조(납세의무자) ① 다음 각 호의…`) 독립 요소로는 ②부터가 정상이다. 보는 것은 시작값이 아니라 **연속성** |
| **실측 결과 📏** | 자동번호 항 **882건 → 0** (법인세 488·부가세 197·여신 197). 불연속으로 `marker_uncertain` 표시된 조 7개 |

> ⚠️ **실행 순서 의존**: C3(LAW) → C1 순서를 지켜야 한다. NFKC가 원문자를 먼저 뭉개면 복원 불가다.

### C8. 실행 순서 (의존성 있음)

실행 순서는 `corrections/pipeline.py`의 `PLANS`에 프로파일별로 고정돼 있다.

```
0. docling 변환                    → DoclingDocument → Element[]
1. C4  목차 블록 제거              (LAW)      ← 노이즈 먼저 제거
2. C3  원문자 항 보존              (LAW)      ← 반드시 C1(NFKC) 이전
3. C1  자간·어절 재결합            (전체)
4. C6  헤딩 정제(개정 배지 분리)    (전체)
5. C7  문서 메타 승격              (REG·LAW)  ← 보일러플레이트 제거 이전
6. C3  고아 마커 복원              (REG·DIA·GEN) ← C1 이후(공백이 정규화된 상태에서 판정)
7. C2  리딩오더 복구 + 장-조 귀속   (전체)     ← 헤딩이 정제된 뒤
```

**깨지면 안 되는 의존성 2개** — ① C3(LAW)가 C1보다 앞. NFKC가 ①을 숫자로 뭉개면 항 번호를 복원할 방법이 없다. ② C7이 헤딩 정제(C6) 뒤. 조별 개정 배지를 분리해야 문서 개정 버전을 집계할 수 있다.

## 6. 중간 표현 — `ParsedDoc`

**docling의 `DoclingDocument`를 하류로 그대로 흘리지 않는다.** 교정 계층·청킹·메타가 docling 버전에 묶이면 엔진 업그레이드가 전부를 흔든다. 얇은 자체 표현 하나를 둔다.

```python
# apps/ai/app/rag/parsing/model.py
ElementType = Literal["title","heading","paragraph","list_item","table",
                      "figure","caption","footnote","code_block"]

@dataclass
class Element:
    element_id: str            # "{doc_id}:p{page}:e{seq}"
    type: ElementType
    text: str                  # 교정 후 텍스트 (표는 Markdown 직렬화)
    level: int | None          # 1=장 2=조 3=항 4=호
    page: int
    bbox: tuple[float,...]|None
    order: int                 # 문서 전체 읽기 순서
    attrs: dict                # table→{rows,cols,grid,header_row,page_span}
                               # heading→{revision, article_no, chapter_no}
                               # 교정→{corrections:["C1","C3"], marker_uncertain:bool}

@dataclass
class ParsedDoc:
    doc_id: str                # 파일 sha256[:16] — 재인덱싱 스킵 판별
    name: str
    profile: str               # REGULATION | LAW | DIAGRAM | GENERIC
    meta: dict                 # C7 승격분 (doc_no, effective_date, revision, owner_dept)
    elements: list[Element]
    report: ParseReport        # §7
    parser_version: str        # "docling-2.x+corr-v1"  ← 재현성
```

**`attrs["corrections"]`를 남기는 이유**: 검색 결과가 이상할 때 "어느 교정을 거친 요소인가"를 즉시 판별해야 한다. `rule_hits.eval_context`에 실행 스냅샷을 남기는 프로젝트 철학과 동일하다.

**표는 이중 저장**: `text`에 Markdown(임베딩·LLM 컨텍스트용), `attrs["grid"]`에 셀 배열(정확 값 조회용). 📏 셀 정확도 0.965는 grid 기준이며, 룰 임계값 원천으로 쓰려면 grid가 필요하다.

### 7.4 `ParseReport`

```python
@dataclass
class ParseReport:
    profile: str
    applied_steps: list[str]           # ["C1","C3","C2"]
    skipped_steps: dict[str,str]       # {"C2":"SKIP:non_monotonic"}
    corrections_count: dict[str,int]   # {"C1":399, "C3":95}
    dropped_elements: list[str]        # C4가 지운 것 — 삭제는 반드시 기록
    warnings: list[str]
    scores: dict[str,float] | None     # GT 있으면 채점 결과
```

**조용한 실패가 RAG 품질 저하의 최대 원인이다.** 실패·스킵·삭제는 전부 리포트에 남기고, 관리자 배치 로그로 노출한다.

## 9. 청킹으로 넘기는 인터페이스 (범위 밖 — 계약만 고정)

> ✅ **청킹 전략은 `_context/chunking-strategy.md`로 확정·구현됐다**(2026-08-12). 아래 계약을 그대로 소비한다 — 특히 `attrs["chapter_no"]` 귀속, `report.skipped_steps` 확인, `marker_uncertain` 신뢰도 강등 3가지가 실제로 청커 코드에 들어가 있다.

파싱이 보장하는 것만 여기 적는다.

- **파싱이 보장**: `Element.level`(1=장 2=조 3=항 4=호) · `attrs["article_no"]`·`["chapter_no"]` · `order` 단조 · `page` · 표 `grid` · `ParseReport.applied_steps`
- **청킹이 기대면 안 되는 것**: 장 헤딩의 **물리적 위치**(§3.1). 반드시 `attrs["chapter_no"]` 귀속을 쓸 것
- **C2가 SKIP된 문서**: 장 계층이 없으므로 **조를 최상위로 놓고 청킹**해야 한다. `report.skipped_steps`를 확인할 것
- **`marker_uncertain` 요소**: 청크는 만들되 인용 신뢰도 메타를 낮출 것

## 부록. 이 전략이 낯선 PDF에도 견디는 이유

**① 엔진 교체 지점이 하나다.** `engine.py`가 `DoclingDocument`를 `ParsedDoc`으로 변환하는 지점에서 엔진 이질성이 끊긴다. docling을 버리게 돼도 교정·채점·청킹은 무변경이다.

**② 교정을 무조건 걸지 않는다.** 📏 도해 문서에 문단 재구성을 걸어 80%→53%로 회귀시킨 실측 사고가 이 설계의 직접적 근거다. 다만 게이트는 **연산의 성격**으로 걸어야지 문서 종류로만 걸면 오히려 필요한 교정을 막는다(§4.2 정정 — 초안대로였으면 직급체계의 고아 마커 4건이 방치됐다). 재배열·요소 내 치환은 열고, 병합·분할은 닫는다.

**③ 실패를 무해한 방향으로 착지시킨다.** C2가 전제(bbox·단일 컬럼)를 잃으면 재배열을 **포기**하고, C3가 번호 연속성 검사에 실패하면 원문을 **유지**하며 `marker_uncertain`을 남긴다. 틀린 계층·추측 번호는 검색 시점에 조용히 나타나지만, 계층 없음·불확실 마킹은 즉시 보인다.

**④ 품질을 측정 가능한 상태로 유지한다.** 📏 `tiger_inc/md/` 8종은 **파싱 정답을 가진 상태**라는 뜻이다. 교정 단계마다 적용 전/후를 채점해 개선분을 리포트에 남기면, 파싱 품질이 침묵 속에 나빠질 수 없다. GT가 없는 법령 3종은 점수를 지어내지 않고 사람 검수 시트로 넘긴다.
