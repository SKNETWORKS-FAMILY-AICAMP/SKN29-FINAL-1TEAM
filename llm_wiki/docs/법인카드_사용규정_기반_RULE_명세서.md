# 1. 개요

### 1.1 목적

이 문서는 법인카드 사용 내역이 정산 시스템에 들어왔을 때 Rule 콘솔이 조건에 따라 승인·보완요청·반려 방향을 1차로 분류하여 재무회계팀의 검토 업무를 자동화할 수 있도록, 업무추진비·회식·출장 3개 카테고리에 대해 사내 규정 조항을 근거로 한 RULE을 정의한다. 각 RULE은 Rule 콘솔에서 "조건(condition) → 액션(action)" 형태로 등록되며, 출처 조항을 태깅해 규정 개정 시 영향받는 RULE을 추적할 수 있도록 한다.

### 1.2 처리 프로세스

모든 RULE은 다음 흐름을 거쳐 실제 서비스에 반영된다.

- RULE 초안 등록 — 담당자가 규정 조항을 근거로 RULE 초안을 Rule 콘솔에 등록("Rule 초안 대기" 상태).

- 시뮬레이션 — 과거 정산 이력 데이터로 매칭 건수·오탐율(False Positive)·예상 검토 감소량을 검증하고, 기존 Active Rule과 조건이 겹치는지 확인한다.

- 승인 및 Active 전환 — 팀장급 이상 승인권자가 시뮬레이션 결과를 검토해 "승인(ACTIVE 전환)"하면 신규 버전으로 반영되고, 이전 버전은 롤백 가능한 상태로 보존된다.

- 운영 — Active Rule이 실제 정산 건에 적용되어 검토 워크스페이스에서 승인/보완요청/반려 추천 의견과 근거(RAG 인용 조항)를 함께 제시한다.

### 1.3 최종 처리 상태와 인적 책임

RULE 엔진이 산출하는 액션·심각도·권장 처리는 검토 워크스페이스에서 담당자가 아래 3개 상태 중 하나로 최종 확정하기 위한 참고 자료이며, 심각도가 CRITICAL인 경우에도 시스템이 자동으로 확정 처리하지 않는다. 손금산입 여부 및 정산 승인에 대한 최종 판단과 책임은 관리자 및 재무회계팀에 있다(법인카드 사용 규정 제16조 인적 책임의 원칙).

- 승인(APPROVE) — 조건 충족, 증빙·기록 이상 없음.

- 보완요청(RETURN) — 증빙·기록 보완 또는 소명 후 재검토.

- 반려(REJECT) — 정책 위반·손금불산입 위험이 확정되어 정산을 거부.

# 3. 심각도 및 권장 처리 매핑 기준

모든 RULE의 액션에는 심각도(severity)가 함께 부여되며, 심각도별 기본 처리 원칙은 다음과 같다. 개별 RULE은 이 기준을 기본값으로 하되, 규정상 특성에 따라 권장 처리를 별도로 지정할 수 있다.

| **심각도**   | **정의**                                                                                    | **권장 처리 원칙**                                                                               |
|--------------|---------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------|
| **CRITICAL** | 정책상 명백히 금지된 행위(유흥업소·사행성 업종 결제, 상품권 현금구매, 2차 유흥업소 결제 등) | 자동 반려 후보 — 검토 워크스페이스 최상단에 노출, 관리자가 최종 반려를 확정한다(자동 확정 아님). |
| **HIGH**     | 손금불산입·청탁금지법 위반 등 세무·법률 리스크가 큰 사안                                    | 반려 권고 또는 법무·상위 승인자 에스컬레이션 — 사람 확인 후 반려 또는 소명 수리.                 |
| **MEDIUM**   | 사전승인 누락, 한도 초과, 참석·목적 기록 불충분 등 절차 위반                                | 보완요청 또는 지정 승인자 승인 확인 전까지 보류.                                                 |
| **LOW**      | 사전승인 대상 알림, 참고성 확인이 필요한 경미한 사안                                        | 승인 대기 확인 — 지정 승인자 승인 이력만 확인되면 통과.                                          |
| **INFO**     | 통계·리스크 등급 산정을 위한 모니터링용 참고 플래그                                         | 개별 건 처리에는 영향 없음 — 사용자 리스크 등급·정기 점검 리포트에만 반영.                       |

# 4. 공통 RULE 베이스 (R-0xx)

「법인카드 사용 규정」(TIGER-REG-2026-003) 제6조·제9조~제13조의 공통 조항에서 도출한 14개 RULE이다(v1.2 대비 R-013·R-014 신규 추가). 업무추진비·회식·출장은 물론 향후 추가되는 모든 지출 카테고리에 기본으로 적용되는 공통 RULE 베이스로, 카테고리별 규정(기업업무추진비 사용 규정·회식 관련 법인카드 운영 규정·출장비 사용 규정)에 더 구체적인 특칙이 있는 항목은 해당 특칙(R-1xx/2xx/3xx)이 우선 적용되고, 특칙이 없는 카테고리에는 본 RULE이 그대로 적용된다. R-002·R-003은 카테고리별 CRITICAL RULE(R-109, R-208, R-304)과 동일 사유를 공통 레벨에서도 함께 판정한다 — GLOBAL 게이트가 카테고리 분류 이전에 가장 먼저 평가되어 매칭 시 그 자리에서 종료되므로 실행상 이중 반환은 일어나지 않지만, ① 향후 카테고리 판정이 게이트보다 먼저 이뤄지는 아키텍처로 바뀔 경우를 대비한 방어적 중복, ② 감사·근거추적 시 "이 건이 업무추진비/회식/출장 관점에서도 금지 사유에 해당한다"는 카테고리별 사유 태깅을 유지하기 위해 조건을 그대로 둔다(§8 참조). R-013은 카테고리 특칙이 없는 지출에 대한 건당 사전승인 기준(별표1)을, R-011은 카테고리를 합산해 집계하는 사용자 단위 RULE이므로 반드시 공통 레벨에서 운영한다. R-012(자기승인 방지)는 「기업업무추진비 사용 규정」제6조⑤·「회식 관련 법인카드 운영 규정」제4조에 공통으로 명시된 원칙을 하나의 공통 RULE로 구현한 것이다. R-014(재무회계부 자체지출 감사)는 「회식 관련 법인카드 운영 규정」제9조③에만 명문화된 이해상충 방지 원칙을 카테고리 무관 공통 RULE로 확장한 것이다.

# 7. 출장 RULE (R-3xx)

「출장비 사용 규정」(TIGER-REG-2026-004)을 근거로 도출한 14개 RULE이다(v1.2 대비 R-314 신규 추가). 출장 중 발생한 회식은 R-212(회식 RULE) 및 본 문서의 R-303(야간식대)·R-310(접대성 식대)이 함께 검토 대상이 될 수 있다.

# 8. RULE 간 상호작용 및 우선순위

- 공통 RULE 우선순위: 공통 RULE 베이스(R-0xx)는 모든 카테고리에 기본 적용되며, 카테고리별 RULE(R-1xx/2xx/3xx)에 더 구체적인 특칙이 있는 경우 특칙이 우선 적용된다(예: 사전승인 금액구간은 각 카테고리 규정의 표가 우선). 별도 특칙이 없는 카테고리(예: 회식의 정산기한)에는 공통 RULE이 그대로 적용되며, 업무추진비 R-113처럼 카테고리 규정이 결과적으로 공통 RULE과 동일한 기준(7영업일)을 가리키는 경우도 있다.

- 재분류 연쇄: 회식에 외부인이 참석하면(R-204) 해당 건은 업무추진비로 재분류되어 R-101~R-114 RULE셋이 전체 재적용된다. 이때 원래 회식 RULE(R-201 사전승인·R-202 야간·R-203 주말 등)은 해제되고 업무추진비 RULE의 사전승인 구간(R-102~R-105)으로 대체된다.

- 최우선 적용 RULE: 청탁금지법 한도 초과(R-106)는 접대 유형·금액과 무관하게 최우선으로 평가하며, 다른 RULE이 승인 방향으로 판정되어도 R-106이 트리거되면 반드시 법무부서 에스컬레이션을 거친다.

- CRITICAL 심각도 RULE(공통 R-002·R-003 및 카테고리별 R-109, R-208, R-304)은 다른 RULE 평가 결과와 무관하게 최우선으로 표시되며, 검토 워크스페이스 목록 최상단에 노출한다.

- **GLOBAL 게이트 실행 순서(명문화)**: R-002(금지업종)·R-003(상품권 현금구매)는 카테고리 분류 이전 단계에서 가장 먼저 평가되는 GLOBAL 게이트이며, 매칭 시 그 자리에서 판정이 종료된다. 따라서 R-109(업무추진비)·R-208(회식)·R-304(출장)에 동일한 유흥업소·사행성업종·상품권현금 조건이 남아있더라도, GLOBAL 게이트를 통과하지 못한 건은 애초에 카테고리 단계에 도달하지 않으므로 실행상 이중 반환은 일어나지 않는다. 카테고리별 RULE이 이 조건을 그대로 유지하는 이유는 ① 향후 카테고리 판정이 게이트보다 먼저 이뤄지는 아키텍처로 전환될 경우를 대비한 방어적 중복, ② 감사·근거추적 시 "이 건이 업무추진비/회식/출장 관점에서도 금지 사유에 해당한다"는 카테고리별 사유 태깅을 유지하기 위함이다. 같은 이유로 R-009(공통, 경조사 20만원)와 R-111(업무추진비 경조사)은 `category != "기업업무추진비"` 배제조건으로 매칭 대상 자체를 역할분리했다(R-008/R-101과 동일 패턴).

- **카테고리별 CRITICAL RULE의 커버리지 비일관성(정보성, 조치 없음)**: R-109(업무추진비)는 R-002·R-003 조건을 모두 재포함하지만, R-208(회식)·R-304(출장)는 R-002 조건만 재포함하고 R-003(상품권 현금구매) 조건은 재포함하지 않는다. 다만 회식은 별도 R-209(금지 품목 구매)가, 출장은 공통 R-003 게이트가 유일한 안전망이라 실제 커버리지 누락은 아니며, 카테고리별 "미러링" 설계 원칙(공통 게이트를 전부 재포함할지, 카테고리 고유 사유만 다룰지)이 아직 통일되어 있지 않다는 점만 후속 개정 시 명문화할 것을 권고한다.

- 배타적 구간 RULE: 사전승인 금액구간 RULE(R-102~R-105, R-201, R-312, R-313)은 조건이 금액 구간으로 서로 배타적이므로 한 건당 하나만 매칭되어야 한다. 신규 RULE 등록 시 콘솔의 조건 겹침 검사로 상호 배타성을 검증한다.

- R-301(해외출장 사전승인, 금액 무관)은 금액 구간 조건이 없는 카테고리 전역 기본 검사이므로 위 배타 그룹에 포함되지 않으며, 동일 해외출장 건에서 R-312·R-313과 함께 매칭될 수 있다. 이 경우 더 높은 승인단계를 요구하는 룰(R-313 > R-312 > R-301 순)이 우선하며, 상위 룰이 요구하는 승인단계가 충족되면 하위 룰의 조건도 함께 충족된 것으로 간주한다(중복 반려 권고 방지).

- 유형 특칙과 금액구간 RULE의 중복: R-105(행사성 접대, 금액무관 부서장 이상)는 금액구간 RULE(R-102~R-104)과 별개 축(유형 기준)이라 배타 그룹에 포함되지 않는다. 30만~100만원 구간은 두 RULE의 요구 승인단계가 동일해 완전히 겹치므로 R-105를 우선 적용(행사계획 첨부까지 요구)하고, 100만원 초과 구간은 R-103·R-104가 더 엄격해 R-105 요건을 자연히 포함한다.

- 모니터링성 RULE(severity=INFO): 사용자 리스크 누적 집계 RULE(R-011, R-112)은 개별 건의 승인/보완요청/반려 판정에 직접 영향을 주지 않고 사용자 리스크 등급·정기 점검 리포트에만 반영한다(§3 INFO 정의와 일치하도록 severity를 INFO로 통일). R-113·R-307(기록·정산기한 초과)은 severity는 LOW이지만 개별 건에 실제 보완요청(RETURN)을 발생시키는 일반 RULE이므로 이 모니터링 그룹에서 제외한다. R-014(재무회계부 자체지출)도 개별 건 판정에는 영향이 없어 severity=INFO이나, 리스크 등급이 아닌 **감사실 사후검증 대상 목록**에 반영되는 별개 용도이므로 R-011·R-112와는 구분해 관리한다.

# 9. 운영 프로세스 및 유지관리

- 규정 개정 연동: 각 RULE은 출처 조항을 태깅하므로, 해당 조항이 개정되면(예: 법인카드 사용 규정 제18조, 기업업무추진비 사용 규정 제16조, 회식 규정 부칙, 출장비 규정 제15조에 따른 개정) 관련 RULE을 재검토 대상으로 자동 플래그하고 재시뮬레이션 후 재승인 절차를 거친다.

- 공통 RULE 영향범위: 법인카드 사용 규정(TIGER-REG-2026-003)의 공통 조항이 개정되면 공통 RULE(R-0xx) 전체와 이를 참조하는 카테고리별 RULE이 함께 재검토 대상이 되어 카테고리별 규정 개정보다 영향범위가 넓다. 재승인 시 업무추진비·회식·출장 전 카테고리에 대한 통합 시뮬레이션을 함께 수행한다.

- 버전 관리: RULE 개정 시 기존 Active 버전은 과거 버전으로 보존되며, 매칭 건수·오탐율 변화를 기준으로 필요 시 이전 버전으로 롤백할 수 있다.

- 승인 권한: RULE의 Active 전환은 팀장급 이상만 수행할 수 있으며, 재무회계 담당자 단독으로는 전환할 수 없다.

- 재무회계부 자체 건의 이해상충 방지: 재무회계부가 지출 주체인 건은 감사실이 사후 검증을 수행한다(공통 R-014로 구현, §4 참조. 회식 규정 제9조③ 준용, 전 카테고리 공통 적용).

# 10. 부록 — 폐기·미채택 RULE 이력

본 문서 본문에서 삭제된 RULE과, 검토했으나 채택하지 않은 신규 RULE(안)을 이력 관리 목적으로 기록한다. 폐기된 RULE의 ID는 이후 회식 카테고리 번호 재정리(v1.4) 과정에서 신규 RULE에 재배정될 수 있다 — 아래 항목은 **당시 ID 기준**으로 표기했으며, 현재 그 ID가 가리키는 RULE은 본문(§6)에서 확인할 것.

## 10.1 폐기된 RULE

**사후승인 반복 (폐기 당시 ID: R-216) — 공통 R-011로 통합**

> ⚠️ 이 항목이 사용하던 ID **R-216**은 폐기 후 결번으로 두었다가, v1.4 번호 재정리에서 신규 RULE "대규모 회식 개인카드 결제"에 재배정되었다. 현재 R-216은 아래 내용과 무관하다.

- **원래 위치**: 회식 RULE(R-2xx), 「회식 관련 법인카드 운영 규정」 부칙 근거
- **원래 조건**: `user_post_approval_count_3m >= 3` · flag = "HIGH_RISK_USER" · severity = MEDIUM
- **폐기 사유**: 공통 [R-011](#4-공통-rule-베이스-r-0xx)의 두 번째 OR절(`user_post_approval_count_3m >= 3`)과 조건·flag·severity가 완전히 동일함이 확인됨. R-011이 "카테고리를 합산하여 산정"하도록 설계되어 있어, 회식 건의 사후승인 반복도 커버리지 손실 없이 R-011로 통합 운영된다.
- **대체 RULE**: R-011(공통)
- **폐기일**: v1.2(2026-07-30) · **ID 재배정일**: v1.4(2026-07-30)

## 10.2 검토 후 미채택된 RULE(안)

**회식 봉사료 과다 포함 (안, 미채택)**

- **검토 배경**: 업무추진비(R-110)·출장(R-306)에 동일한 "결제금액 중 봉사료 10% 이상 포함 시 엄격 심사" RULE이 있는데 회식 카테고리에는 대응 RULE이 없어, 카테고리 간 형평성 보완 차원에서 신설을 검토함.
- **미채택 사유**: 「회식 관련 법인카드 운영 규정」 원문을 대조한 결과 봉사료 관련 조항 자체가 없어, 규정상 근거 없이 RULE을 신설하지 않음.
- **후속 제안**: 회식비 결제 특성상 봉사료가 흔히 발생하므로, 규정 개정(제8조에 봉사료 조항 신설)을 통한 반영을 별도 정책 제안으로 재무회계팀에 권고함.
- **검토일**: v1.3(2026-07-30)
