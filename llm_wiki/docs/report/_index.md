# 결과 보고서

각 파트가 **무엇을 만들었고 얼마나 검증됐는지**를 담는다. 발표·인수인계용 산출물이다.

`docs/qa/`와 나누는 기준:

| | 무엇 |
|---|---|
| `docs/report/` | **결과서** — 설계 의도 · 실측 수치 · 남은 과제. 이해관계자가 읽는다 |
| `docs/qa/` | **테스트 케이스** — 어떤 입력에 어떤 결과를 기대하는가. 만든 사람이 돌린다 |

| 보고서 | 대상 | 핵심 수치 |

## 규약

- **불리한 수치를 결과에서 빼지 않는다.** 대신 「아쉬운 점과 개선 계획」 절에서 **무엇을 알고
  있고 어디까지 준비했는지**로 다룬다 — 실제 기업 환경의 제약을 고려했다는 증거가 그쪽이다.
- 수치는 **실행한 결과만** 적는다. 재현 명령을 함께 남긴다.
- 원자료(노트북·실험 로그)는 옮기지 않고 **경로로 가리킨다**.
