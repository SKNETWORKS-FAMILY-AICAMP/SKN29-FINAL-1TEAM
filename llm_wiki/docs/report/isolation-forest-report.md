# 이상탐지 모델 보고서 — Isolation Forest

_Risk Review 1단계 · 법인카드 이상거래 탐지_

> **한 줄**: 라벨이 한 건도 없는 도입 시점부터 작동하는 **1차 분기 지표**가 필요했다.
> 비지도 모델 11종을 실측 비교해 **Isolation Forest**가 정확도·속도 양쪽에서 가장 앞섰고,
> 컷오프를 우리 데이터 분포로 잡아 **LLM 호출을 10분의 1로 줄이면서 검토 안정성을 지켰다.**

---

## 1. 왜 1차 분기 지표가 필요한가

Risk Review는 3단이다.

```
① ML 이상탐지 (1차 필터)  →  ② RAG 내규 검증 (2차 정밀)  →  ③ 회계 담당자 확정
   빠르고 싸다                 정확하지만 비싸다              최종 책임
```

**전수를 ②로 보내면 감당이 안 된다.** RAG 한 건은 임베딩 + 벡터검색 + LLM 추론을 거치는데,
①은 로컬 트리 순회 연산이라 비교가 안 될 만큼 가볍다(148만 건 학습 1.94초 · 47만 건 추론 5.38초).

그래서 ①의 역할은 **「정밀하게 판단하는 것」이 아니라 「볼 만한 것을 추리는 것」**이다.
정밀 판단은 ②가 하므로 ①은 **놓치지 않는 것(recall)**이 정확도보다 중요하다.

### 콜드스타트 — 라벨이 0건인 상태에서 시작한다

도입 시점에는 회계 담당자의 승인·반려 기록이 **한 건도 없다.** 지도학습은 애초에 불가능하다.

카드사 부정사용 라벨(`이상거래여부`)이 있긴 하지만 **정의가 다르다** — 그건 카드사 기준의
부정사용이지 우리 회사 내규 기준의 「검토가 필요한 지출」이 아니다. 정답으로 쓸 수 없다.

> **라벨 없이 첫날부터 작동해야 한다** — 이것이 비지도를 택한 이유이고,
> 실제 기업에 적용할 때 가장 먼저 부딪히는 제약이다.

## 2. Isolation Forest — 어떻게 동작하나

### 핵심 원리: 이상치는 **빨리 고립된다**

무작위로 피처 하나를 고르고, 그 피처의 값 범위 안에서 무작위 분할점을 잡아 데이터를 자른다.
이것을 데이터 하나가 혼자 남을 때까지 반복한다.

```
정상 건 ─ 다수와 뒤섞여 있어 여러 번 잘라야 혼자가 된다   → 경로 길다
이상 건 ─ 값이 동떨어져 있어 몇 번만 잘라도 혼자가 된다   → 경로 짧다
```

트리 200그루의 **평균 경로 길이**를 점수로 쓴다. 짧을수록 이상하다.

### 왜 이상탐지에 유리한가

| | |
|---|---|
| **분포 가정이 없다** | 「정상이 정규분포」 같은 전제를 안 한다. 법인카드 사용액처럼 한쪽으로 심하게 치우친 분포에서도 그대로 쓴다 |
| **정상을 학습하지 않는다** | 거리·밀도 기반(LOF·DBSCAN)은 「정상이 어떤 모양인지」를 먼저 알아야 하는데, 이상탐지는 정상의 모양이 다양해서 그게 어렵다 |
| **선형 시간** | 서브샘플링으로 데이터가 늘어도 비용이 거의 안 는다. 전수 거래를 매일 돌려야 하는 우리 구조에 맞는다 |
| **고차원에서 잘 버틴다** | 원-핫 인코딩으로 23차원이 되는데, 무작위 분할이라 차원의 저주를 덜 탄다 |

_(Liu, Ting & Zhou, 2008 — Isolation Forest)_

## 3. 비지도 모델 11종 비교 — 실측

동일 데이터(train 1,482,969건 / test 469,902건 / 기저율 3.49%)로 채점했다.

### 정확도

| 모델 | PR-AUC | recall@top3% | 비고 |
|---|---:|---:|---|
| **Isolation Forest** | **0.5865** | **52.6%** | **채택** |
| COPOD | 0.5330 | 48.0% | 결정론적·튜닝 불필요 |
| One-Class SVM (RBF) | 0.4320 | 54.3% | recall은 근접하나 속도 열위(아래) |
| ECOD | 0.4294 | 40.0% | 결정론적·튜닝 불필요 |
| CBLOF | 0.3858 | 44.2% | 클러스터 기반 |
| PCA | 0.3833 | 43.9% | 재구성 오차 |
| INNE | 0.3762 | 39.3% | |
| GMM | 0.3418 | 43.0% | |
| SGD One-Class SVM | 0.3150 | 35.8% | 선형 경계 — 비선형 패턴 포착 부족 |
| LOF | 0.037~0.066 | 5.1% | 원-핫 혼재 데이터에서 거리 판별력 없음 |
| LODA | 0.0283 | 1.6% | 기저율 대비 판별력 없음 |

**최근접 경쟁모델 COPOD와 유의성까지 확인했다** — 5-fold paired t-test, t=4.929,
**p=0.0079** (< 0.05).

### 속도 — 실제 배포에서 갈린다

| 모델 | 학습 규모 | fit | predict (47만 건) |
|---|---:|---:|---:|
| **Isolation Forest** | **1,482,969건 (전체)** | **1.94초** | **5.38초** |
| SGD One-Class SVM | 1,482,969건 (전체) | 3.01초 | 0.02초 |
| LOF | 50,000건 (서브샘플) | 11.5초 | 46.1초 |
| One-Class SVM (RBF) | 50,000건 (서브샘플) | 86.3초 | **1,248초 (≈21분)** |

One-Class SVM은 recall이 근접(54.3%)했지만 **5만 건 서브샘플만으로도 추론에 21분**이 걸렸다.
Isolation Forest는 그 30배인 148만 건 전체를 학습하고도 추론이 5초다.

> **정확도와 속도가 같은 방향을 가리켰다** — 트레이드오프를 고민할 필요가 없었다.

### 확정 성능

train 1,482,969건 학습 → test 469,902건 **단 1회** 채점(2024년, 기저율 3.49%).

| 컷오프 | recall | precision |
|---|---:|---:|
| 상위 1% | 24.9% | 86.8% |
| 상위 3% | 52.6% | 61.1% |
| 상위 5% | 66.4% | 46.3% |
| **상위 10%** | **79.0%** | **27.6%** |

날짜 기준 분할(2021~2023 학습 / 2024 평가)로 **look-ahead 누수를 구조적으로 차단**했다.

## 4. 서비스에서 어떻게 쓰이나

### 등급이 곧 비용 배분이다

점수 하나로 **다음 단계에 얼마를 쓸지**를 정한다.

| 등급 | 다음 단계 | 비용 |
|---|---|---|
| **LOW** | LLM **0회** — 고정 안내문 | 0 |
| **MEDIUM** | fast 모델 1회 | 낮음 |
| **HIGH** | heavy 모델 + 2차 RAG 내규 검증 | 높음 |

### 컷오프는 비율이 아니라 **분포가 갈리는 지점**으로 잡는다

등급의 뜻이 곧 기준이다.

- **LOW는 LLM을 한 번도 안 부른다** → 「거의 정상이라고 확신할 수 있는」 구간이어야 한다.
  확신 없이 넓히면 그대로 놓친다.
- **HIGH는 가장 비싸다** → 「위험한 건이 확실히 많은」 구간이어야 값어치가 있다.
- **MEDIUM은 그 사이 애매한 전부** → **비대해지는 것이 정상**이다.

우리 데이터(`seed_adopted` 185건)의 위험 밀도를 10분위로 재서 경계를 잡았다.

| 분위 | 점수 구간 | 위험 밀도 |
|---|---|---|
| d1~d2 | −0.0087 ~ 0.0105 | **0%** ← 여기까지 LOW |
| d3~d9 | 0.0109 ~ 0.0713 | 0~6% (경향 없음) |
| d10 | 0.0718 ~ 0.1128 | **11%** ← 여기부터 HIGH |

**적용 결과**

| 등급 | 비중 | 위험 밀도 |
|---|---:|---:|
| LOW | 20.5% | **0.0%** |
| MEDIUM | **69.7%** | 2.3% |
| HIGH | 9.7% | **11.1%** |

전체 위험이 2.7%인데 **HIGH가 그 4배**이고 **LOW에는 한 건도 없다.**
비싼 경로(HIGH)는 10%로 묶고, LLM을 아예 안 쓰는 경로(LOW)는 **위험이 관측되지 않은
구간까지만** 좁게 잡았다 — **비용과 검토 안정성을 동시에 확보**한 지점이다.

### 점수를 그대로 보여주지 않는다

`anomaly_score`는 **확률이 아니다.** 정상/이상 그룹의 점수 분포가 겹친다. 화면과 2차 검증에는
raw score 대신 **백분위 구간별 실측 이상비율**로 보정해 전달한다.

## 5. 아쉬운 점과 개선 계획

_실제 기업 환경에서 마주칠 제약을 미리 짚고, 각각에 대한 준비를 마쳐 둔 항목들._

### ① 라벨이 쌓이면 훨씬 잘할 수 있다

지금은 콜드스타트 전제라 비지도만 쓴다. 회계 담당자의 검토 결과가 쌓이면
**지도학습·하이브리드 스코어링**으로 넘어갈 수 있다.

**준비된 것**: `decision_labels` 스키마와 결정 사례 적재 경로(`case_history`)가 이미 있고,
**「다르게 판단한 것」만 골라 담는 규율**까지 정해져 있다(일치 건까지 넣으면 봐야 할 예외가
묻힌다). 남은 것은 검토 화면에 **「실제로 문제였나」를 남기는 칸** 하나다.

### ② 컷오프의 근거를 더 두텁게

현재 컷오프는 우리 데이터 분포에서 잡았지만 **위험 라벨이 5건**이라, 분리점이라기보다
방향이 일관된 지점이다.

**준비된 것**: 재는 절차가 코드로 있다 — 거래에서 피처를 뽑아(`build_tx_features`) 모델에
넣고 10분위 밀도를 내는 흐름을 그대로 다시 돌리면 된다. 실 거래 200~300건 · 위험 라벨
20건이 모이면 **분위마다 2건 이상**이 되어 곡선이 노이즈와 구분된다.

### ③ 컷오프가 코드 상수다

지금은 상수라 **재학습해도 자동으로 갱신되지 않는다.**

**개선 방향**: 모델 메타데이터(`AnomalyModel`)에 컷오프를 얹으면 모델과 함께 따라온다.
재학습 파이프라인에 그 산출 단계를 넣는 것으로 해결된다.

### ④ 학습 분포와 운영 분포의 차이

학습에 쓴 공개 데이터와 실제 회사 거래는 분포가 다르다. 실측에서도 우리 데이터가 모델의
백분위 기준으로 위쪽에 몰렸다.

**대응**: 그래서 컷오프를 **모델의 캘리브레이션이 아니라 우리 데이터 분포**에서 다시 잡았다.
이것이 실제 기업 적용 시의 정석적인 절차이며, 회사가 바뀌면 그 회사 데이터로 같은 절차를
한 번 더 돌리면 된다 — **재는 방법이 정해져 있다는 것이 핵심**이다.

재학습 시에는 sklearn 버전을 배포 환경(1.5.2)에 고정하고 `feature_stats`를 함께 저장해
**피처 기여도(어떤 값 때문에 이상으로 봤는가)**까지 화면에 띄운다. 그 필드와 계산 경로는
이미 모델 클래스에 들어가 있다.

### ⑤ 가맹점 신호를 모델에서 뺐다

카드 공유 구조 때문에 가맹점 피처의 시간축 정합을 보장할 수 없어 제외했다.

**대안이 이미 돌고 있다**: 가맹점 관련 신호는 **RAG 쪽 `case_history`와 업종 분류**가
담당한다. 모델이 못 보는 축을 다른 단계가 보도록 나눠 둔 구조다.
