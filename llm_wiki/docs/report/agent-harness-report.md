# 에이전트 하네스 통합 보고서

_LLM을 쓰는 5개 지점에 무엇을 씌웠고, 그것이 수치로 얼마나 달라졌는가_

---

## 1. 무엇을 중요하게 봤나

모델을 바꾸거나 프롬프트를 다듬는 것보다 **틀릴 수 있는 자리를 구조로 막는 것**을 먼저 했다.
LLM 출력은 확률적이라 "잘 되게" 만들 수는 없고, **틀렸을 때 드러나게** 만들 수 있다.

세 가지를 원칙으로 뒀다.

| | |
|---|---|
| **모델이 낼 수 없어야 하는 값은 스키마에서 뺀다** | 지시로 막으면 지켜지지 않는다. 출력 스키마에 자리가 없으면 낼 수 없다 |
| **프롬프트와 검증은 같은 출처를 본다** | 갈리면 "목록에서 고르라"는 지시가 검증되지 않는다 |
| **조용한 실패를 만들지 않는다** | 틀렸는데 에러가 안 나는 것이 가장 나쁘다. 검사에 걸리거나 화면에 사유가 남아야 한다 |

## 2. 적용한 하네스 — 8종

### ① 컨텍스트 카탈로그 (`domain/context`)

프롬프트에 싣는 도메인 어휘(DSL 문법 · EvalContext 경로 · 값 어휘 · 별표 축 · 판정 선택지 ·
플래그)를 **live 모델에서 조립**한다. 어떤 리터럴도 이 계층에서 새로 태어나지 않는다.

**불변식**: 프롬프트 블록과 검증 기준이 **같은 `Bundle`**에서 나온다. TTL 180초, 조회 실패는
`stale`로 명시(조용한 폴백 금지).

적용: Rule Agent · 별표 추출 · 증빙 추출

### ② 구조화 출력 + 스키마 제약

`response_format: json_schema`(strict). 모델이 JSON을 손으로 짜면 문법 변종이 계속 나온다.
**구조를 스키마로 못 박고 조립은 파이썬이 한다.**

적용: 전 에이전트

### ③ 값 어휘 강제

enum이 있는 경로는 **허용 값을 프롬프트에 나열하고, 밖의 값은 받은 뒤 버린다.**

이게 없으면 「문서 표기 그대로」가 들어와 별표 payload의 키와 안 맞고, **룩업이 매번
기본값(`*`)으로 조용히 떨어진다** — 에러도 로그도 없다.

적용: 별표 추출(축 8경로) · 증빙 추출

### ④ 자동검사 → 재시도 피드백 루프

출력을 받아 **결정론적으로 검사**하고, 문제를 문장으로 적어 다시 부른다.

승인 시점에 하던 검사를 **추출 시점으로 당긴 것**이다 — 승인 화면에서 막히면 사람이 손으로
고쳐야 하지만, 여기서 걸리면 모델이 다시 만든다.

**재시도가 실패해도 첫 결과를 버리지 않는다.** 검사에 걸린 것은 문제를 달아 올리면 사람이
고칠 수 있지만, 통째로 사라지면 그게 있었다는 것조차 모른다.

적용: 별표 추출(2회) · Rule Agent(3회)

### ⑤ 서버가 모델 출력을 대조

Risk Review 보고서의 근거 `ref`를 실제 검색 결과와 대조해 **지어낸 인용을 버리고**,
근거가 없어진 판단은 **참고사항으로 강등**한다.

### ⑥ 엔진이 결정하고 모델은 옮긴다

「지금 제출하면 보완요청될까」는 **결정론적 엔진이 이미 답을 갖고 있다**
(`orchestrator.judge(record=False)`). 룰 그래프를 프롬프트에 주고 순회를 흉내내게 하면
틀리고, 틀려도 티가 안 난다.

적용: Draft Agent(판정 미리보기) · 결정 사유 초안(선택지는 서버 정본)

### ⑦ 맥락 확대 — 조각이 아니라 덩어리로

부모 청크로 페이지 분할 조각을 합치고, 문서·장·조 제목과 앞뒤 문맥을 함께 싣는다.
**표 안에 없는 것이 표의 의미를 정한다** — 머리글이 "구분"뿐이면 무엇의 구분인지는 표 밖에 있다.

적용: 별표 추출

### ⑧ 등급 분기 — 비용을 결과에 맞춰 쓴다

이상탐지 점수로 3등급을 나눠 **다음 단계에 얼마를 쓸지** 정한다
(LOW = LLM 0회 / MEDIUM = fast / HIGH = heavy + RAG).

### 그 밖

| | |
|---|---|
| **신뢰도 게이트** | 증빙 추출 0.6 미만은 EvalContext에 안 올린다 |
| **fail-open과 fail-closed 구분** | rerank는 실패 시 원본 top_n(안 그러면 하류가 "근거가 원래 없었다"로 오인). 값 어휘는 fail-closed |
| **이어 붙이기** | Rule Agent 호출이 기존 DRAFT에 이어 붙는다 — 호출마다 새 계열이 생기던 것 해소 |

## 3. 플로우별 적용 지점

```
문서 업로드
  └─ 파싱·청킹
      ├─ 조항 분류 ──────────────── ②
      └─ 별표 추출 ──────────────── ①②③④⑦  ← 가장 두껍다
           └─ 승인 화면 ─────────── (검사 결과·활용 안내 노출)

정산 등록
  ├─ 영수증 비전 판독 ───────────── ②
  ├─ 증빙 추출 ─────────────────── ①②③ + 신뢰도 게이트
  └─ 초안 작성 ─────────────────── ①②⑥

제출 → 룰 판정(결정론적, LLM 없음)
  └─ 검토 필요 시 Risk Review
       ├─ 1차 이상탐지(ML) ───────── ⑧
       └─ 2차 RAG 검증 ──────────── ②⑤ + rerank fail-open

룰 생성
  └─ Rule Agent ─────────────────── ①②④ + 이어 붙이기
```

## 4. 가장 두꺼운 하네스 — 별표 추출

규정 문서의 별표(한도표)를 판정 임계값(`PolicyTable`)으로 옮기는 자리다. **여기서 잘못
읽은 숫자는 모든 정산 판정에 들어간다.** 표 파싱은 셀 병합·페이지 분할 때문에 틀리기 쉽고,
축을 잘못 잡으면 에러 없이 기본값으로 떨어진다.

### 적용된 하네스와 각각이 잡은 실패

| 하네스 | 없을 때 실제로 일어난 일 |
|---|---|
| **그룹화**(부모 청크) | 출장비 별표2가 A·B등급(5쪽)과 C등급(6쪽) 두 청크로 갈려 **반쪽 표 두 개**가 승인 대기에 올라왔다. 머리글이 첫 조각에만 있어 뒷 조각은 축조차 못 골랐다 |
| **맥락 주입** | 머리글이 "구분"뿐인 표가 여럿이라 무엇의 구분인지 알 수 없었다 |
| **값 어휘 대조** | 업무추진비 별표1이 `category.value` 축으로 **검사를 통과**했다. 키는 음식물·선물·경조사인데 그 축의 값이 아니라 **룩업이 매번 `*`로 떨어진다**(맞는 축은 `category.item_type`) |
| **깊이·리프 검사** | 축 2개를 선언하고 payload는 3중첩 — 승인해도 `lookup`이 늘 `None`을 주는데 에러가 안 난다 |
| **「원문에 없는 숫자」 검사** | `{"value": 300000}`을 냈는데 그 수가 원문에 없었다. 모델 메모에 *"표에 직접적인 숫자 확인이 없으므로 기본값 300,000원을 넣었습니다"* — **확신도 0.5로 지어냈다** |
| **`null` 리프 검사** | `{"*": null}` 하나 때문에 표 전체가 `ctx.policy.*`에 안 올라간다. 승인은 되는데 아무 데도 안 쓰인다 |
| **재시도** | 검사에 걸린 문제를 적어 다시 부르면 대부분 한 번에 고쳐졌다 |
| **few-shot 3개** | 지시문으로 안 잡히던 셋 — 표기 매핑(「식음료」→「식사」) · 값 열이 여럿일 때 나누기 · 절차 표 건너뛰기 |
| **모델 상향**(→ `heavy`) | `gpt-4o-mini`로는 같은 입력의 결과가 실행마다 달랐다(key 이름·축 선택·스킵 여부) |

### 검증 방법

세 규정(업무추진비·출장비·회식)의 파싱 덤프를 **운영과 같은 경로**로 읽어
(`chunking/index.py:_load`) 실제 LLM 호출로 돌렸다. 모킹 없음.

```bash
python <scratch>/run_dump.py && python <scratch>/make_md.py   # → .personal/TRIAGE_TABLE_DUMP.md
```

### 수치

| | 초기 | **최종** |
|---|---|---|
| 모델 | gpt-4o-mini | **gpt-5-mini(`heavy`)** |
| 출력 스키마 | 단건 | **표 배열**(값 열마다 하나) |
| 표 청크 → 호출 단위 | 17 → 17 | 17 → **14 그룹** |
| **만든 표** | 5~6 | **12** |
| **자동검사 경고** | 3~4 | **0** |
| **그대로 승인 가능** | **0** | **12** |

세 규정의 별표가 전부 제대로 나왔다 — 업무추진비 별표1이 `category.item_type`(식사·선물·
경조사), 출장비 별표1이 일비·식비·숙박비 **3개로**, 별표2가 숙박비·일비 **2개로**(2축),
회식 제7조가 1인당 한도와 사전승인 기준 **2개로** 갈라졌다.

### 개선 과정에서 하네스가 잡은 것 — 우리 실수 포함

프롬프트를 고치다 **회귀를 만들었다.** 「payload 키는 축의 값 목록 표기여야 한다」를 넣자
모델이 **어휘 전체를 채웠다**:

```json
{"회식": 50000, "회의": 50000, "식대": 50000, "출장": 50000, "접대": 50000, "기타": 50000}
```

축 유효·깊이·리프·숫자 검사를 **전부 통과**했다. 이전보다 나쁘다 — 조용히 틀렸는데 `✅`다.

「모든 값이 같으면 축이 아니다」로는 못 잡는다(실제 별표도 세 항목이 다 5만원이다).
구분되는 것은 **키가 표에서 나왔는가**뿐이라, 「원문에 근거 없는 항목이 과반」을 잡는 검사를
더했다. 표기 변환은 정당하므로 전부가 아니라 **과반**이다.

**검사가 오탐을 내면 사람이 검사를 안 믿는다** — 「원문에 없는 숫자」가 `50000`을 잡았는데
원문이 **「5만원」**이었다. 만·천 단위를 펴도록 고쳤다.

## 5. 두 번째 사례 — 증빙 추출

서식 예시 7종을 만들고 **실제 비전 판독**으로 검증했다. 세 가지가 순서대로 드러났다.

| | 증상 | 조치 |
|---|---|---|
| **① 체크박스를 못 읽는다** | 「부서」로 체크했는데 「팀」으로, 「성과축하」를 「프로젝트」로 읽었다. 9pt 사각형 8개 중 어느 것이 칠해졌는지 구분이 안 된다 — **표·텍스트는 전부 정확**했으므로 형식의 문제 | 선택값을 **텍스트로** 찍고 선택지는 작은 글씨로 |
| **② 불린에 선택지를 붙이면 뒤집힌다** | 「포함 (포함 / 미포함)」을 **뒤의 「미포함」**으로 읽었다 | 값만 적는다 |
| **③ 모델이 원인이었다** | 서식을 두 번 고쳐도 두 건이 남았다 — 「주류 포함: 예」를 `false`로, 참석 「5명」을 `58`로. **둘 다 확신도 1.00**이라 신뢰도 게이트로도 못 거른다 | `gpt-4o-mini` → **`gpt-4o`** |

**최종 판독 20/20** (회식 7/7 · 접대 4/4 · 출장 2/2 · 참석자명단 3/3 · 사전승인 1/1 · 회의록 3/3)

> 판독값은 곧 판정 사실이다. 틀리면 **조용히 잘못된 한도**가 적용된다 — 별표 추출을
> `heavy`로 올린 것과 같은 판단이다.

## 6. 정리

| 하네스 | 얻은 것 |
|---|---|
| 그룹화 + 맥락 | 페이지 분할 표·머리글 없는 조각 해소 |
| 값 어휘 강제 | **경로만 맞고 표기가 다른** 조용한 실패 차단 |
| 자동검사 + 재시도 | 승인 화면에서 막히던 것을 추출 단계에서 해결 |
| few-shot | 지시문으로 안 잡히던 표기 매핑·다열 분리 |
| 모델 상향 | 실행마다 답이 달라지던 것, 확신도 1.00으로 틀리던 것 |

**별표 추출**: 만든 표 5~6 → **12**, 자동검사 경고 3~4 → **0**, 그대로 승인 가능 0 → **12**
**증빙 추출**: 판독 **20/20**
