## 1. Rule Agent — "규정 문서를 읽고 룰을 얼마나 정확히 만드는가"

### 검증 방법
사내 규정(회식·출장·접대·회의·식대) 조항 50개를 골라 "이 조항으로 룰을 만들어줘"라고 실제로 요청하고, 생성된 룰 조건을 정답(규정 원문 기준)과 대조했다.

| 지표 | 결과 |
|---|---|
| 실행 성공률 | 50/50 (100%) |
| 생성된 룰의 문법 정확도 | 268/268 노드 (100%) |
| **핵심 조건 정확 재현** | 15/44 (34%) |
| 느슨한 기준(개념은 맞음 포함) | 23/44 (52%) |
| "근거 없음" 함정 케이스 오답률 | 5/6 (83%) |
| 평균 처리 시간 | 약 48초/건 |

### 발견한 문제
1. **중요한 규칙일수록 놓친다** — 가장 위험한 조항(2차 유흥업소 결제 반려 등)을 콕 집어 요청해도, 검색이 매번 같은 흔한 조항만 상위로 뽑아 정작 중요한 조항을 놓쳤다.
2. **관련 규정이 없으면 지어낸다** — 아직 규정이 없는 항목을 물었을 때, 엉뚱한 다른 규정의 숫자를 가져와 그럴듯하게 답한 경우가 다수(6건 중 5건).
3. **직책·구간별로 달라지는 금액 기준이 뭉개진다** — "직책마다 다른 한도"처럼 복잡한 규정을 하나의 고정값으로 단순화하는 경향.

### 조치
1건(2번 문제, 아래 Risk Review와 공통 원인)은 이번 라운드에 바로 고쳤다. 나머지는 검색 방식 개선이 필요한 것으로 확인되어 다음 단계 과제로 남겼다.

## 2. Risk Review Agent — "위험한 거래를 사람에게 얼마나 정확히 걸러주는가"

### 검증 방법
정답이 정해진 거래 50건(명백히 정상 12건, 명백히 위반 20건, 애매한 건 10건, 경계값 8건)을 실제로 심사시켜, AI 판정과 정답을 비교했다. 개편 전(v1)·후(v2) 같은 50건으로 두 번 비교했다.

| 지표 | 개편 전 | 개편 후 |
|---|---|---|
| 정답과 일치 | — | 38/50 (76%) |
| **"정상인데 위반으로 오판"한 비율** | 68% | **17%** |
| 금액 경계값 판정(예: 30만원 vs 30만원+1원) | 오류 | 정확 |
| 총액→1인당 금액 계산 | 계산 오류 | 정확 |
| 근거 조항을 지어낸 경우 | 0건 | 0건 |
| 평균 처리 시간 | — | 약 27초/건(위험도 낮은 건은 AI 호출 없이 즉시 처리) |

### 발견한 문제 — 카테고리 착오
"식대"로 분류된 소액 거래(예: 3,000원 야근 식사)에 **"회식" 규정**(참석 인원 3인 이상 필요)을 잘못 적용해 반려한 사례를 2건 발견했다. 실제 서비스에서 흔한 "1인 야근 식대" 같은 케이스가 잘못 걸릴 수 있는 실질적 위험이었다.

**원인**: 근거 검색이 "이 거래의 카테고리"로 범위를 좁히지 않고 전체 규정을 뒤져, 관련 없는 규정이 섞여 들어왔다. Rule Agent가 겪은 문제(위 1번)와 **같은 원인**이었다.

### 조치 — 수정 완료 + 재검증
검색 시 거래 카테고리로 규정 문서를 먼저 좁히도록 수정했다. 수정 후 같은 케이스를 재실행해 확인:
- 식대 거래 재검토 시 더 이상 회식 규정을 인용하지 않고 공통 규정만 인용함을 확인
- Rule Agent도 같은 수정으로 "회의비 규정 질의" 재실행 시 회식 규정이 전혀 섞이지 않음을 확인
- 정규 회귀 테스트 재실행 결과 기존 기능 영향 없음 확인

## 정리

| | |
|---|---|
| 검증 규모 | 두 에이전트 각 50건, 실제 운영 코드·실제 AI 모델로 실행 |
| 가장 큰 개선 | Risk Review 오탐율 **68% → 17%**(4배 개선) |
