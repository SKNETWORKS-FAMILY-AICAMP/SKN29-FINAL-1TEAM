# 비지도 이상탐지 대안 알고리즘 비교실험 결과보고서

**목적**: 현재 MVP 후보인 **Isolation Forest(IF)**를 기준으로, 성격이 다른 비지도 이상탐지 알고리즘 8종을
같은 데이터·같은 피처셋·같은 평가 방식으로 비교해 "IF보다 나은 대안이 있는가"를 확인한다.

**결론 먼저**: 8종 중 IF를 넘어선 모델은 없었다. **IF를 MVP 최종 후보로 유지**하고, 근소하게 2위였던
**COPOD**는 "설명가능성이 필요해지는 시점의 대안"으로 별도 기록해둔다.

---

## 1. 실험한 모델 8종 — 쉬운 설명

전문 용어를 최대한 줄이고, "이 모델이 이상거래를 어떤 방식으로 찾아내는가"라는 직관 위주로 정리했다.
모든 모델은 **정답(라벨) 없이** 거래 데이터의 패턴만 보고 "이상하다"는 점수를 매기는 비지도 학습이다.

### 1-1. Isolation Forest (IF) — 현재 MVP 후보, 오늘 실험의 기준선

**비유**: "숨바꼭질에서 쉽게 들키는 사람 찾기." 무작위로 아무 기준(예: 거래금액)이나 골라서, 그 기준의
아무 지점에서나 뚝 잘라 데이터를 두 그룹으로 나눈다. 이걸 계속 반복하면, 극단적으로 튀는 값(아주 큰 금액 등)은
몇 번만 잘라도 금방 혼자 남고, 평범한 값은 오래 버틴다. **몇 번 만에 혼자 남았는가**가 이상치 점수가 된다 —
빨리 혼자 남을수록 이상치.

- **강점**: 대용량에도 빠르고, 스케일(단위)이 서로 다른 컬럼이 섞여 있어도 안정적
- **약점**: 의미 없는 이진 컬럼(원-핫 인코딩 결과)이 많이 섞이면, 무작위로 기준을 고르는 과정에서 그런 컬럼이
  자주 뽑혀 성능이 떨어질 수 있음. 왜 이 거래가 이상한지 사람이 알아보기 쉽게 설명하는 기능이 기본적으로 없음

### 1-2. ECOD — 값이 얼마나 극단적인지를 통계로 계산

**비유**: "반 전체 성적에서 이 학생 점수가 상위 몇 %인지 보는 것"과 비슷하다. 각 항목(금액, 시간대 등)마다
전체 데이터에서 이 값이 얼마나 꼬리(극단) 쪽에 있는지를 계산하고, 모든 항목의 "극단 정도"를 다 더해서 최종
점수를 만든다. 무작위성이 전혀 없어 몇 번을 돌려도 항상 같은 결과가 나온다.

- **강점**: 튜닝(하이퍼파라미터 설정)이 필요 없음, 완전히 재현 가능, **왜 이 거래가 이상한지 항목별로 쪼개서
  설명 가능**(`explain_outlier` 기능 내장)
- **약점**: 항목을 하나씩 따로 보기 때문에, "이 항목과 저 항목의 조합이 이례적"인 경우는 잘 못 잡음

### 1-3. COPOD — ECOD의 원조 격, 통계적으로 더 정교한 버전

ECOD와 원리가 거의 같다(같은 연구진이 만든 이전 버전). 여러 항목 간의 관계를 통계적으로 조금 더 정교하게
다루는 "코퓰라"라는 이론을 쓴다. 실제 계산 결과는 ECOD와 비슷하지만, 이번 실험에서는 **ECOD보다 확실히 더
좋은 성능**을 보였다.

- **강점**: ECOD와 동일(튜닝 불필요, 재현 가능, 설명 가능) + 이번 실험에서 ECOD보다 우수한 성능
- **약점**: ECOD와 동일(항목 간 복잡한 조합 신호를 놓칠 수 있음)

### 1-4. INNE — Isolation Forest의 개선판

IF와 발상은 비슷한데(고립시키기), 무작위로 자르는 대신 **가까운 이웃까지의 거리**를 활용해서 IF가 가진
알려진 결함(데이터가 몰린 곳과 드문 곳이 섞여 있으면 판단이 편향되는 문제)을 보완하도록 설계된 알고리즘이다.

- **강점**: 이론적으로 IF의 결함을 보완
- **약점**: 거리를 직접 계산하는 방식이라 **각 항목의 단위(스케일)를 맞춰주지 않으면 성능이 크게 무너짐**
  (실제로 이번 실험에서 처음엔 이 문제로 거의 무작위 수준까지 떨어졌다가, 단위를 맞춘 뒤 정상 범위로 회복됨)

### 1-5. GMM (가우시안 혼합 모델) — "정상 패턴은 몇 개의 전형적인 무리로 나뉜다"는 가정

**비유**: "이 반 학생들은 대략 3~5개의 그룹(운동부, 독서부, 음악부...)으로 나뉜다"고 가정하고, 각 그룹의
중심과 퍼진 정도를 통계적으로 추정한다. 그런 다음 "이 데이터가 그 어느 그룹에도 잘 안 맞는 정도"를 이상치
점수로 쓴다.

- **강점**: 항목 간의 관계(상관관계)를 수학적으로 명시적으로 반영
- **약점**: 몇 개의 그룹으로 나눌지 미리 정해야 하고, 계산 과정(EM 알고리즘)은 초기화에 따라 실행할 때마다
  결과가 달라질 수 있음. **이번 실험에서는 fold(데이터 구성)를 바꿔가며 반복했을 때 성능 편차가 가장
  컸음**(§3 참고) — 이는 "같은 데이터에서 재실행 시 결과가 흔들린다"는 것과는 다른 관찰이며, 재실행
  자체의 안정성을 확인하려면 같은 fold·같은 데이터에서 seed만 바꿔 반복 실행하는 별도 검증이 필요함

### 1-6. LODA — 여러 개의 무작위 "단면도"를 합쳐서 보는 방식

데이터를 여러 방향에서 무작위로 투영(그림자를 만드는 것과 비슷)해서, 각 투영에서 히스토그램을 만들고
이 히스토그램들을 종합해 이상치 점수를 낸다. 원래는 실시간 스트리밍 데이터에 강점이 있는 가벼운 알고리즘이다.

- **강점**: 매우 가볍고 빠름
- **약점**: **이번 데이터·피처셋과는 근본적으로 안 맞았음** — 스케일을 맞춰줘도 사실상 무작위로 순위를 매긴
  것과 다름없는 결과가 나옴

### 1-7. CBLOF — "몇 개의 무리로 나누고, 무리에서 멀리 떨어진 정도"를 보는 방식

GMM과 비슷한 발상이지만, 확률 모델 대신 **클러스터링(무리 짓기)**을 먼저 하고, 그 무리의 크기와 무리
중심까지의 거리로 이상치를 판단한다. "이 카드는 비슷한 씀씀이를 가진 카드 무리에서 얼마나 벗어나 있는가"를
보는 셈이다.

- **강점**: 해석이 직관적("이 무리에 안 어울린다")
- **약점**: 무리가 뚜렷하게 나뉘지 않는 데이터에서는 알고리즘이 실패할 수 있음(실제로 특정 설정에서 에러
  발생, 설정을 바꿔 재시도해야 했음), 스케일 맞춤 필요

### 1-8. PCA 기반 이상탐지 — "몇 개의 핵심 축으로 요약했을 때 잘 안 맞는 정도"

데이터의 핵심적인 몇 개 방향(주성분)만 남기고 나머지는 버린 뒤, 원래 데이터를 그 몇 개 방향만으로
재구성해본다. **원래 값과 재구성한 값의 차이(오차)가 큰 데이터**를 이상치로 본다 — 정상 데이터는 몇 개
핵심 축만으로도 잘 요약되지만, 이상치는 그 축들로 잘 설명이 안 돼서 오차가 크다.

- **강점**: 계산이 가볍고 빠름
- **약점**: 항목 간 관계가 순수하게 직선적(선형)인 경우에만 잘 작동, 스케일 맞춤 필요

## 3. Fold 교차검증 결과 (train 내부 5-fold, IF·COPOD·INNE·GMM만 재검증)

test 1회 결과만으로는 "진짜 차이"인지 "우연"인지 확실치 않아, train 데이터 안에서 카드 단위로 5등분해
5번 반복 검증했다.

> **[참고]** 기존 파이프라인 원칙(train/test 시간 기반 분리)과 달리 이 fold는 카드 단위 분할이라 fold
> 내부에서 시간이 섞인다. 비지도 모델이라 라벨 리키지 문제는 없으나, 시간 파생 피처가 있다면 실제 운영
> (미래 데이터 채점) 환경과 평가 조건이 다를 수 있다. 다행히 fold 평균(0.589)과 시간 기반 test
> 결과(0.5865)가 거의 일치해 실질적 영향은 없어 보이지만, 카드 단위를 택한 이유(카드 간 리키지 방지 등)를
> 한 줄 밝혀두면 재현성 측면에서 더 명확해집니다 — 의도하신 이유가 맞는지 확인 부탁드립니다.

| 모델 | PR-AUC (평균 ± 표준편차) | recall@top5% | recall@top10% |
|---|---|---|---|
| **IF** | **0.589 ± 0.049** | 0.660 ± 0.016 | **0.793 ± 0.016** |
| COPOD | 0.567 ± 0.055 | 0.621 ± 0.025 | 0.766 ± 0.015 |
| INNE | 0.453 ± 0.069 | 0.666 ± 0.072 | 0.790 ± 0.015 |
| GMM | 0.328 ± 0.035 | 0.589 ± 0.072 | 0.738 ± 0.110 |

- test 1회 결과에서 INNE·GMM이 특정 구간(top5~10%)에서 IF보다 근소하게 높게 나왔던 적이 있었는데,
  fold로 반복 검증하니 그 차이가 **모델 자체의 변동폭(표준편차) 안에 들어가는 노이즈**로 확인됐다.
- **IF가 fold 검증에서도 종합 1위를 유지**했다.
- **GMM은 성능도 낮고, fold 간 편차(특히 top10%에서 표준편차 0.110)도 매우 커서 데이터 구성 변화에
  민감하다** — 카드/기간 구성이 조금만 바뀌어도 결과가 크게 흔들릴 수 있어 운영 환경에서 예측 가능성이
  떨어진다. (단, 이 수치는 fold 간 변동이며 "같은 데이터에서 재실행 시 결과가 흔들리는지"에 대한 직접적인
  증거는 아니다 — 위 §1-5 참고)

## 4. 결론 및 권고

1. **Isolation Forest를 MVP 최종 후보로 유지한다.** 시도한 8개 모델(트리 분기, 항목별 극단값, 거리·부분공간,
   히스토그램·투영 등 서로 다른 4개 계열의 대표 알고리즘) 중 IF를 넘어선 모델은 없었고, 이는 test 1회 채점과
   fold 5회 반복 검증에서 일관되게 재확인됐다.
2. **COPOD를 "설명가능성이 필요해지는 시점의 대안"으로 별도 기록해둔다.** 성능은 IF보다 낮다(fold 기준
   0.567 vs 0.589).
   > **[확인 필요] 유의성 판단 방식**: "차이(0.022)가 IF 자체의 fold 표준편차(0.049)보다 작다"는 근거로
   > "통계적으로 구분되지 않는다"고 쓰는 것은 올바른 비교가 아니다. IF와 COPOD는 **같은 5개 fold**에서
   > 평가됐으므로, 두 모델의 개별 표준편차가 아니라 **fold별 쌍대 차이**(fold마다 IF점수 − COPOD점수,
   > 5개 값)의 평균과 표준편차를 봐야 한다. 같은 fold는 데이터 난이도가 공유되므로 쌍대 차이의 변동폭은
   > 보통 개별 모델 표준편차보다 작고, 이 경우 오히려 IF 우위가 유의할 가능성도 있다.
   > → **fold별 IF·COPOD 원점수 5쌍을 알려주시면 쌍대 차이로 재계산해 이 문장을 정정하겠습니다.**
   > (COPOD를 대안으로 기록해두는 결론 자체는 설명가능성이라는 별개 장점 때문에 유지될 가능성이 높지만,
   > "성능 차이가 유의하지 않다"는 표현은 근거가 바뀔 수 있음)

   한편 COPOD·ECOD는 "왜 이 거래가 이상한지"를 항목별로 쪼개 설명하는 기능이 내장돼 있어, RAG 2단계에서
   근거를 제시해야 하는 요구사항과 잘 맞는다. IF는 이런 설명 기능이 기본적으로 없다.
3. **나머지 6개(ECOD, INNE, CBLOF, PCA, GMM, LODA)는 채택하지 않는다.** 성능이 명확히 낮거나(ECOD 제외
   대부분 PR-AUC 0.34~0.39대), 안정성이 나쁘거나(GMM), 사실상 무작위 수준(LODA)이었다.
4. **여기서 비지도 알고리즘 탐색은 마무리한다.** 남은 후보 중 DBSCAN은 오늘 시도한 "거리·부분공간 기반"
   계열과 성격이 같아 추가 시도의 기대 이득이 낮다고 판단했다. One-Class SVM은 계열 유사성과 별개로,
   기본 구현이 데이터 규모에 대해 최소 O(n²) 이상으로 확장되어 이번 데이터(약 174만 건) 기준 학습 자체가
   운영상 비현실적이라는 **확장성 문제**로 배제했다(계열이 달라도 이 문제는 유효함).

## 5. 참고 — 실험 중 발견·수정한 이슈 (재현성 기록용)

- **피처셋 버전 불일치**: 초기에 쓰인 `feature_tiers.json`이 구버전이라 가맹점 파생 피처 2개가 포함된
  16개짜리 목록이었음 — Tier0(14개) + `일시불할부구분코드`로 직접 고정해 15개로 정정.
  > **[확인 필요]** "15개(모델 입력 13개)"에서 15개 중 2개가 왜 모델 입력에서 빠졌는지가 본문에 없다.
  > (예: 식별자 컬럼 제외, 파생 전 원천 컬럼 제외 등) 어떤 2개이고 왜 제외했는지 알려주시면 한 줄
  > 근거를 추가하겠습니다.
  **정정 후 성능이 오히려 하락**했는데(가맹점 피처 있을 때 COPOD가 순간적으로 IF를 앞서는
  구간도 있었음), 이는 가맹점 피처 자체가 look-ahead 오염 신호를 담고 있어 인위적으로 부풀려진 결과였을
  가능성이 높다 — 애초에 가맹점 피처를 제외하기로 한 결정(§전처리 v3)이 다시 한번 타당했음을 시사한다.
- **스케일링 필요 여부 정정**: 초기에 INNE·LODA를 "스케일링 불필요"로 잘못 판단했으나, 실제로는 거리·투영
  기반이라 스케일링이 필수였다(스케일링 전 INNE PR-AUC 0.07 → 스케일링 후 0.38로 회복). IF·ECOD·COPOD만
  스케일 무관, 나머지(INNE·GMM·CBLOF·PCA·LODA)는 전부 스케일링 필요로 최종 정리.
- **PCA `weighted=True`(기본값) 오류**: 원-핫 인코딩 시 `drop_first=False`를 써서, 같은 범주형 변수에서
  나온 원-핫 컬럼들이 항상 합이 1이 되는 완전 다중공선성이 존재 → PCA의 기본 가중치 옵션이 이 때문에
  무한대에 가까운 값을 출력. `weighted=False`로 해결.
- **CBLOF 클러스터 분리 실패**: 특정 `n_clusters` 값에서 정상/이상 클러스터 분리 기준을 못 찾아 에러 발생 →
  값을 바꿔가며 재시도하는 방식으로 우회.

## 6. 이 실험이 답하지 못하는 것

이 비교는 **"비지도 알고리즘 중 어느 것이 나은가"만 답한다.** 별도로 검토한 지도학습(XGBoost 등) 실험
결과(top3% recall 74.7%, README 기준)와의 격차는 이 실험으로 전혀 해소되지 않는다 — 그 격차는 라벨
(`이상거래여부`)의 타당성이 실제 정산 검토 기준과 얼마나 겹치는지 검증돼야 판단할 수 있는, 완전히 별개의
트랙이다.
