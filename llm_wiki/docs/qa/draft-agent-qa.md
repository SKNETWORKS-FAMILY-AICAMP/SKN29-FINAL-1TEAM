# Draft Agent QA — 테스트 케이스 + 실행 결과 (2026-08-22, 경로 상태 갱신 2026-08-24)

> Draft Agent는 DB에 쓰지 않으므로(§2.0) 정리할 DB 레코드 자체가 없다. 업종 캐시(TTL 30일)만
> 부수효과로 남는다.

## ⚠️ 2026-08-24 — 이 보고서가 테스트한 경로는 이제 레거시다

main 대량 풀(44커밋)로 **Draft Agent v2**(`llm_wiki/_context/draft-agent-v2.md`)가 들어왔다. 핵심
변화: LLM이 더는 가맹점명·금액·업종을 출력하지 않는다(서버가 사실로 채움), "보완요청될 것 같은가"는
LLM 예측이 아니라 `orchestrator.judge(record=False)` 룰엔진 dry-run으로 얻는다. **이 문서가 테스트한
`/lab/draft/run`(`/agent/draft` 폼 기반 경로, 생성 모드)은 v2 문서가 "저장 전 상태에서만 쓰이고 사실상
사용처가 거의 없다, 다음 정리 대상"이라고 명시한 바로 그 레거시 경로다.** 새 경로는
`POST /agent/draft/settlement`이며, **AI-LAB에 아직 이 경로를 실행할 탭이 없다**(`draft-agent-v2.md`
§5).

**결론**: 아래 실측 결과(카테고리 정확도 90~95%, §2.5의 카카오 재검증 결과 등)는 **레거시
폼 경로 기준**으로만 유효하다. v2 경로(정산 사실 조립 + 판정 dry-run + 축소된 LLM 출력 스키마)에
대한 실측은 아직 없다 — AI-LAB에 정산 모드 탭이 추가되거나, 실제 Settlement를 만들어 `/agent/draft/settlement`를
직접 두드리는 별도 테스트 설계가 필요하다(사이드이펙트 있는 흐름이라 `/lab/*`처럼 가볍게 반복 실행할
수 없다). 이번 라운드에서는 범위 밖으로 남겨둔다.

## 2. 실행 결과 보고서 (레거시 경로 기준)

대상: `POST http://localhost:9000/lab/draft/run`(모델 `gpt-4o-mini`).

### 2.0 사이드이펙트 확인

`draft_agent.run()`은 Django/Postgres에 아무것도 쓰지 않는다(`run()`은 `tools.classify_merchant`
조회와 OpenAI 호출만 하고 반환값을 그대로 리턴, `Settlement`/`Transaction` 생성 없음). **단, 업종 분류
캐스케이드(`app/merchant/classify.py::classify`)가 카카오 조회에 성공하면 core의 가맹점 업종 캐시
테이블에 upsert하는 부수효과가 있다** — 판정 데이터가 아니라 재사용 가능한 업종 캐시(TTL 30일)라
"DB 오염"은 아니다.

### 2.1 환경 제약 — 카카오 업종 조회 비활성 (최초 실행)

ai 컨테이너 로그: `KAKAO_REST_API_KEY가 비어 있어 가맹점 업종 조회를 건너뜁니다`. 업종 분류
캐스케이드는 이번 실행에서 **캐시 조회만** 동작했다. 50건 중 사전에 캐시가 있던 "스타벅스" 계열
3건(#4, #19, #47)만 `CAFE`로 해석됐고, 나머지 47건은 전부 `merchantIndustryCode=""`(미확정)으로
귀결됐다. 이는 Draft Agent/classify_merchant의 결함이 아니라 **테스트 환경에 카카오 키가 없었던
환경 제약**이다.

**소결**: #21/#44는 골든 라벨 설계의 모호성 문제로 감액해서 봐야 하고, 실제 순수 정확도는 사실상
39/41(95%)에 가깝다고 보는 게 더 공정하다. 다만 **#42(편의점 동일유형 불일치)는 재현 가능한 진짜
불일치 사례**로, 온도(temperature=0.3)에서도 벌어질 수 있는 카테고리 불안정성을 보여준다.

### 발견된 이슈 요약

1. **[환경 제약, 최상위] 카카오 업종 조회가 최초 실행 내내 비활성** — 캐시 미스 47건이 전부 카카오
   단계를 못 타고 즉시 미확정 처리됐다 → §2.5로 재검증.
2. **[재현 가능한 실제 불일치] 동일 유형 편의점 간 카테고리 불일치** — GS25(#41)는 "식대", CU(#42)는
   "비품"으로 갈림. temperature=0.3에서도 상호명만으로는 편의점류 지출 분류가 불안정할 수 있음을 시사.
3. **[적대적 케이스 관찰] 개인 사용 의심 정황에 대한 별도 경고 없음** — #48(명품 매장, TEAM카드,
   인원0, 350만원)이 "비품(고급 비품)"으로, #49(노래방, PERSONAL카드, 인원0, 50만원)가 "회식"으로
   조용히 분류됨. Draft Agent는 이상탐지·개인사용 의심 로직이 없고(그건 Risk Review Agent의 역할이라
   설계상 분리는 합리적), 다만 comments 필드에도 경고가 전혀 없어 **1차 방어선이 통과된 뒤 Risk
   Review까지 문제가 넘어가기 전에는 사람이 이를 알아챌 단서가 draft 단계 응답에는 없다**.
4. **[스키마 관찰] 금액 하한 미검증** — `DraftRequest.amount: int`는 음수·0을 막지 않는다.

### 골든 라벨 관련 정직한 정정

#21/#44(호텔, TRIP으로 기대)와 #25(백화점 선물세트, ENTERTAIN으로 기대)는 애초에 **참석 인원·목적
정보가 전혀 없는 상태에서 호텔=출장, 선물세트=접대라고 가정한 것 자체가 약한 전제**였다 — 오분류로
세지 않고 "골든 라벨 설계의 한계"로 재분류하는 것이 더 정직하다. 업종 캐스케이드 정확도·false-확정율
지표는 카카오 비활성으로 표본이 사실상 3건으로 축소됐다.

### 2.5 카카오 활성화 재검증 (2026-08-22, 후속)

`.env`에 `KAKAO_REST_API_KEY` 설정 → 컨테이너 재생성 → 동일 50건을 `/lab/draft/run`에 재실행(`trace.industry.source` 필드로 캐시/카카오 경로 구분).

**카카오 API 자체는 정상 동작**: ai 컨테이너 로그에서 카카오 검색 요청이 다수 관측되고 전부 `200 OK`.

**업종 확정 건수: 3/50 → 30/50**

| 지표 | 카카오 비활성(최초) | 카카오 활성(재검증) |
|---|---|---|
| 업종 확정(비어있지 않음) | 3/50 | **30/50** |
| 그 중 기대값과 일치 | 3/3 | 30/32(기대값 있는 44건 중 확정 32건) |
| 여전히 미확정 | 47/50 | 20/50 |

**미확정으로 남은 20건의 원인 분리 — 코드 결함이 아니라 테스트 케이스가 가상 상호였다.** 미확정
20건 대부분은 카카오 호출 자체는 200 OK로 성공했지만 검색 결과가 없어(가상의 상호명) 이후 LLM
재분류 단계 자체가 호출되지 않았다:

- **순수 가상 상호(코드가 못 찾는 게 정상)**: 삼겹살구이 대박당·곱창집 만석당·회의실렌탈 서울센터
  등. **UNKNOWN 골든(#33·34·36·38) 4건은 의도대로 미확정 유지** — 설계 원칙("미확정을 기타로
  밀지 않는다") 정상 동작 확인.
- **⚠️ 새로 발견된 진짜 결함 후보**: #35(제이케이물류센터)·#37(미래테크놀로지연구소)는 UNKNOWN(미확정
  기대)인데 카카오가 뭔가를 찾아 LLM이 `기타`(OTHER)로 **확정**해버렸다 — 법인명·연구소명 같은
  비영리·비매장 법인명도 카카오 지도에 좌표가 있으면 검색에 걸릴 수 있고, 이 경우 "미확정을 기타로
  밀지 않는다"는 원칙이 **의도한 방식으로는 아니게** 우회당한다(완전히 잘못된 값은 아니지만 "미확인"과
  "확인했더니 기타"가 화면상 구분이 안 됨). 실무에서 법인명·연구소명이 실제 지출 가맹점으로 잘 안
  들어온다는 점에서 영향은 제한적이나 기록해 둘 가치가 있다.
- **오타 상호 2건(#39·40)**: 캐시에 있던 정상 상호와 달라 카카오도 0-hit → 미확정(오타 보정은
  설계상 기대하지 않았던 기능).

**실제 오분류 2건**

| # | 가맹점 | 기대 | 실제 | 평가 |
|---|---|---|---|---|
| 20 | 대한항공 | OTHER(15종에 항공 없음) | FUEL_TRANSPORT(주유/교통) | 골든 라벨이 더 약함 — 15종 어휘에 "항공"이 없는 상태에서 "교통" 계열로 근사 매핑한 것은 합리적 근사로 볼 여지가 큼 |
| 22 | KTX 코레일 | FUEL_TRANSPORT | LEISURE(레저) | 실제 미분류로 보임 — 철도 이동을 "레저"로 분류한 것은 근거가 약함, 카카오 원시 카테고리를 우리 어휘로 재분류하는 LLM 단계의 판단 오류 가능성 |

**결론**: 최초 리포트의 "false-확정율 0/6" 결론은 대체로 유지되나, 카카오가 활성화된 지금 #35·#37
2건이 "미확정이어야 할 이름이 기타로 확정"되는 경계 사례로 새로 관찰됐다(표본이 작아 강한 결론은
이르다) — 법인명·비매장 상호에 대한 카카오 0-hit 판정을 조금 더 보수적으로(주소·카테고리 신뢰도
기준 추가) 다뤄야 할 수 있다는 개선 여지로 남긴다. 카카오 API 연동 자체와 실존 브랜드에 대한 분류
정확도(30/32)는 both 정상.
